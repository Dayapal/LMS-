Chapter 01

The Browser Environment

❖

JavaScript does not run in isolation inside a browser. The browser provides a set of API objects that connect your code to the page, the URL, the device and the wider web.

Real-Life Analogy: The Car Dashboard

Think of the browser as a car. The driver sees the road through the windshield, reads navigation from GPS, checks trip data from the trip computer, and looks at the physical dashboard for engine info — six separate screens, all working together.

Reading the Six Objects

ObjectResponsibilityExample
windowBrowser window and many APIswindow.innerWidth
documentThe current HTML document and DOMdocument.querySelector("h1")
locationCurrent URL and navigationlocation.pathname
historySession history entrieshistory.back()
navigatorBrowser capabilities and device APIsnavigator.onLine
screenInformation about the displayscreen.width
Important distinction

window and document are not interchangeable. window is the browser's window environment; document is the page's DOM.

Page Lifecycle Events

❖

A page goes through stages — building, loading, becoming visible, losing focus, losing network, and returning. Each stage has an event. Listen to the right one and your code runs at the right moment.

Real-Life Analogy: A Restaurant Opening

A restaurant opens in stages: first the doors unlock, then the kitchen is fully stocked, then staff notice who is seated in the room, and finally the phone line tells them whether outside calls are getting through.

Web Storage

❖

Browsers let a website save small amounts of string data locally. Two notebooks, two lifetimes.

Real-Life Analogy: Two Notebooks

Imagine two notebooks on your desk. The first is a permanent diary — whatever you write stays there across days. The second is a sticky-note pad — useful during the current session, but torn off when you leave the room.

3.4 Saving Arrays and Objects

Web Storage stores strings. Use JSON for structured data.

3.5 The storage Event

When another tab of the same origin changes a stored value, eligible other tabs receive a storage event.

Security

Never store passwords, secrets, sensitive personal data, or API keys in Web Storage. Any script on the same origin can read it. It is not a database — it is a small local notebook.

Timers & Animation

❖

JavaScript can schedule work for later, or for every frame. The three time-based tools — setTimeout, setInterval, requestAnimationFrame — each fits a different situation.

Real-Life Analogy: Three Kinds of Clocks

A kitchen has three kinds of clocks: a one-shot alarm you set for the oven, a wall clock that ticks forever, and a film projector that advances one frame at a time, perfectly synchronised with the screen.

5.1 setTimeout

5.2 setInterval

Common bug

Starting a new setInterval without clearing the previous one creates multiple overlapping timers. Always store the ID and call clearInterval before starting again.

5.3 requestAnimationFrame — The Film Projector

5.4 Debounce — The Elevator Door

Real-life analogy: An elevator door waits for people to stop entering before it closes. Each new passenger resets the timer.

5.5 Throttle — The Water Faucet

Real-life analogy: A faucet has a maximum flow rate. No matter how hard you push the handle, water comes out at a controlled pace.

When to pick which

Debounce when you want to wait for input to settle. Throttle when you want steady updates during continuous input.

6.1 Scroll Events

Scroll events can power reading progress indicators, sticky navigation, and lazy-load behaviours.

The passive flag

{ passive: true } tells the browser your handler will not call preventDefault(). The browser can then scroll smoothly without waiting for your handler.

6.2 Resize Events

Chapter 07

Observer APIs

❖

Instead of repeatedly checking the DOM, let the browser notify you when something meaningful changes. That is what observers do — and they do it efficiently.

Real-Life Analogy: Three Watches

A security camera watches who enters a room. A tailor measures a growing child. A door guard watches who comes and goes through a door. Three watches — three observer types.

7.1 IntersectionObserver

Common uses: lazy-loading images, revealing sections while scrolling, implementing infinite scroll, detecting when a component enters the visible area.

7.2 Native Lazy Images

The native loading="lazy" is often simpler than manual image lazy loading. Reach for IntersectionObserver when you need custom logic.

7.3 ResizeObserver

Beware of resize loops

Changing the observed element's size inside the observer callback can trigger infinite loops. Set a flag or ignore the update if the change came from yourself.

7.4 MutationObserver

7.5 Disconnect When Done

The Rule

Always disconnect observers when the work is done. They keep references alive and can quietly cost memory.

Clipboard, Geolocation & File Downloads

❖

8.1 Clipboard — The Copy Machine

Real-life analogy: A copy machine duplicates a document onto the user's clipboard. It only works when the user actually presses the button.

8.2 Geolocation — Asking for Directions

Real-life analogy: You ask someone for directions. They may help, may refuse, or may not know. You must handle all three.

Privacy

Only request location when the feature genuinely needs it. Explain why, handle denial gracefully, and never collect it unnecessarily.

8.3 File Downloads — Writing a Letter

Accessibility, Performance & Cleanup

❖

Real-Life Analogy: A Building for Everyone

A good public building has ramps, braille signs, wide doors, clear lighting. It works for every visitor — not just the ones who walk in through the main door.

9.1 Use Semantic HTML

  • <button> for actions.
  • <a> for navigation.
  • <form> for form submission.
  • <label> for form controls.
  • Headings in a logical hierarchy.
  • Live status regions for important dynamic feedback.

9.2 Manage Focus Deliberately

After opening a dialog, focus should move inside. When it closes, focus should return to the trigger. After deleting a list item, focus should land somewhere sensible.
