Chapter 01

The DOM Tree — The Stage

❖

When a browser loads an HTML page, it does not treat the markup as a plain string. It parses the HTML and builds a tree of objects called the DOM — the Document Object Model. Every element, attribute, and piece of text becomes a node in this tree.

JavaScript does not change the HTML file. It changes the DOM. When the DOM changes, the browser re-renders the page.

Real-Life Analogy: A Family Tree of the Page

Think of a family tree. There is a root ancestor, then children, then grandchildren. The DOM works exactly like this — every element has parents, children, and siblings.

Node Relationships You Will Use

RelationshipMeaning
parentNodeThe direct parent
childrenAll element children
firstElementChild / lastElementChildFirst / last element child
nextElementSibling / previousElementSiblingAdjacent siblings
Why This Matters

Selection, modification, events and dynamic creation all make sense only if you can picture the tree. Draw it whenever you get stuck.

3.2 textContent vs. innerText

Both properties can read or change text, but they behave differently when reading existing content.

Conceptually, the results are:

  • textContent includes the text from the hidden paragraph.
  • innerText generally reflects rendered text and excludes content that is not being rendered.

Exact whitespace and line breaks can vary with markup and rendering.

PropertyMain purposeIncludes hidden descendant text when reading?
textContentRead or replace text contentGenerally yes
innerTextRead or set rendered textGenerally no

Real-life analogy: Think of textContent as reading everything written in a document, including notes hidden from view. Think of innerText as reading what is actually visible on the classroom notice board.

Practical rule

Prefer textContent for most ordinary text updates. Use innerText when rendered-text behavior is specifically needed.

4.2 appendChild() vs. append()

Both methods insert content at the end of a parent element, but they have some differences.

appendChild()

  • Accepts a single Node.
  • Returns the inserted Node.
  • Does not accept a plain string as a text node automatically.

append()

  • Accepts multiple Nodes or strings.
  • Returns undefined.
  • Converts strings into text nodes.

The last string becomes a text node inside the list.

Quick comparison

FeatureappendChild()append()
Insert one NodeYesYes
Insert multiple itemsNoYes
Accept a string directlyNoYes
Returns inserted NodeYesNo
Practical rule

Use append() when you want to add several items at once. Use appendChild() when working with a single Node or when its return value is useful.

4.3 Inserting with prepend(), before(), and after()

You don't always want to add an element at the end. Sometimes it should appear at the beginning or next to a specific element.

Real-life analogy: Adding a notice to a classroom board:

  • before() places it immediately before a particular notice.
  • after() places it immediately after a particular notice.
Important

5.6 preventDefault() — Prevent the Browser's Default Action

Browsers perform certain actions automatically. Submitting a form normally triggers navigation or a page reload. Clicking a link normally navigates to its destination. Some keyboard actions have default behavior.

event.preventDefault() prevents the default action when that action is cancelable.

Example: Prevent form reload

What happens without preventDefault()?

The form may submit normally, causing a navigation or page reload. Your JavaScript feedback may disappear as the browser processes the submission.

What happens with it?

The browser's default submission is prevented, and your handler can validate the input and update the page.

Important

preventDefault() does not automatically validate data, save it to a database, or stop an event from bubbling. Those are separate concerns.

  3. Bubbling phase — the event travels back through ancestors toward the document.

5.9 Event Delegation — A Very Important Concept

Suppose a student list contains 100 student cards, each with a Delete button. You could attach an individual listener to every button. But if new student cards are added later, you would also need to attach listeners to those new buttons.

Event delegation solves this by attaching one listener to a common parent and using bubbling to identify which child was interacted with.

Real-life analogy: Imagine one security guard at the college entrance checking everyone who enters, rather than assigning one guard to every classroom.

6.1 What Is an HTML Form?

An HTML form collects information from users — student registration, login, CRM lead creation, course enrollment, payments, contact messages.

Real-life analogy: A student admission form on paper asks for a name, email, phone number, and preferred course. In a website, HTML creates the form, JavaScript reads and validates the inputs, and a backend can save the information.

Basic form structure

Important attributes:

  • form groups controls that belong to the form.
  • id identifies an element so JavaScript or a label can reference it.
  • name identifies a field in submitted form data.
  • type defines what kind of input the user can enter.
  • label describes the field for users and assistive technologies.
  • type="submit" submits the form.
Remember

An input's id is commonly used for selecting the element, while its name is important when collecting or submitting form data.

6.11 Common Mistakes to Avoid

Mistake 1: Forgetting preventDefault() — a normal form submission can navigate or reload the page. Use preventDefault() when handling the submission entirely through JavaScript.

Mistake 2: Reading .value from a checkbox to check selection — use .checked to determine the selected state.

Mistake 3: Forgetting the name attribute — FormData relies on named form controls. Add a meaningful name to each field that must be collected.

Mistake 4: Using innerHTML for untrusted input — use textContent to display user-provided values as text and avoid unintentionally interpreting them as HTML.

Mistake 5: Assuming frontend validation is sufficient — client-side validation can be bypassed. Validate inputs on the server before storing or acting on submitted data.

Mistake 6: Forgetting empty values and trimming — a field containing only spaces may not be useful. Apply .trim() to values where surrounding whitespace should not be accepted.

Store arrays and objects

Web Storage stores strings. To persist JavaScript objects or arrays, use JSON.stringify() and JSON.parse().

The key idea: JSON.stringify() converts the object into a JSON string. JSON.parse() converts that string back into a JavaScript value. Malformed JSON throws an error, so parsing potentially invalid stored content should be guarded.

Use storage safely

Security note

Never use Web Storage for passwords, secret API keys, session tokens that should be inaccessible to JavaScript, or sensitive personal information. JavaScript running on the same origin may be able to read it. Storage also is not a replacement for a database or an authenticated backend.

7.2 Essential Browser APIs

The window object

The window object represents the browser window environment for a page. Many browser features are available through it.

These properties can be useful for responsive behavior, debugging, and understanding the current URL. The browser's document object represents the page's DOM. In a browser, it is available through window.document.

Browser dialogs

The browser provides simple dialog methods.

Limitations

These APIs are useful for small demos and basic interactions, but they block ordinary page interaction while the dialog is open and offer limited customization. Production interfaces generally use accessible in-page dialogs or notification components.

Timers: setTimeout() and setInterval()

Use clearTimeout(timerId) to cancel a pending timeout. Timers schedule work; they do not guarantee that the callback executes at exactly the requested time. Browser scheduling and background-tab behavior can delay callbacks.

Real-world uses: temporary notifications, clocks, delayed search, polling and scheduled UI updates.

7.4 Clipboard and Geolocation APIs

Some browser APIs are permission-sensitive. They may require a secure context, such as HTTPS or localhost, and may be restricted by browser settings.

Copy text to the clipboard

The Clipboard API is asynchronous and may require permission or direct user activation. A real interface should tell the user when copying fails rather than assuming success.

Get the user's location

The browser typically asks for the user's permission. A location request can fail because permission was denied, a position could not be obtained, or the request timed out.

Ethical use

Only request location when it is necessary, explain why it is needed, and handle denial gracefully. Do not request it secretly or assume permission will be granted.

7.5 Browser Lifecycle Events and Accessibility

DOMContentLoaded

Sometimes JavaScript executes before the HTML elements it needs have been parsed. One solution is to place scripts near the end of the body. Another is to use DOMContentLoaded.

This event fires after the initial HTML has been parsed and the DOM built. It does not mean every image or external resource has finished loading.

Use semantic HTML and labels

Accessible interfaces are easier to operate with keyboards, screen readers and other assistive technologies.

Prefer:

over a collection of unlabeled inputs and clickable div elements. Use a <button> for an action, an <a> for navigation, a <form> for form submission, and headings in a logical hierarchy.

Show errors accessibly

The aria-live="polite" attribute helps assistive technology announce changes to the status region without unnecessarily interrupting the user. Error messages should also be clearly associated with the relevant controls.

Focus management

After opening a form or dialog, move keyboard focus to the first meaningful control. After removing an item, consider placing focus somewhere sensible rather than leaving the user disoriented.

Use focus behavior deliberately, especially when moving users between forms, dialogs and dynamic lists.
