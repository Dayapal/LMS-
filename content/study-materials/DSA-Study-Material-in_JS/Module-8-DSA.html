class TreeNode {
  constructor(val, left = null, right = null) {
    this.val = val;
    this.left = left;
    this.right = right;
  }
}

// Build from a LeetCode-style level-order array:
// [1, 2, 3, 4, 5, null, 6]
function buildTree(arr) {
  if (!arr.length || arr[0] === null) return null;
  const root = new TreeNode(arr[0]), q = [root];
  let head = 0, i = 1;
  while (i < arr.length) {
    const node = q[head++];
    if (arr[i] !== null && arr[i] !== undefined) {
      node.left = new TreeNode(arr[i]); q.push(node.left);
    }
    i++;
    if (i < arr.length && arr[i] !== null) {
      node.right = new TreeNode(arr[i]); q.push(node.right);
    }
    i++;
  }
  return root;
}

function traverse(node, out = { pre: [], in: [], post: [] }) {
  if (!node) return out;
  out.pre.push(node.val);   // preorder: before children
  traverse(node.left, out);
  out.in.push(node.val);    // inorder: between children
  traverse(node.right, out);
  out.post.push(node.val);  // postorder: after children
  return out;
}

Interviewers ask for iterative versions to check you understand what recursion does for you. A skewed tree with 10⁵ nodes can also overflow JS's call stack.

function preorderIter(root) {
  if (!root) return [];
  const out = [], st = [root];
  while (st.length) {
    const node = st.pop();
    out.push(node.val);
    if (node.right) st.push(node.right); // pushed first
    if (node.left)  st.push(node.left);  // popped first
  }
  return out;
}

2.3 Iterative inorder

Walking down a staircase of left children. Go left as far as possible, dropping a marker. At the bottom, pick up the last marker (visit), then try that node's right side.

function inorderIter(root) {
  const out = [], st = [];
  let cur = root;
  while (cur || st.length) {
    while (cur) { st.push(cur); cur = cur.left; } // all the way left
    cur = st.pop();
    out.push(cur.val);                     // visit
    cur = cur.right;                        // then the right subtree
  }
  return out;
}

2.4 Level order (BFS) — LC 102

A lift stopping floor by floor. At each floor it greets everyone waiting (the current level), and while doing so notes who's waiting on the floor below (their children).
Think first: recursion naturally goes deep, not wide. Which structure serves "first in, first out"? How do you know where one floor ends?

function levelOrder(root) {
  if (!root) return [];
  const res = [], q = [root];
  let head = 0;
  while (head < q.length) {
    const size = q.length - head, level = []; // freeze this floor's size
    for (let i = 0; i < size; i++) {
      const node = q[head++];
      level.push(node.val);
      if (node.left)  q.push(node.left);
      if (node.right) q.push(node.right);
    }
    res.push(level);
  }
  return res;
}

Result [[1], [2, 3], [4, 5, 6]]. Freezing size at the start of each floor is the whole trick: children added during the loop belong to the next floor.

function maxDepthBFS(root) {
  if (!root) return 0;

function minDepth(n) {
  if (!n) return 0;
  if (!n.left)  return 1 + minDepth(n.right); // only one side exists
  if (!n.right) return 1 + minDepth(n.left);
  return 1 + Math.min(minDepth(n.left), minDepth(n.right));
}

function minDepthBFS(root) {
  if (!root) return 0;
  let q = [root], depth = 1;
  while (q.length) {
    const next = [];
    for (const n of q) {
      if (!n.left && !n.right) return depth; // first leaf!
      if (n.left)  next.push(n.left);
      if (n.right) next.push(n.right);
    }
    q = next; depth++;
  }
}

3.3 Balanced Binary Tree (LC 110)

At every node, do the left and right heights differ by at most 1? Our tree → true. The chain 1 → 2 → 3 (all left children) → false.

A mobile hanging over a baby's cot. At every joint, the two sides must hang at nearly the same depth, or the mobile tilts. Checking only the top joint isn't enough.
Think first: you need the height of both subtrees at every node. If you call a separate height() function at every node, how many times is each node's height recomputed?

Approach 1 — Brute force: height() at every node (top-down)

balanced_brute.js JS

const height = n =>
  n ? 1 + Math.max(height(n.left), height(n.right)) : 0;

function isBalancedBrute(n) {
  if (!n) return true;
  if (Math.abs(height(n.left) - height(n.right)) > 1) return false;
  return isBalancedBrute(n.left) && isBalancedBrute(n.right);
}
The root computes heights of the whole tree; its child recomputes heights of its whole subtree; and so on. For a skewed tree that's n + (n − 1) + … = O(n²).

Approach 2 — Optimal: bottom-up, return −1 for "unbalanced"

function isBalanced(root) {
  function check(n) {
    if (!n) return 0;
    const L = check(n.left);
    if (L === -1) return -1;
    const R = check(n.right);
    if (R === -1) return -1;
    if (Math.abs(L - R) > 1) return -1; // raise the alarm
    return 1 + Math.max(L, R);
  }
  return check(root) !== -1;
}

[1, 2, 2, 3, 4, 4, 3] → true ; [1, 2, 2, null, 3, null, 3] → false
A butterfly. Fold it down the middle. The left wing's outer edge must meet the right wing's outer edge, and inner meets inner.
Think first: which node on the right must match the left child's left child?

function isSymmetric(root) {
  const mirror = (a, b) => {
    if (!a && !b) return true;
    if (!a || !b || a.val !== b.val) return false;
    return mirror(a.left, b.right) && mirror(a.right, b.left);

function hasPathSumBrute(root, target) {
  const sums = [];
  (function go(n, s) {
    if (!n) return;
    s += n.val;
    if (!n.left && !n.right) sums.push(s);
    go(n.left, s); go(n.right, s);

4.4 Diameter of Binary Tree (LC 543)

Longest path (in edges) between any two nodes. Our tree → 4 (4 → 2 → 1 → 3 → 6).

The longest rope through a junction. At every node, hang one rope down to the deepest point on the left and one to the deepest point on the right. The longest combined rope at any node is the diameter — it doesn't have to pass through the root.
Think first: the helper must return one thing (height, for its parent) but record another (the best path through itself). How do you do both?

Approach 1 — Brute force: call height() at every node

  if (!n) return 0;

  return Math.max(through,

function diameterOfBinaryTree(root) {
  let best = 0;
  function height(n) {
    if (!n) return 0;
    const L = height(n.left), R = height(n.right);
    best = Math.max(best, L + R);   // record: path through this node
    return 1 + Math.max(L, R);    // return: height for the parent
  }
  height(root);
  return best;
}

5.2 Lowest Common Ancestor (LC 236)

The deepest node that has both p and q in its subtree (a node can be its own ancestor). Our tree: LCA(4, 6) = 1, LCA(4, 5) = 2, LCA(2, 4) = 2.

Two cousins at a family reunion. Each asks their two children "Is p or q in your family?" The first person who hears yes from both sides is the meeting point. If you yourself are p or q, you are the answer for your branch.
Think first: brute force — write down the family line from the root to p and to q. Where do they split?

function pathTo(root, target, path = []) {
  if (!root) return false;
  path.push(root);
  if (root === target ||
      pathTo(root.left, target, path) ||
      pathTo(root.right, target, path)) return true;
  path.pop();  // backtrack: not on this branch
  return false;
}

function lcaBrute(root, p, q) {
  const a = [], b = [];
  pathTo(root, p, a); pathTo(root, q, b);
  let i = 0;
  while (i < a.length && i < b.length && a[i] === b[i]) i++;
  return a[i - 1];  // last common node
}
O(n) time, but two full searches plus O(h) arrays.

function lowestCommonAncestor(node, p, q) {
  if (!node || node === p || node === q) return node;
  const left  = lowestCommonAncestor(node.left,  p, q);

6.1 Construct Binary Tree from Preorder and Inorder (LC 105)

preorder = [3, 9, 20, 15, 7], inorder = [9, 3, 15, 20, 7] → rebuild the tree: 
    3

A guest list and a seating chart. The preorder list tells you who arrived first — the first name is always the head of the family (root). The inorder seating chart tells you who sits to the left and right of that person. Repeat for each family.
Think first: preorder's first value is the root. Where is that value in inorder, and what does it split?

Approach 1 — Brute force: indexOf and slice at every step

function buildTree(preorder, inorder) {
  const pos = new Map(inorder.map((v, i) => [v, i])); // value ⇒ inorder index
  let p = 0;                                     // next root in preorder
  function build(lo, hi) {                       // inorder window [lo..hi]
    if (lo > hi) return null;
    const val = preorder[p++];
    const node = new TreeNode(val);
    const k = pos.get(val);
    node.left  = build(lo, k - 1);                 // left family first
    node.right = build(k + 1, hi);
    return node;
  }
  return build(0, inorder.length - 1);
}

6.2 Binary Tree Maximum Path Sum (LC 124) — a hard favourite

A path is any chain of connected nodes (no node twice); it needn't pass through the root. Max sum? [−10, 9, 20, null, null, 15, 7] → 42 (15 → 20 → 7).

    -10
    /  \
   9    20
       /  \
      15   7
A salary chain with debts. Each person can join a chain with at most one report on each side. A report who brings negative money (debt) is simply left out. Each person tells their manager "the best single line through me", while privately checking "what if I'm the top of the chain, using both sides?"
Think first: this is the diameter pattern (4.4) with values instead of edge counts. What should a node return to its parent — can the parent use both of its branches? What do you do with a negative branch?

Approach 1 — Brute force: try every node as the top

For each node, compute the best downward path into its left and right subtrees with a separate helper, and take node + best left + best right. Each helper call re-walks a subtree → O(n²).

Approach 2 — Optimal: one postorder pass with clamped gains

function maxPathSum(root) {
  let best = -Infinity;
  function gain(n) {
    if (!n) return 0;
    const L = Math.max(gain(n.left), 0);  // drop losing branch
    const R = Math.max(gain(n.right), 0);
    best = Math.max(best, n.val + L + R);      // n as the top of the path
    return n.val + Math.max(L, R);        // one branch only, for parent
  }
  gain(root);
  return best;
}

7.1 Theory questions (with model answers)

QuestionModel answer
What is a binary tree?A structure where each node has at most two children, left and right; each child is itself a binary tree.
Height vs depth?Depth of a node = edges from the root down to it; height of a tree = levels from root to the deepest leaf.
Full vs complete vs perfect?Full: every node has 0 or 2 children. Complete: all levels full except the last, filled left to right. Perfect: every level completely full.
Why do balanced trees matter?Height stays O(log n), so operations along one path are fast; a skewed tree degrades to O(n).
DFS vs BFS on a tree — when to use which?DFS (recursion) for heights, paths, subtree answers; BFS (queue) for level-based questions and the nearest / shallowest node.
Space complexity of DFS and BFS?DFS O(h) for the call stack; BFS O(w), the maximum width (up to n/2).
Which traversal gives sorted order in a BST?Inorder (left, node, right).
Can preorder alone rebuild a tree?No (unless nulls are recorded). Preorder + inorder (distinct values) or postorder + inorder can.
Why write iterative traversals?To avoid stack overflow on deep trees and to show you understand what recursion does.
Information up vs down?Up = return values (height, size, diameter). Down = parameters (remaining sum, current depth, allowed range).

7.3 Teacher's notes

  • Start every tree function with if (!node) return … — decide what an empty tree returns before anything else.
  • Ask: does information flow up (return values) or down (parameters)? Many problems need both.
  • "Return one thing, record another in an outer variable" solves diameter, max path sum and many "best path" problems.
  • If a brute force calls a helper (like height()) at every node, look for one bottom-up pass that returns the helper's value — that's the O(n²) → O(n) move.
  • A leaf is !n.left && !n.right. A missing child is not a leaf (the min-depth trap).
  • Always test: empty tree, single node, a skewed tree (all left), and the 6-node example.
Interview flow that impresses:
"Brute force recomputes heights at every node, O(n²). Computing height bottom-up once and recording the answer on the way gives O(n) time and O(h) space."
Tree problem checklist 🎯

② Up or down?
③ Return one, record another.
④ Leaf vs missing child.

E Bugs to never repeat
