1.2 Queue in JavaScript — the shift() trap

arr.shift() removes the front, but every remaining element must move one place left: O(n). Inside a BFS loop over 10⁵ nodes that silently becomes O(n²).

The queue where everyone steps forward (shift) vs a token display that just moves to the next number (head pointer). The second is instant.

1.3 Deque (double-ended queue)

A deque adds and removes at both ends — it's what the sliding-window maximum uses (section 4). In interviews a plain array with push, pop, and a head index (or shift for small inputs) is accepted; say out loud that shift is O(n).

2.1 Valid Parentheses (LC 20)

Input: "{{()}}" → true ; "{{)}}" → false ; "(" → false
Nested gift boxes. You can only close the box you opened most recently. "Most recent" = top of a stack.
Think first:
• When you see a closing bracket, which opening bracket must it match?
• What three situations make the string invalid?

Approach 1 — Brute force: keep deleting matched pairs

Idea: a valid string always contains an adjacent pair "()", "[]" or "{}" somewhere. Delete pairs until nothing changes; valid strings shrink to "".

function isValid(s) {
  if (s.length % 2 !== 0) return false;      // odd length → impossible
  const pair = { ")": "(", "]": "[", "}": "{" };
  const st = [];
  for (const ch of s) {
    if (ch === "(" || ch === "[" || ch === "{")
      st.push(ch);
    else if (st.pop() !== pair[ch])
      return false;                           // wrong match or empty stack
  }
  return st.length === 0;                          // leftovers → invalid
}

Design a stack with push, pop, top and getMin — all O(1).

The sticky note on each plate. Every plate carries "the smallest plate in the pile, including me". Read the top note for getMin in O(1).
Think first: after popping the current minimum, how would you know the previous minimum without re-scanning?

3. Monotonic Stack

Nearest greater element

People in a line looking right. Each wants the first taller person ahead. A short person behind a taller one is hidden forever, so throw them away.

Trigger words  next greater, next smaller, previous greater, "how many days until", "span", "first element to the right that…".

3.1 Next Greater Element (classic)

For each element, the first greater element to its right, or −1.

Input: [2, 1, 2, 4, 3] → [4, 2, 4, −1, −1]
Think first: brute force checks everything to the right. Scanning from the right, which elements can never be anyone's answer again?

Approach 1 — Brute force: look right from every element

function nextGreaterBrute(arr) {
  const res = new Array(arr.length).fill(-1);
  for (let i = 0; i < arr.length; i++)
    for (let j = i + 1; j < arr.length; j++)
      if (arr[j] > arr[i]) {
        res[i] = arr[j]; break;

  return res;

function nextGreater(arr) {
  const res = new Array(arr.length).fill(-1), st = [];
  for (let i = arr.length - 1; i >= 0; i--) {
    while (st.length && st[st.length - 1] <= arr[i])
      st.pop();                              // hidden: discard
    if (st.length) res[i] = st[st.length - 1];
    st.push(arr[i]);
  }
  return res;
}

function dailyBrute(t) {
  const ans = new Array(t.length).fill(0);
  for (let i = 0; i < t.length; i++) {
    for (let j = i + 1; j < t.length; j++) {
      if (t[j] > t[i]) {
        ans[i] = j - i; break;
      }
    }
  }
  return ans;
}
Day 2 (75) walks 71, 69, 72, 76 ⇒ found at day 6 ⇒ 4. O(n²) in the worst case (temperatures falling every day).

4.1 Implement Queue using Stacks (LC 232)

Build push, pop, peek, empty for a FIFO queue using only stack operations.

Pouring plates. Pour a stack of plates one by one into a second stack and the order flips — the oldest plate is now on top.
Think first: one stack reverses order. What do two reversals give you?

Approach 1 — Brute force: pour back and forth on every pop

class MyQueueBrute {
  constructor() { this.st = []; }
  push(x) { this.st.push(x); }
  pop() {
    const tmp = [];
    while (this.st.length > 1) tmp.push(this.st.pop()); // dig to bottom
    const front = this.st.pop();
    while (tmp.length) this.st.push(tmp.pop()); // put back
    return front;
  }
}
Every pop moves all n plates out and back: O(n) per pop.

Approach 2 — Optimal: in-stack and out-stack, pour only when out is empty

class MyQueue {
  constructor() { this.in = []; this.out = []; }
  push(x) { this.in.push(x); }
  move() {
    if (!this.out.length)
      while (this.in.length) this.out.push(this.in.pop());
  }
  pop()  { this.move(); return this.out.pop(); }
  peek() { this.move(); return this.out[this.out.length - 1]; }
  empty() { return !this.in.length && !this.out.length; }
}

4.2 Sliding Window Maximum (LC 239)

Max of every window of size k.

nums = [1, 3, −1, −3, 5, 3, 6, 7], k = 3 → [3, 3, 5, 5, 6, 7]
Talent show queue. Contestants join at the back; anyone weaker than the newcomer can never win while the newcomer is on stage, so they leave. The front is always the current champion.
Think first: recomputing each window costs O(k). When a big number enters, which numbers in the window become useless forever?

Approach 1 — Brute force: max of every window

function maxSlidingBrute(nums, k) {
  const res = [];
  for (let i = 0; i + k <= nums.length; i++) {
    let m = -Infinity;
    for (let j = i; j < i + k; j++)
      m = Math.max(m, nums[j]);
    res.push(m);
  }
  return res;
}
Windows [1,3,−1]→3, [3,−1,−3]→3, [−1,−3,5]→5… O(n · k); with n = 10⁵ and k = 5 × 10⁴ that's billions of steps.

function maxSlidingWindow(nums, k) {
  const dq = [], res = [];     // dq holds indices; dq[head] = champion
  let head = 0;
  for (let i = 0; i < nums.length; i++) {
    if (head < dq.length && dq[head] <= i - k)
      head++;                          // champion's time is up
    while (dq.length > head && nums[dq[dq.length - 1]] <= nums[i])
      dq.pop();                 // weaker ones leave
    dq.push(i);
    if (i >= k - 1) res.push(nums[dq[head]]);
  }
  return res;
}

5.1 Evaluate Reverse Polish Notation (LC 150)

Tokens ["2", "1", "+", "3", "*"] mean (2 + 1) × 3 ⇒ 9. Division truncates toward zero.
A calculator with a memory tray. Numbers go on the tray. When an operator arrives, it takes the two most recent numbers, combines them, puts the result back.
Think first: for − and /, which popped number is the left operand?

Approach 1 — Brute force: find an operator, collapse, repeat

function evalRPNBrute(tokens) {
  const t = [...tokens];
  while (t.length > 1) {
    const i = t.findIndex(x => "+-*/".includes(x) && x.length === 1);
    const a = Number(t[i - 2]), b = Number(t[i - 1]);
    const v = t[i] === "+" ? a + b : t[i] === "-" ? a - b
                : t[i] === "*" ? a * b : Math.trunc(a / b);
    t.splice(i - 2, 3, String(v)); // replace "a b op" with value
  }
  return Number(t[0]);
}

function evalRPN(tokens) {
  const st = [];
  for (const tok of tokens) {
    if (!"+-*/".includes(tok) || tok.length > 1) {
      st.push(Number(tok)); continue;  // "-11" is a number

Bar heights [2, 1, 5, 6, 2, 3], each width 1. Largest rectangle area → 10 (bars 5 and 6, height 5 × width 2).

A skyline with a tape measure. Every bar asks "how far can I stretch left and right while all bars stay at least as tall as me?" Its rectangle = its height × that width.

function largestRectBrute(h) {
  let best = 0;
  for (let i = 0; i < h.length; i++) {
    let l = i, r = i;
    while (l > 0 && h[l - 1] >= h[i]) l--;
    while (r < h.length - 1 && h[r + 1] >= h[i]) r++;
    best = Math.max(best, h[i] * (r - l + 1));
  }
  return best;
}

function largestRectangleArea(heights) {
  const h = [...heights, 0], st = [];

  for (let i = 0; i < h.length; i++) {
    while (st.length && h[st[st.length - 1]] > h[i]) {

6. Interview Question Bank

Theory + 20 coding problems

Practise saying each theory answer aloud in under 30 seconds. For every coding question, state the brute force and its cost first, then improve it.

6.1 Theory questions (with model answers)

QuestionModel answer
Stack vs queue? Stack is LIFO (undo, recursion, matching); queue is FIFO (BFS, scheduling, buffering).
How would you implement a queue in JS efficiently? An array plus a head index (or a linked list); avoid shift(), which is O(n).
What is the call stack? The stack of active function calls; each call pushes a frame and returns pop it. Too deep → stack overflow.
What is a monotonic stack? A stack kept in increasing or decreasing order by popping elements that can no longer be an answer; gives next/previous greater or smaller in O(n).
Why is the monotonic stack O(n) despite a nested while? Each element is pushed once and popped at most once, so total work is at most 2n.
What does amortized O(1) mean? Some operations are expensive, but the total cost of n operations is O(n), so the average per operation is O(1) (e.g. queue using two stacks).
What is a deque and where is it used? A double-ended queue (add/remove both ends); used for sliding window maximum and 0-1 BFS.
What is a circular queue? A fixed-size array where front and rear wrap around with % capacity, reusing freed slots.
How does recursion relate to stacks? Any recursion can be rewritten with an explicit stack — useful when recursion depth would overflow.
Real-world uses? Browser back/forward, undo/redo, expression evaluation, compilers checking brackets, print and task queues, rate limiters.

6.3 Teacher's notes

  • Ask yourself: "Does the most recent unresolved item decide what happens next?" → stack. "Does the oldest waiting item go next?" → queue.
  • Store indices in monotonic stacks when you need distances or widths; values when you only need the value.
  • Always check st.length before reading or popping the top.
  • shift() in a loop is the most common hidden O(n²) bug in JS solutions — say it before the interviewer does.
  • Sentinel values (a 0 at the end of the histogram) flush the stack and remove special cases.
Interview flow that impresses:
"Brute force rescans to the right for every element, O(n²). Elements hidden behind a bigger one can never be answers, so a monotonic stack discards them — each element is pushed and popped once, O(n)."

D Bugs to never repeat

  • shift() in a BFS loop → O(n²) silently.
  • Reading the top of an empty stack — always check st.length.
  • In RPN, computing b − a instead of a − b.
  • Using Math.floor for division — use Math.trunc for negatives.
  • In monotonic stack, storing values when you need distances — store indices.
  • Forgetting the sentinel at the end of a histogram scan.
