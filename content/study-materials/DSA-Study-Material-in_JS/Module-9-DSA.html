A BST is a binary tree with one extra promise: everything in a node's left subtree is smaller, everything in its right subtree is larger. That single rule makes search, insert and delete one walk down the tree — O(h) — and makes an inorder traversal come out sorted. ✍️

1. Fundamentals

4 real-life pictures · The BST rule · Balanced vs skewed

1.1 Real-life pictures of a BST

Dictionary · Number guessing · Library shelf signs · Sorted contact list. Each one is a BST: at every junction a comparison throws away half of what's left.
The paper dictionary: to find "mango", open the middle — "lion". Mango comes later, so ignore the whole left half. Every page you open throws away half of what's left. A BST is that dictionary frozen into a tree: each node is a page; left = earlier words, right = later words.
The number-guessing game: "I'm thinking of a number from 1 to 100." You guess 50 — "higher". You guess 75 — "lower". Each answer is a step left or right in a BST. About 7 guesses always suffice.
A library shelf system: books are arranged so that at every junction a sign says "call numbers below 500 ⇒ left aisle, above ⇒ right aisle". A librarian never scans every shelf.
A sorted contact list that keeps changing: a sorted array finds a name fast (binary search) but inserting a new contact means shifting everyone after it. A balanced BST keeps names in order and inserts in O(log n).

1.2 The BST rule

For every node:
all values in its left subtree < node value < all values in its right subtree.
Not just the direct children — the whole subtree.
This module assumes distinct values; for duplicates, pick a rule like "equal goes right" and state it.
The 9-node BST used throughout this module. Level-order array: [8, 3, 10, 1, 6, 14, 4, 7, 13]

1.3 Balanced vs skewed — why shape matters

Insertion order decides the shape. Sorted inserts make every node go right → a single-file line. A mixed order keeps the tree shallow.
Real example: a school gives roll numbers 1, 2, 3, … in admission order and inserts each student into a BST as they join. Every new number is bigger than all before it, so every insert goes right — the "tree" becomes a single-file line, and searching for student 1000 takes 1000 steps.

2.1 Search (LC 700)

Find the node with value 7.

Finding a flat in an apartment complex. The security guard says "flats below 800 → left tower, above → right tower"; inside the tower another sign splits again. You walk one path, never visiting every flat.

Approach 1 — Brute force: ignore the ordering, search the whole tree

Any traversal: O(n). This is what you'd do for a plain binary tree — and a red flag in an interview if the input is a BST.

function insert(node, x) {

function insertIter(root, x) {
  const fresh = new TreeNode(x);
  if (!root) return fresh;
  let cur = root;
  while (true) {
    if (x < cur.val) {
      if (!cur.left) { cur.left = fresh; break; }
      cur = cur.left;

      if (!cur.right) { cur.right = fresh; break; }
      cur = cur.right;
    }
  }
  return root;
}

function floorBST(node, x) {
  let ans = null;
  while (node) {
    if (node.val === x) return x;
    if (node.val < x) {
      ans = node.val;          // affordable: try pricier
      node = node.right;
    } else {
      node = node.left;        // too expensive: go cheaper
    }
  }
  return ans;
}

function ceilBST(node, x) {
  let ans = null;
  while (node) {
    if (node.val === x) return x;
    if (node.val > x) {
      ans = node.val;          // fits: try smaller
      node = node.left;
    } else {
      node = node.right;
    }
  }
  return ans;
}

3. Delete a node (LC 450)

Three cases · Inorder successor · Predecessor variant

An employee leaving a company organized by seniority. No reports → leaves. One report → that report moves up. Two reports → the inorder successor (next in seniority) steps in, and their old seat is the easy case.
Think first: why does the inorder successor always have at most one child? (Hint: it's the leftmost node of the right subtree.)

Approach 1 — Brute force: rebuild

Inorder into an array, remove the value, rebuild a BST from the sorted array (section 6.2). Correct and even re-balances, but O(n) time and space for one deletion.

Approach 2 — Optimal: three cases, inorder successor

function deleteNode(node, key) {
  if (!node) return null;
  if (key < node.val)      node.left  = deleteNode(node.left,  key);
  else if (key > node.val) node.right = deleteNode(node.right, key);
  else {
    if (!node.left)  return node.right;      // leaf or only right child
    if (!node.right) return node.left;       // only left child

    let succ = node.right;               // two children
    while (succ.left) succ = succ.left; // leftmost of right subtree
    node.val = succ.val;                // copy successor up
    node.right = deleteNode(node.right, succ.val); // remove the copy below
  }
  return node;
}

4. Validate BST (LC 98)

The most-asked BST question · The wrong version · 4 correct approaches

Price-band aisles in a supermarket. The main sign says "right side: above £500". Inside that side, a smaller sign says "left aisle: below £700". A £400 item placed there satisfies the small sign but breaks the big sign. Every item must satisfy every sign on the way to it, not just the nearest one.
That's exactly node 4 in the example tree: 5 / 3 7 / 4 — it's less than its parent 7 (fine locally) but it sits in 5's right subtree, so it must be greater than 5. Answer: false.

function isValidInorderArray(root) {
  const vals = [];
  (function go(n) {
    if (!n) return;
    go(n.left);
    vals.push(n.val);
    go(n.right);

function isValidBST(root) {
  const st = [];
  let cur = root, prev = -Infinity;
  while (cur || st.length) {
    while (cur) { st.push(cur); cur = cur.left; }
    cur = st.pop();
    if (cur.val <= prev) return false;  // out of order → stop
    prev = cur.val;
    cur = cur.right;
  }
  return true;
}
O(n) time, O(h) space, early exit the moment an inversion is found.

5.1 Kth Smallest Element in a BST (LC 230)

k = 3 in the example tree → 4 (sorted: 1, 3, 4, 6, 7, 8, 10, 13, 14)
A race leaderboard. Finishing times are stored in a BST. "Who came 3rd?" = the 3rd smallest time. If the leaderboard is updated constantly and asked this often, the approach matters.
Think first: which traversal visits a BST in sorted order? Can you stop once you've seen k values?

function kthSmallest(root, k) {
  const st = [];
  let node = root;
  while (node || st.length) {
    while (node) { st.push(node); node = node.left; }
    node = st.pop();
    if (--k === 0) return node.val;
    node = node.right;
  }
}

Approach 3 — Follow-up: store subtree sizes (for frequent queries on a changing tree)

Real example: a page asks "rank #k" thousands of times a second while scores keep changing. If each node remembers how many nodes are in its left subtree, you can jump straight to the answer.

Idea: at node n with leftSize nodes on its left:

  • if k ≤ leftSize → go left;
  • if k = leftSize + 1 → it's n;
  • otherwise → go right with k − (leftSize + 1).

Sizes are updated on every insert / delete.

function findTargetSet(root, k) {
  const seen = new Set();

function findTargetArray(root, k) {
  const a = [];
  (function go(n) {
    if (!n) return;
    go(n.left); a.push(n.val); go(n.right);
  })(root);
  let l = 0, r = a.length - 1;
  while (l < r) {
    const s = a[l] + a[r];
    if (s === k) return true;
    s < k ? l++ : r--;
  }
  return false;
}

  }
  pushAll(n) {
    while (n) {
      this.st.push(n);
      n = this.rev ? n.right : n.left;
    }
  }
  next() {
    const n = this.st.pop();
    this.pushAll(this.rev ? n.left : n.right);
    return n.val;
  }
}

function findTarget(root, k) {
  const lo = new BSTIterator(root, false);
  const hi = new BSTIterator(root, true);
  let a = lo.next(), b = hi.next();
  while (a < b) {
    if (a + b === k) return true;
    if (a + b < k) a = lo.next();
    else b = hi.next();
  }
  return false;
}

6.2 Convert Sorted Array to Balanced BST (LC 108)

[1, 2, 3, 4, 5, 6, 7] → a height-balanced BST
Organising a knockout tournament bracket. To keep the bracket balanced, the player ranked in the middle goes at the top, and each half of the list forms its own balanced sub-bracket.
Think first: if you insert 1, 2, 3, … one by one, what shape do you get? Which element should be the root so both sides have equal size?

Approach 1 — Brute force: insert the values one by one

Inserting a sorted list makes every node go right → a chain of height 7 (section 1.3). Each insert walks the whole chain → O(n²) time, and every later operation is O(n).

7.1 Theory questions (with model answers)

QuestionModel answer
What is a BST?A binary tree where, for every node, all left-subtree values are smaller and all right-subtree values are larger.
Why is inorder traversal of a BST sorted?Inorder visits left subtree (all smaller), then the node, then right subtree (all larger) — recursively, that's ascending order.
Time complexity of search / insert / delete?O(h): O(log n) when balanced, O(n) when skewed.
How can a BST become skewed?Inserting already-sorted (or reverse-sorted) data; every node goes to the same side.
How do self-balancing trees fix that?AVL and Red-Black trees rotate nodes after inserts / deletes to keep height O(log n).
BST vs hash map?Hash map: O(1) average lookup but no order. BST: O(log n) but supports sorted iteration, min/max, floor/ceil and range queries.
BST vs sorted array?Both search in O(log n); the BST inserts / deletes in O(log n) (balanced) while the array must shift elements, O(n).
What is the inorder successor?The next larger value: leftmost node of the right subtree, or (if no right subtree) the nearest ancestor for which the node is in the left subtree.
Why check ranges instead of parent-child when validating?A node must respect every ancestor's bound, not just its parent's; parent-child checks miss violations deeper in the tree.
Where are BST-like structures used?Ordered maps (TreeMap), database indexes (B-trees), schedulers, leaderboards, autocomplete with ranges.

7.3 Teacher's notes

  • "Sorted" + "tree" in a problem ⇒ think inorder.
  • "Uses BST property?" is the interviewer's hidden question. If your solution would work on any binary tree, you probably haven't used the ordering yet.
  • Pass ranges down (min, max) rather than checking parent-child.
  • Floor, ceil, successor and LCA in a BST are all the same move: walk one path, remember the best candidate.
  • Prefer iterative versions when they're just as short — O(1) space instead of O(h).
  • Duplicates: decide and state your rule (equal goes right, or store a count on the node).
  • Always test: empty tree, a single node, a skewed tree (sorted inserts), and a value smaller than the min / larger than the max.
Interview flow that impresses:
"A plain traversal is O(n). Because it's a BST, each comparison discards a whole subtree, so I only walk one root-to-leaf path: O(h) time, O(1) space iteratively."
BST problem checklist 🎯
① Does it use the ordering?
② Inorder = sorted?
③ Pass ranges down (min, max).
④ Record candidate + keep going (floor/ceil/LCA).
⑤ Prefer iterative when O(1) space.
⑥ Test empty / single / skewed / out-of-range.

Quick Reference — One-Page Recap

A The BST rule & what it buys you

  • Every node: left subtree < node < right subtree.
  • Inorder traversal → sorted (the single most useful fact).
  • Search / insert / delete = one walk down → O(h).
  • Balanced → O(log n); skewed → O(n).
  • Order is the point vs a hash map: min/max, floor/ceil, ranges.

D Bugs to never repeat

  • Validating only parent-child — misses the deep violation.
  • Using integer limits instead of ±Infinity — breaks on ±2³¹.
  • Deleting the successor from the whole tree instead of from node.right.
  • Forgetting node.left = … / node.right = … when recursing on delete.
  • Building a BST by inserting sorted data — get a skewed chain.
  • Slicing arrays in sortedArrayToBST — O(n log n) copying instead of O(n).
  • Forgetting to state the duplicate rule.
