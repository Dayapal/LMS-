How to Use This Module

Binary search cuts the search space in half every step, turning O(n) into O(log n). This module builds it in four layers over about 2 weeks; the hard part is never the idea, it is the boundaries — so every problem has a dry-run table.

Prerequisites from Module 1: time complexity (especially O(log n)), linear search, two-pointering.
Code language: Java, same as Module 1.

🗺️ Roadmap (do in order)

  • 1. Fundamentals: classic binary search — 1–2 days
  • 2. Boundary variations: lower / upper bound, first / last occurrence, floor / ceil — 3 days
  • 3. Modified arrays: rotated array, peak, single element — 3 days
  • 4. Binary search on answer — 4–5 days
  • 5. Practice bank — ongoing

🖐️ The 5-step method (same as Module 1, plus one binary-search question)

  1. Understand — normal input + edge input.
  2. Brute force — usually a linear scan, O(n).
  3. Optimize — ask: is there a monotonic property? (once a condition becomes true, it stays true). If yes, binary search applies.
  4. Dry run — table of low, mid, high and the decision at every step.
  5. Code + test — always test arrays of size 1 and 2, and targets smaller than the first / larger than the last element.
Edge-case checklist for binary search
n = 1 · n = 2 · target < arr[0] · target > arr[n−1] · duplicates (all equal) · rotated arrays · single element arrays

1. Binary Search Fundamentals

1–2 days  •  Classic template · Dry runs · Common bugs

On a sorted array, compare the target with the middle element and throw away the half that cannot contain it. Each step halves the range, so n elements need at most about log₂(n) + 1 steps.

1.1 Why O(log n) matters

nLinear search (worst)Binary search (worst)

Doubling n adds just one step. That is the meaning of O(log n).

1.2 Question

Given a sorted array arr (ascending, distinct) and target, return its index or −1.

Input: arr = [3, 8, 15, 21, 30, 42, 57, 64], target = 42 → Output: 5

1.3 Iterative code (memorize this)

static int binarySearch(int[] arr, int target) {
  int low = 0, high = arr.length - 1;
  while (low <= high) {                  // range [low..high] is nonempty
    int mid = low + (high - low) / 2;  // overflow-safe
    if (arr[mid] == target) return mid;
    else if (arr[mid] < target) low = mid + 1;  // discard left half
    else high = mid - 1;                        // discard right half
  }
  return -1;
}

1.6 Recursive version

static int bs(int[] arr, int low, int high, int target) {
  if (low > high) return -1;           // base case: empty range
  int mid = low + (high - low) / 2;
  if (arr[mid] == target) return mid;
  if (arr[mid] < target) return bs(arr, mid + 1, high, target);
  return bs(arr, low, mid - 1, target);
}
Complexity: Same O(log n) time, but O(log n) space for the call stack. Prefer the iterative version.

1.7 Why low + (high − low) / 2?

With (low + high) / 2, if low = 1,500,000,000 and high = 2,000,000,000, the sum exceeds the int limit (≈ 2.147 × 10⁹) and becomes negative. low + (high − low) / 2 gives the same mid without the overflow.

1.8 Common bugs

BugSymptomFix
while (low < high) with this template Misses the last remaining element (size-1 arrays fail) Use low <= high
low = mid or high = mid with <= Infinite loop when low == high Use mid + 1 / mid − 1
(low + high) / 2 Negative mid on huge indices low + (high − low) / 2
Running on unsorted data Wrong answers, no error Sort first, or check for a monotonic property
Classic template in one line 🧠
low <= high · mid = low + (high − low) / 2 · move to mid ± 1 on mismatch.

2. Boundary Variations

3 days  •  Lower / upper bound · First / last · Floor & ceil

Most interview binary-search problems are one of two templates: lower bound (first index with arr[i] ≥ x) and upper bound (first index with arr[i] > x). First / last occurrence, count, insert position, floor and ceil all come from these two.

2.1 Lower bound — first index with arr[i] ≥ x

Idea: when arr[mid] ≥ x, mid might be the answer: record it, then keep searching left for an earlier one. Default answer n means "every element is smaller".

static int lowerBound(int[] arr, int x) {
  int low = 0, high = arr.length - 1, ans = arr.length;
  while (low <= high) {
    int mid = low + (high - low) / 2;
    if (arr[mid] >= x) { ans = mid; high = mid - 1; } // candidate, go left
    else low = mid + 1;
  }
  return ans;
}

2.4 Floor — largest value ≤ x

Idea: mirror of lower bound. When arr[mid] ≤ x it is a candidate; record it and search right for a bigger one.

static int floorVal(int[] arr, int x) {
  int low = 0, high = arr.length - 1, ans = -1;
  while (low <= high) {
    int mid = low + (high - low) / 2;
    if (arr[mid] <= x) { ans = arr[mid]; low = mid + 1; }
    else high = mid - 1;
  }
  return ans;
}

2.5 The "record and continue" idea

Every template in this section follows one rule: when mid satisfies the condition, save it and keep shrinking toward the side where a better answer could be.

Decide two things before coding:
① What condition marks a candidate?
② Is "better" to the left or right?
That decides high = mid − 1 or low = mid + 1.
Boundary templates 🎯
Lower bound → arr[mid] ≥ x → go left
Upper bound → arr[mid] > x → go left
Floor → arr[mid] ≤ x → go right
All three record ans and keep going.

3. Binary Search on Modified Arrays

3 days  •  Rotated · Min · Peak · Single element

The array doesn't have to be fully sorted. Binary search works whenever, by looking at mid, you can tell which half is safe to throw away. All four problems below are O(log n) time, O(1) space.

3.1 Search in a rotated sorted array (LC 33)

A sorted array of distinct values was rotated at an unknown point. Find the target's index or −1.

Input: [4, 5, 6, 7, 0, 1, 2], target = 0 → Output: 4

Key fact: cut a rotated array at any mid and at least one half is sorted. Check if the target lies inside the sorted half's range; if yes go there, otherwise go to the other half.

int low = 0, high = arr.length - 1;
while (low <= high) {
  int mid = low + (high - low) / 2;
  if (arr[mid] == target) return mid;

  if (arr[low] <= arr[mid]) {              // left half sorted
    if (arr[low] <= target && target < arr[mid]) high = mid - 1;
    else low = mid + 1;
  } else {                                  // right half sorted
    if (arr[mid] < target && target <= arr[high]) low = mid + 1;
    else high = mid - 1;
  }
}
return -1;

3.2 Minimum in a rotated sorted array (LC 153)

Input: [4, 5, 6, 7, 0, 1, 2] → Output: 0

Idea: compare mid with high. If arr[mid] > arr[high], the drop (and the minimum) is to the right of mid. Otherwise mid itself might be the minimum, so keep it.

int low = 0, high = arr.length - 1;
while (low < high) {              // stops when one element remains
  int mid = low + (high - low) / 2;
  if (arr[mid] > arr[high]) low = mid + 1;
  else high = mid;               // mid may be the answer
}
return arr[low];

Template note: high = mid is safe here because the loop is low < high, so mid is always < high and the range always shrinks. This is the second binary-search template: use it when you are converging on an answer rather than checking for equality.

3.3 Find a peak element (LC 162)

A peak is greater than its neighbours (outside the array counts as −∞). Return any peak's index.

Input: [1, 2, 1, 3, 5, 6, 4] → Output: 5 (value 6). Index 1 is also valid.

Idea: if arr[mid] < arr[mid + 1], you are on an uphill slope; a peak must exist to the right. Otherwise a peak is at mid or to its left.

int low = 0, high = arr.length - 1;
while (low < high) {
  int mid = low + (high - low) / 2;
  if (arr[mid] < arr[mid + 1]) low = mid + 1;
  else high = mid;
}
return low;

3.4 Single element in a sorted array (LC 540)

Every element appears twice except one. Find it in O(log n).

Input: [1, 1, 2, 3, 3, 4, 4, 8, 8] → Output: 2

Idea: before the single element, each pair starts at an even index. After it, pairs start at odd indices. Look at an even mid: if arr[mid] == arr[mid + 1], the pattern is still intact, so the single is to the right.

int low = 0, high = arr.length - 1;
while (low < high) {
  int mid = low + (high - low) / 2;
  if (mid % 2 == 1) mid--;              // make mid even
  if (arr[mid] == arr[mid + 1]) low = mid + 2;
  else high = mid;
}
return arr[low];

4. Binary Search on Answer

4–5 days  •  Monotonic predicate · Minimize · Maximize

When the question asks for the minimum (or maximum) value that works, and "works" is monotonic (if k works, every bigger k also works), binary search over the range of possible answers instead of over an array.

Cost: O(log(range) × cost of one check).

4.1 The template

int low = smallestPossible, high = largestPossible, ans = high;
while (low <= high) {
  int mid = low + (high - low) / 2;
  if (isFeasible(mid)) { ans = mid; high = mid - 1; }  // works: try smaller
  else low = mid + 1;                                  // fails: need bigger
}
return ans;
Three decisions for every problem:
1. Range: what is the smallest and largest answer that could ever make sense?
2. Check: given a candidate mid, can I test "does it work?" in O(n) or less?
3. Direction: minimize (go left on success, as above) or maximize (go right on success)?

4.2 Integer square root (LC 69)

Return ⌊√x⌋ without using Math.sqrt.

Input: x = 28 → Output: 5

Range [1, x]. Check: mid × mid ≤ x. We want the largest mid that passes, so go right on success.

long low = 1, high = x, ans = 0;
while (low <= high) {
  long mid = low + (high - low) / 2;
  if (mid * mid <= x) { ans = mid; low = mid + 1; }  // long avoids overflow
  else high = mid - 1;
}
return (int) ans;

4.3 Koko eating bananas (LC 875)

Piles of bananas; Koko eats at speed k per hour, one pile per hour (if a pile has fewer than k, she finishes it and waits). Find the minimum k to finish within h hours.

Input: piles = [3, 6, 7, 11], h = 8 → Output: 4

Range: k from 1 to max(piles) = 11 (faster than the biggest pile never helps). Check: hours(k) = sum of ⌈pile / k⌉ ≤ h.

First, see why it is monotonic:

kHours per pile (3, 6, 7, 11)Total≤ 8?
13, 6, 7, 1127No
22, 3, 4, 615No
31, 2, 3, 410No
41, 2, 2, 38Yes
51, 2, 2, 38Yes
61, 1, 2, 26Yes
No, No, No, Yes, Yes, Yes… — we want the first Yes. That is exactly lower bound on the answer space. 
static boolean canFinish(int[] piles, int k, int h) {
  long hours = 0;
  for (int p : piles) hours += (p + k - 1) / k;  // ceil(p / k) with ints
  return hours <= h;
}
// main: low = 1, high = max(piles); use the template from 4.1

4.4 Ship packages within D days (LC 1011)

Load packages in the given order; each day the ship carries at most cap weight. Find the minimum cap to ship everything in days days.

Input: weights = [3, 2, 2, 4, 1, 4], days = 3 → Output: 6

Range: low = max weight = 4 (must carry the heaviest one), high = total = 16 (all in one day). Check: greedily fill each day until the next package doesn't fit; count days.

static int daysNeeded(int[] w, int cap) {
  int days = 1, load = 0;
  for (int x : w) {
    if (load + x > cap) { days++; load = 0; }  // start a new day
    load += x;
  }
  return days;
}
Check for cap = 6: day 1 [3, 2], day 2 [2, 4], day 3 [1, 4] → 3 days.

4.5 How to spot "binary search on answer"

  • The question says minimum maximum, maximum minimum, "smallest speed / capacity / time such that…".
  • Constraints have a large value range (up to 10⁹) but you can check one candidate in O(n).
  • Writing "for k from 1 to max, check(k)" would work but is too slow — replace that loop with binary search.
Answer-space recipe 🎯
① Find the range [smallest, largest].
② Write the O(n) isFeasible check.
③ Minimize → go left on success; maximize → go right.

Quick Reference — One-Page Recap

A The two loop conditions

low <= high
Equality search.
Move to mid + 1 / mid − 1.
Returns an index or −1.
Classic, lower bound, upper bound, floor, rotated search.
low < high
Converging search.
Use high = mid (keep mid).
Returns the element / position the range converges to.
Minimum in rotated, peak, single element.

B Boundary recipes

  • Lower bound — arr[mid] ≥ x → ans = mid; go left
  • Upper bound — arr[mid] > x → ans = mid; go left
  • Floor — arr[mid] ≤ x → ans = arr[mid]; go right
  • First occurrence = lowerBound; verify arr[lb] == x
  • Last occurrence = upperBound − 1
  • Count = upperBound − lowerBound

C Answer-space recipe

  1. Range — smallest & largest sensible answer.
  2. Check — O(n) isFeasible(mid).
  3. Direction — minimize → go left on success; maximize → go right on success.

D Edge cases to test

  • Array size 1 and size 2.
  • Target smaller than arr[0] or larger than arr[n−1].
  • All elements equal.
  • Rotated array with k = 0 or k = n.
  • Answer-space problems: check the lowest and highest candidates by hand.
Reminder: the dry-run table is not optional. If you can't say aloud why each low / high update is safe, you haven't understood the template yet.
