1. Fundamentals

The train analogy · Nodes · Helpers · Array vs list

Analogy — the train
A train is a chain of coaches. Each coach knows only the next coach (the coupling). To reach coach 5 you must walk through 1, 2, 3, 4 — no jumping. But adding a coach in the middle is easy: uncouple, insert, recouple — no other coach moves. An array is a row of fixed cinema seats; a linked list is a train.

1.1 Node class and helpers (use these to test every problem)

class ListNode {
  constructor(val, next = null) {
    this.val = val;
    this.next = next;
  }
}

// [1, 2, 3] -> 1 -> 2 -> 3
function fromArray(arr) {
  const dummy = new ListNode(0);
  let tail = dummy;
  for (const x of arr) {
    tail.next = new ListNode(x);
    tail = tail.next;
  }
  return dummy.next;
}

// 1 -> 2 -> 3 -> [1, 2, 3]
function toArray(head) {
  const out = [];
  for (let cur = head; cur; cur = cur.next) out.push(cur.val);
  return out;
}

1.3 Insert at position — dry run

Insert 99 at index 2 in 10 → 20 → 30 → 40.

function insertAt(head, index, val) {
  const dummy = new ListNode(0, head);
  let prev = dummy;
  for (let i = 0; i < index; i++) prev = prev.next;   // stop just BEFORE the spot
  prev.next = new ListNode(val, prev.next);            // new coach points forward first
  return dummy.next;
}

1.4 Delete by value — the dummy node trick

Analogy — an engine coach
A dummy is an engine coach that never carries passengers. Because there's always a coach in front, "remove the first coach" stops being a special case.

Remove all nodes with value 6: 6 → 1 → 6 → 2.

Brute force: copy the values you keep into an array and build a new list — O(n) time, O(n) extra space. Optimal (in place, O(1) space):

function removeElements(head, val) {   // LC 203
  const dummy = new ListNode(0, head);
  let cur = dummy;
  while (cur.next) {
    if (cur.next.val === val) cur.next = cur.next.next;   // uncouple; stay put
    else cur = cur.next;
  }
  return dummy.next;
}

Without the dummy, removing the first 6 would need separate code to move head.

1.5 Interview trick — Delete Node in a Linked List (LC 237)

You're given only the node to delete (not the head). It's never the last node.

Think first: you can't reach the previous coach. But can you make this coach become the next one? 
function deleteNode(node) {
  node.val = node.next.val;        // copy the next passenger in
  node.next = node.next.next;      // drop the next coach
}
For 4 → 5 → 1 → 9, deleting node 5:
Copy 1 into it → 4 → 1 → 1 → 9, skip the old 1 → 4 → 1 → 9. O(1).
Interviewers ask this to see if you think beyond the obvious.

2. Reverse a Linked List (LC 206)

The #1 interview question

Input: 1 → 2 → 3 → null
Output: 3 → 2 → 1 → null
Analogy — turning a conga line around
Everyone in a conga line holds the shoulders of the person in front. To reverse the line, each person lets go and turns to hold the person who was behind them. The trick is to remember who was in front before letting go.
Think first:
• To flip one arrow (cur.next = prev), what do you lose? How do you not lose it?
• How many pointers must you hold at the same time?

2.1 Approach 1 — Brute force: copy to an array

Idea: read all values into an array, then walk the list again writing values back in reverse order.

function reverseBrute(head) {
  const vals = [];
  for (let cur = head; cur; cur = cur.next) vals.push(cur.val);
  let cur = head;
  for (let i = vals.length - 1; i >= 0; i--) {
    cur.val = vals[i];
    cur = cur.next;
  }
  return head;
}
PassWhat happensResult
1collect valuesvals = [1, 2, 3]
2write vals[2], vals[1], vals[0] into nodes3 → 2 → 1
Time O(n), space O(n). Works, but interviewers will say "don't use extra space, and don't change values — change the links."

2.2 Approach 2 — Optimal: iterative pointer reversal

Idea: three pointers — prev, cur, next. Save next, flip the arrow, step both forward.

function reverseList(head) {
  let prev = null, cur = head;
  while (cur) {
    const next = cur.next;   // 1. remember who's in front
    cur.next = prev;         // 2. turn around
    prev = cur;              // 3. step prev forward
    cur = next;              // 4. step cur forward
  }
  return prev;               // new head
}

Complexity: O(n) time, O(1) space.
Bug to avoid: flipping the arrow before saving next — the rest of the train is gone.

2.3 Approach 3 — Recursive

Idea (leap of faith from Module 5): trust that reverseRec(head.next) reverses everything after head and returns the new head. Then just make head's old next point back to head.

function reverseRec(head) {
  if (!head || !head.next) return head;   // empty or one node
  const newHead = reverseRec(head.next);  // reverse the rest
  head.next.next = head;                  // the node after me now points back to me
  head.next = null;                       // I become the tail
  return newHead;
}

Complexity: All three return 3. Time O(n), space O(n) for the call stack — fine for interviews, but say it can overflow for very long lists.

3. Fast and Slow Pointers

Two runners on a track

Analogy — two runners
Two runners on a track; one runs twice as fast. On a straight track, when the fast one finishes, the slow one is exactly at the halfway point. On a circular track, the fast one eventually laps the slow one — they meet.

3.1 Middle of the Linked List (LC 876)

Return the middle node; for even length return the second middle.

1 → 2 → 3 → 4 → 5 → 3 ; 1 → 2 → 3 → 4 → 5 → 6 → 4
Think first: without knowing the length, how can one pass find the halfway point?

Approach 1 — Brute force: count, then walk (two passes)

function middleBrute(head) {
  let n = 0;
  for (let cur = head; cur; cur = cur.next) n++;   // pass 1: length
  let cur = head;
  for (let i = 0; i < Math.floor(n / 2); i++) cur = cur.next;  // pass 2
  return cur;
}
For 1→2→3→4→5: n = 5, walk floor(5/2) = 2 steps → node 3.
For 6 nodes: walk 3 steps → node 4.
Time O(n) (about 1.5n steps), space O(1).

Approach 2 — Optimal: fast and slow (one pass)

function middleNode(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
  }
  return slow;
}

3.2 Linked List Cycle (LC 141)

1 → 2 → 3 → 4 → 5 → back to 3. Is there a cycle? → true

Think first: if you could remember every coach you've visited, how would you spot a loop? Can you do it without memory?

Approach 1 — Brute force: a Set of visited nodes

function hasCycleSet(head) {
  const seen = new Set();
  for (let cur = head; cur; cur = cur.next) {
    if (seen.has(cur)) return true;   // stored the NODE, not its value
    seen.add(cur);
  }
  return false;
}

Time O(n), space O(n).

Approach 2 — Optimal: Floyd's tortoise and hare

function hasCycle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) return true;
  }
  return false;
}
Complexity: O(n) time, O(1) space.

3.3 Linked List Cycle II — where does the cycle start? (LC 142)

Same list ⇒ the cycle starts at node 3.

Approach 1 — Brute force: the Set approach above — the first node seen twice is the start. O(n) space.

Approach 2 — Optimal: after slow and fast meet, put one pointer back at head. Move both one step at a time; they meet at the cycle's start.

function detectCycle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) {
      let p = head;
      while (p !== slow) {
        p = p.next;
        slow = slow.next;
      }
      return p;
    }
  }
  return null;
}

① Meet inside the loop → cycle exists.
② Restart one pointer at head → they meet at the cycle start.

4.1 Merge Two Sorted Lists (LC 21)

The zipper

a = 1 → 3 → 5, b = 2 → 4 → Output: 1 → 2 → 3 → 4 → 5
Analogy — the zipper
Two sorted rows of teeth; the slider always takes the smaller tooth next. When one side runs out, the rest of the other side just follows.
Think first: both lists are already sorted. Which value must come first in the result? After you take it, what's the same smaller problem?

Approach 1 — Brute force: collect, sort, rebuild

function mergeBrute(a, b) {
  const vals = [];
  for (let c = a; c; c = c.next) vals.push(c.val);
  for (let c = b; c; c = c.next) vals.push(c.val);
  vals.sort((x, y) => x - y);   // ignores that inputs were sorted!
  return fromArray(vals);
}
vals = [1, 3, 5, 2, 4] ⇒ sorted [1, 2, 3, 4, 5] ⇒ new list.
Time O((n + m) log(n + m)), space O(n + m). It wastes the fact that the inputs are already sorted.

Approach 2 — Optimal: iterative with a dummy (the zipper)

function mergeTwoLists(a, b) {
  const dummy = new ListNode(0);
  let tail = dummy;
  while (a && b) {
    if (a.val <= b.val) {
      tail.next = a;
      a = a.next;
    } else {
      tail.next = b;
      b = b.next;
    }
    tail = tail.next;
  }
  tail.next = a || b;   // attach whatever is left
  return dummy.next;
}

Approach 3 — Recursive

function mergeRec(a, b) {
  if (!a) return b;
  if (!b) return a;
  if (a.val <= b.val) {
    a.next = mergeRec(a.next, b);
    return a;

  b.next = mergeRec(a, b.next);
  return b;

4.2 Remove Nth Node From End (LC 19)

Remove the 2nd node from the end of 1 → 2 → 3 → 4 → 5 → Output: 1 → 2 → 3 → 5

Analogy — the measuring stick
Hold a stick exactly n coaches long. Put its back end at the start and slide it forward. When the front end falls off the train, the back end is right before the coach to remove.
Think first: you don't know the length. If one pointer starts n + 1 steps ahead, where is the other one when the first falls off the end?

Approach 1 — Brute force: two passes

function removeNthBrute(head, n) {
  let L = 0;
  for (let c = head; c; c = c.next) L++;   // pass 1: length
  const dummy = new ListNode(0, head);
  let prev = dummy;
  for (let i = 0; i < L - n; i++) prev = prev.next;   // pass 2: stop before target
  prev.next = prev.next.next;
  return dummy.next;
}
1 → 2 → 3 → 4 → 5, n = 2 → walk 3 steps from dummy: 1, 2, 3 → prev = 3, prev.next = 5. Time O(n), space O(1), but two passes.

Approach 2 — Optimal: one pass with a gap

function removeNthFromEnd(head, n) {
  const dummy = new ListNode(0, head);
  let fast = dummy, slow = dummy;
  for (let i = 0; i <= n; i++) fast = fast.next;   // gap of n + 1
  while (fast) {
    fast = fast.next;
    slow = slow.next;
  }
  slow.next = slow.next.next;   // skip the target
  return dummy.next;
}

The dummy makes "remove the head" (n = 5) work without a special case — try it: fast falls off after the head start, slow stays at dummy, and dummy.next skips node 1.
Complexity: O(n) time, O(1) space, one pass.
Gap trick 📏
Move fast n + 1 steps first.
Then walk both until fast hits null.
slow is just before the target.

5.1 Palindrome Linked List (LC 234)

Does the list read the same both ways? 1 → 2 → 2 → 1 → true

Analogy — folding a paper strip
Fold the strip in half at the middle; if it's a palindrome, the two halves line up letter for letter. In a list we can't fold, so we find the middle (two runners) and turn the second half around (reverse), then compare.
Think first: a singly linked list can't walk backward. What would let you compare the last element with the first?

Approach 1 — Brute force: copy to an array, two pointers

function isPalindromeBrute(head) {
  const v = toArray(head);
  for (let l = 0, r = v.length - 1; l < r; l++, r--)
    if (v[l] !== v[r]) return false;
  return true;
}
v = [1, 2, 2, 1]: compare (1, 1) ✓, (2, 2) ✓ → true. Time O(n), space O(n).

Approach 2 — Optimal: middle + reverse second half + compare

function isPalindrome(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
  }                                       // 1. middle
  let prev = null;                        // 2. reverse from slow
  while (slow) {
    const nx = slow.next;
    slow.next = prev;
    prev = slow;
    slow = nx;
  }
  for (let a = head, b = prev; b; a = a.next, b = b.next)  // 3. compare
    if (a.val !== b.val) return false;
  return true;
}

Complexity: Time O(n), space O(1). In an interview, mention you'd reverse the second half back to restore the input.

5.2 Intersection of Two Linked Lists (LC 160)

A: 4 → 1 → 8 → 4 → 5 and B: 5 → 6 → 1 → 8 → 4 → 5 share the tail starting at node 8 (the same node object, not just the same value). Return that node.

Analogy — two walkers, equal distance
Walker A walks list A then list B; walker B walks list B then list A. Both walk exactly lenA + lenB steps, so they step onto the shared part at the same moment.
Think first: the lists have different lengths before they merge. How can you cancel out that difference?

Approach 1 — Brute force

Compare every pair — for each node of A, scan all of B: O(n · m) time, O(1) space.

Approach 2 — Better: a Set of A's nodes

function getIntersectionSet(a, b) {
  const seen = new Set();
  for (let c = a; c; c = c.next) seen.add(c);
  for (let c = b; c; c = c.next) if (seen.has(c)) return c;
  return null;
}
O(n + m) time, O(n) space. Note: B's node 1 has the same value as A's node 1 but is a different node, so it isn't matched.

Approach 3 — Optimal: switch heads

function getIntersectionNode(headA, headB) {
  let a = headA, b = headB;
  while (a !== b) {
    a = a ? a.next : headB;
    b = b ? b.next : headA;
  }
  return a;   // the meeting node, or null if they never meet
}

5.3 Add Two Numbers (LC 2)

Digits stored in reverse, one per node. 1₁ = 2 → 4 → 5, 1₂ = 5 → 6 → 4. Output: 7 → 0 → 8 → 1 (i.e. 542 + 465 = 1007).

Analogy — column addition on paper
Add the ones column first, carry into the tens, keep going. Because the digits are stored back to front, we can walk both lists forward and treat them as columns.
Think first: the two lists may have different lengths. After the shorter one runs out, what value do you use for its digits? And what happens if there's a carry left at the very end? 
function addTwoNumbers(l1, l2) {
  const dummy = new ListNode(0);
  let tail = dummy, carry = 0;
  while (l1 || l2 || carry) {
    const sum = (l1 ? l1.val : 0) + (l2 ? l2.val : 0) + carry;
    carry = Math.floor(sum / 10);
    tail.next = new ListNode(sum % 10);
    tail = tail.next;
    if (l1) l1 = l1.next;
    if (l2) l2 = l2.next;
  }
  return dummy.next;
}

Time O(max(n, m)), space O(1) extra (besides the answer). The || carry in the loop condition handles 5 + 5 = 10 → 0 → 1.

6. Interview Question Bank

Theory + 20 coding problems

Interviewers mix quick theory questions with coding. Practise saying the theory answers aloud in under 30 seconds, and for every coding question state the brute force first, then improve it.

6.1 Theory questions (with model answers)

QuestionModel answer
Array vs linked list — when would you choose a linked list? When you insert or delete often at known positions (O(1)) and don't need random access; arrays win for indexing and cache-friendliness.
Why is access O(n)? Nodes aren't contiguous; the only way to reach node i is to follow i links from the head.
What is a dummy (sentinel) node and why use it? A fake node before head, so inserting or deleting at the head needs no special case; return dummy.next.
Singly vs doubly linked list? Doubly nodes also store prev: O(1) delete of a known node and backward walks, at the cost of extra memory. Used in LRU caches.
How do you detect a cycle in O(1) space? Floyd's fast and slow pointers; if they meet there's a cycle, if fast hits null there isn't.
Why must fast and slow meet inside a cycle? Inside the loop, fast gains one node per step on slow, so the gap shrinks to zero.
How do you find the middle in one pass? Slow moves 1, fast moves 2; when fast reaches the end, slow is in the middle.
What's the space complexity of recursive reversal? O(n) for the call stack; iterative is O(1).
Can you delete a node given only that node? Yes, unless it's the tail: copy the next node's value into it and skip the next node.
Where are linked lists used in real systems? LRU caches, undo histories, hash-map collision chains, OS free-memory lists, music playlists.

6.3 Teacher's notes

  • Draw boxes and arrows for every pointer change. Linked-list bugs are invisible in your head and obvious on paper.
  • Before x.next.next, make sure x.next isn't null.
  • Compare nodes (a == b), not values — two different nodes can hold the same value (see the intersection dry run).
  • Lost head? Return dummy.next, never the original head after deletions.
  • Always test: empty list, one node, two nodes, and the operation at the head and at the tail.
Interview flow that impresses:
"Brute force is X with O(n) space. We can avoid the extra space with fast/slow pointers (or a dummy, or reversal), giving O(1)."
