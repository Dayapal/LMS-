1. Sorting Basics

Half a day  •  Key terms · Comparison table · Which one when

The simple sorts (bubble, selection, insertion) are O(n²) and fine up to about 10⁴ elements; merge sort and quick sort are O(n log n) and handle 10⁶ easily. Two properties decide which one to use besides speed: stability and in-place.

1.1 Key terms

  • In-place: uses only O(1) (or O(log n) stack) extra memory; sorts inside the same array.
  • Stable: equal elements keep their original relative order. Example: sort students [(Ravi, 80), (Asha, 90), (Neha, 80)] by marks. A stable sort always gives Ravi before Neha; an unstable one may swap them. This matters when you sort by one key after another.
  • Comparison sort: decides order only by comparing two elements. No comparison sort can beat O(n log n) in the worst case.
  • Non-comparison sort: uses the values themselves (e.g. counting sort), can be O(n + k) when values lie in a small range k.

2. Simple Sorts

2 days  •  Bubble · Selection · Insertion

All three are O(n²) and in-place. Learn them for the ideas — "bubble the largest to the end", "select the smallest", "insert into the sorted part" — because those ideas show up inside harder problems.

2.1 Bubble sort

Idea: compare neighbours and swap if out of order. After pass i, the largest remaining element has "bubbled" to the end. If a pass makes no swaps, the array is already sorted — stop early.

static void bubbleSort(int[] arr) {
  int n = arr.length;
  for (int i = 0; i < n - 1; i++) {
    boolean swapped = false;
    for (int j = 0; j < n - 1 - i; j++) {  // last i are already in place
      if (arr[j] > arr[j + 1]) {
        int t = arr[j];
        arr[j] = arr[j + 1];
        arr[j + 1] = t;
        swapped = true;
      }
    }
    if (!swapped) break;  // optimization: O(n) on sorted input
  }
}

2.2 Selection sort

Idea: for each position i, find the minimum of the unsorted part arr[i..n−1] and swap it into position i.

static void selectionSort(int[] arr) {
  int n = arr.length;
  for (int i = 0; i < n - 1; i++) {
    int minIdx = i;
    for (int j = i + 1; j < n; j++)
      if (arr[j] < arr[minIdx]) minIdx = j;
    int t = arr[i];
    arr[i] = arr[minIdx];
    arr[minIdx] = t;
  }
}

2.3 Insertion sort

Idea: like sorting playing cards in your hand. Keep arr[0..i−1] sorted; take key = arr[i], shift bigger elements one step right, and drop key into the gap.

static void insertionSort(int[] arr) {
  for (int i = 1; i < arr.length; i++) {
    int key = arr[i];
    int j = i - 1;
    while (j >= 0 && arr[j] > key) {
      arr[j + 1] = arr[j];   // shift right
      j--;
    }
    arr[j + 1] = key;
  }
}

On already-sorted input the while loop never runs ⇒ O(n). That's why insertion sort is used for small or nearly sorted arrays, and inside Java's own TimSort.

3. Merge Sort

2–3 days  •  Recursion primer · Divide & conquer · Split/merge tree

Merge sort splits the array in half, sorts each half recursively, then merges the two sorted halves. It is O(n log n) on every input and stable, at the cost of O(n) extra space.

3.1 Recursion primer (5 minutes)

A recursive function solves a problem by calling itself on a smaller version, and stops at a base case. Every recursive function needs both, or it runs forever (StackOverflowError).

static int fact(int n) {
  if (n <= 1) return 1;     // base case
  return n * fact(n - 1);   // smaller problem
}
Dry run of fact(4) — calls go down, answers come back up

Read the table top-down for the calls and bottom-up for the returns. Merge sort works exactly this way, but each call makes two smaller calls.

3.2 Divide and conquer

  1. Divide: split [low..high] at mid.
  2. Conquer: sort both halves recursively. Base case: a range of 1 element is already sorted.
  3. Combine: merge two sorted halves into one sorted range — the only step with real work.

3.3 Code

static void mergeSort(int[] arr, int low, int high) {
  if (low >= high) return;              // 0 or 1 element
  int mid = low + (high - low) / 2;
  mergeSort(arr, low, mid);
  mergeSort(arr, mid + 1, high);
  merge(arr, low, mid, high);
}

static void merge(int[] arr, int low, int mid, int high) {
  int[] temp = new int[high - low + 1];
  int i = low, j = mid + 1, k = 0;
  while (i <= mid && j <= high) {
    if (arr[i] <= arr[j]) temp[k++] = arr[i++];  // <= keeps it stable
    else temp[k++] = arr[j++];
  }
  while (i <= mid)  temp[k++] = arr[i++];        // leftovers from left
  while (j <= high) temp[k++] = arr[j++];        // leftovers from right
  for (int x = 0; x < temp.length; x++) arr[low + x] = temp[x];
}
// call: mergeSort(arr, 0, arr.length - 1);

A merge of n total elements takes O(n): each element is taken exactly once. This is the same two-pointer idea as "Merge Sorted Array" from Module 1.

3.6 Why O(n log n)?

The array is halved until size 1, so the tree has about log₂n levels. On each level, all merges together touch n elements. Total = n × log n.

For n = 8: 3 levels × 8 = 24 element moves, versus up to 8 × 8 = 64 comparisons for an O(n²) sort.
Space: O(n) for the temp arrays + O(log n) recursion stack. Time: O(n log n) on every input. Stable: yes. In-place: no.
Merge sort in one line 🌳
Split until size 1, then merge sorted halves — the merge is where all the work happens.

4. Quick Sort & Counting Sort

2 days  •  Lomuto partition · Worst case · O(n + k)

Quick sort picks a pivot, moves smaller elements to its left and larger to its right (partition), then recurses on both sides. It does all its work before recursing, while merge sort does it after.

4.1 Quick sort code (Lomuto partition, last element as pivot)

static void quickSort(int[] arr, int low, int high) {
  if (low >= high) return;
  int p = partition(arr, low, high);  // pivot lands at its final index p
  quickSort(arr, low, p - 1);
  quickSort(arr, p + 1, high);
}

static int partition(int[] arr, int low, int high) {
  int pivot = arr[high];
  int i = low - 1;                    // end of the "smaller than pivot" zone
  for (int j = low; j < high; j++) {
    if (arr[j] < pivot) {
      i++;
      swap(arr, i, j);
    }
  }
  swap(arr, i + 1, high);             // put pivot right after the smaller zone
  return i + 1;
}

Pivot 70 is now at index 4 — its final sorted position. Everything left is smaller, everything right is larger.

4.3 Complexity and the worst case

  • Average O(n log n): a pivot near the middle splits the array roughly in half, giving about log n levels.
  • Worst O(n²): an already sorted array with last-element pivot — each partition removes only the pivot, so n levels of n work.
  • Fix: pick a random pivot (swap a random index with high before partitioning) or the median of first, middle, last.
  • Space: O(log n) recursion stack on average; in-place, not stable.

4.5 Counting sort (non-comparison)

Idea: when values are small integers 0..k, count how many times each value appears, then write them back in order. No comparisons → O(n + k).

static void countingSort(int[] arr, int k) {  // values in 0..k
  int[] count = new int[k + 1];
  for (int x : arr) count[x]++;

  int idx = 0;
  for (int v = 0; v <= k; v++)
    while (count[v]-- > 0) arr[idx++] = v;
}
Dry run on [4, 2, 2, 8, 3, 3, 1], k = 8

Count012210001
Write back left to right: 1, 2, 2, 3, 3, 4, 8 → [1, 2, 2, 3, 3, 4, 8].
Use it only when k is small compared to n (marks 0–100, ages, letters a–z). For values up to 10⁹ the count array would be impossibly large. For negatives, shift every value by −min first.
Sorting cheat strip 📌
Nearly sorted → Insertion.
Guaranteed O(n log n) + stable → Merge.
Fast in practice + in-place → Quick.

5. Sorting in Java

1 day  •  Library sorts · Comparators · Multi-key

In real problems, call the library sort and spend your effort on the comparator. Primitive arrays use a Dual-Pivot Quicksort (not stable); object arrays and Lists use TimSort (stable, O(n log n)).

5.1 The calls you need

GoalCode
Sort int[] ascendingArrays.sort(arr);
Sort part of an array [from, to]Arrays.sort(arr, 2, 6);
Sort Integer[] descendingArrays.sort(boxed, Collections.reverseOrder());
Sort a ListCollections.sort(list); or list.sort(null);
Sort List descendinglist.sort(Collections.reverseOrder());
Sort Strings by lengthArrays.sort(words, (a, b) -> a.length() - b.length());
Trap: Collections.reverseOrder() does not work on int[] (primitives). Either sort ascending and read backwards, or use Integer[].

5.2 Comparators: the rule

A comparator (a, b) -> returns negative if a should come first, positive if b should come first, 0 if equal.

// Sort intervals by start time
int[][] iv = {{8, 10}, {1, 3}, {15, 18}, {2, 6}};
Arrays.sort(iv, (a, b) -> Integer.compare(a[0], b[0]));
// iv = {{1,3}, {2,6}, {8,10}, {15,18}}
Use Integer.compare(x, y), not x - y. With x = −2,147,483,648 and y = 1, x − y overflows to a large positive number and the order breaks silently.

5.3 Sorting objects by multiple keys

class Student {
  String name;
  int marks;
  Student(String n, int m) { name = n; marks = m; }
}

List<Student> list = new ArrayList<>(List.of(
  new Student("Ravi", 80),
  new Student("Asha", 90),
  new Student("Neha", 80)));

// Marks descending, then name ascending for ties
list.sort(Comparator.comparingInt((Student s) -> s.marks).reversed()
        .thenComparing(s -> s.name));

5.4 Complexity of library sorts

Sorting n elements costs O(n log n). If a solution sorts first, its total complexity is at least O(n log n), even if the rest is O(n). Always include it when you state your final complexity.

6. Sorting-Based Problem Patterns

2–3 days  •  Sort + scan · Merge-sort counting

Two patterns come up again and again: sort first, then one linear scan (intervals, meetings, pairs), and modify merge sort to count something during the merge (inversions, reverse pairs).

6.1 Sort + scan — Merge Intervals (LC 56)

Trigger  "intervals", "meetings", "overlapping".

Merge all overlapping intervals.
Input: [[8, 10], [1, 3], [15, 18], [2, 6]] → Output: [[1, 6], [8, 10], [15, 18]]

Brute force: compare every pair repeatedly → O(n²). Better: sort by start; then overlapping intervals sit next to each other, and one pass merges them → O(n log n).

static int[][] merge(int[][] iv) {
  Arrays.sort(iv, (a, b) -> Integer.compare(a[0], b[0]));
  List<int[]> res = new ArrayList<>();
  for (int[] cur : iv) {
    if (res.isEmpty() || cur[0] > res.get(res.size() - 1)[1]) {
      res.add(cur);                                        // no overlap: new interval
    } else {
      int[] last = res.get(res.size() - 1);
      last[1] = Math.max(last[1], cur[1]);                 // overlap: extend end
    }
  }
  return res.toArray(new int[0][]);
}

6.2 Merge sort + count — Count Inversions

Trigger  "count pairs i < j with arr[i] > arr[j]".

Idea: an inversion is any pair (i, j) with i < j and arr[i] > arr[j]. During the merge step, whenever we take an element from the right half, every remaining element in the left half forms an inversion with it. So add (mid − i + 1) to the count at that moment.

static long countInv(int[] arr, int low, int high) {
  if (low >= high) return 0;
  int mid = low + (high - low) / 2;
  return countInv(arr, low, mid) + countInv(arr, mid + 1, high)
       + mergeCount(arr, low, mid, high);
}
