Topic 01

Rules of Hooks

Why React cares about the order in which Hooks are called.

1.1 What Are React Hooks?

Hooks are special React functions that let functional components use React features such as state, effects, context, and references.

Some important built-in Hooks include:

HookPrimary purpose
useStateStore state
useEffectSynchronize with an external system
useRefRetain a value or reference a DOM element
useContextRead shared context values
useReducerManage state through a reducer
Custom HooksReuse stateful logic

For example:

Counter.jsxJSX
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  );
}

export default Counter;

Here, useState lets the component remember its count between renders.

1.2 Why Are There Rules for Hooks?

React needs to associate each Hook call with the correct component state or other Hook-related information.

To do that reliably, React expects Hooks to be called in a consistent order whenever a component renders.

If you call Hooks conditionally, the order of Hook calls can change between renders, making the component's behavior incorrect.

◆ Analogy: Numbered Lockers

Imagine a school where every student has an assigned locker number.

If the school changes the numbering randomly every day, students may open the wrong lockers.

React similarly needs Hook calls to occur in a predictable order so that the correct state and Hook data remain associated with the correct calls.

1.3 Rule 1: Only Call Hooks at the Top Level

Call Hooks at the top level of a React function component or another custom Hook.

Do not call Hooks inside:

  • Conditions
  • Loops
  • Nested functions
  • Event handlers
  • try/catch blocks

Incorrect example

✕ IncorrectJSX
import { useState } from "react";

function App({ isLoggedIn }) {
  if (isLoggedIn) {
    const [name, setName] = useState("Rahul");
  }

  return <h1>Welcome</h1>;
}

This violates the Rules of Hooks because useState is called conditionally.

If isLoggedIn changes, the number and order of Hooks called during rendering can differ.

Correct example

✓ CorrectJSX
import { useState } from "react";

function App({ isLoggedIn }) {
  const [name, setName] = useState("Rahul");

  if (!isLoggedIn) {
    return <h1>Please log in</h1>;
  }

  return <h1>Welcome, {name}</h1>;
}

The Hook is always called before the conditional return.

The component can return different JSX, but the Hook call remains at the top level.

Another incorrect example: A Hook inside a loop

✕ IncorrectJSX
function App() {
  const values = [1, 2, 3];

  values.forEach(value => {
    // Do not call Hooks here.
  });

  return <h1>Example</h1>;
}

You can loop through values and render JSX, but you must not call Hooks within the loop.

1.4 Rule 2: Call Hooks Only from React Functions

You should call Hooks from:

  1. React function components.
  2. Custom Hooks.

Do not call Hooks from ordinary JavaScript utility functions, event handlers, or class components.

Incorrect example

✕ IncorrectJSX
function calculateTotal() {
  const [total, setTotal] = useState(0);

  return total;
}

This is an ordinary JavaScript function. React does not recognize it as a component or a custom Hook.

Correct example

✓ CorrectJSX
import { useState } from "react";

function useTotal() {
  const [total, setTotal] = useState(0);

  return { total, setTotal };
}

function App() {
  const { total, setTotal } = useTotal();

  return (
    <button onClick={() => setTotal(current => current + 1)}>
      Total: {total}
    </button>
  );
}

export default App;

Notice that the custom Hook's name begins with use.

React's Hooks lint rules help detect many mistakes. See the official guide: https://react.dev/reference/rules/rules-of-hooks

◆ Remember

Call Hooks at the top level of components or custom Hooks. Keep their order consistent, and never call them inside conditions, loops, event handlers, or ordinary functions.

Topic 02

useEffect and the Effect Lifecycle

Synchronizing React with systems that live outside React.

This is one of the most important topics in real-world React development.

2.1 What Is useEffect?

useEffect is a React Hook that lets you synchronize a component with something outside React.

Examples include:

  • Fetching data from a remote API.
  • Connecting to a chat service.
  • Registering a browser event listener.
  • Starting a timer.
  • Synchronizing a third-party widget.
  • Subscribing to an external system.

Basic syntax:

syntaxJSX
import { useEffect } from "react";

useEffect(() => {
  // Synchronization logic

  return () => {
    // Optional cleanup logic
  };
}, [dependencies]);

An Effect consists of setup logic and, when necessary, cleanup logic.

Not every Effect needs cleanup. For example, a simple one-time browser notification after a particular synchronization might not need to be undone. But connections, subscriptions, listeners, and timers typically need a corresponding cleanup.

2.2 Analogy: Subscribing to a Service

Imagine subscribing to a messaging service.

When you start using it, you connect. If you switch to another channel, you disconnect from the old channel and connect to the new one. When you stop using the service, you disconnect.

useEffect is designed for this kind of synchronization:

  • Setup establishes the synchronization.
  • Dependencies indicate which values affect it.
  • Cleanup stops or reverses the previous synchronization.

2.3 Your First useEffect

App.jsxJSX
import { useEffect } from "react";

function App() {
  useEffect(() => {
    console.log("Effect executed");
  });

  return <h1>Learning useEffect</h1>;
}

export default App;

There is no dependency array in this example.

The Effect runs after the initial commit and after every subsequent commit of the component.

This means it can execute multiple times while the component is being used.

We will see how dependency arrays change this behavior in Topic 3.

2.4 Fetching Data from an API

One of the most common real-world examples is fetching remote data.

Imagine a student directory that displays information received from a server.

Users.jsxJSX
import { useEffect, useState } from "react";

function Users() {
  const [users, setUsers] = useState([]);

  useEffect(() => {
    async function fetchUsers() {
      const response = await fetch(
        "https://jsonplaceholder.typicode.com/users"
      );

      if (!response.ok) {
        throw new Error("Failed to fetch users");
      }

      const data = await response.json();

      setUsers(data);
    }

    fetchUsers().catch(error => {
      console.error(error);
    });
  }, []);

  return (
    <div>
      <h1>Users</h1>

      {users.map(user => (
        <p key={user.id}>{user.name}</p>
      ))}
    </div>
  );
}

export default Users;

Explanation

Step 1: Create state

stateJSX
const [users, setUsers] = useState([]);

The application initially has an empty list of users.

Step 2: Declare an Effect

effectJSX
useEffect(() => {
  // Fetch the users
}, []);

The empty dependency array indicates that the Effect has no reactive dependencies. It runs when the component first commits and does not re-synchronize merely because ordinary state changes occur.

In development, Strict Mode can run an extra setup-and-cleanup cycle. We will explain this shortly.

Step 3: Request the data

fetchJSX
const response = await fetch(
  "https://jsonplaceholder.typicode.com/users"
);

The browser makes an HTTP request to the example API.

Step 4: Convert the response to JSON

parseJSX
const data = await response.json();

This parses the response body into JavaScript data.

Step 5: Update React state

updateJSX
setUsers(data);

React receives the new list of users and can render the names in the UI.

The example is deliberately small. In a production application, you should also handle loading, errors, request cancellation, and other relevant concerns.

2.5 What Is the Effect Lifecycle?

It is useful to think of an Effect as an independent synchronization process rather than as code that always runs only once.

The sequence is:

This sequence applies when cleanup has been provided and when a re-synchronization or unmount makes cleanup necessary.

2.6 What Is Mounting, Updating, and Unmounting?

Mounting

Mounting means the component is added to the rendered UI.

An Effect runs after the initial commit.

Updating

An update occurs when React renders and commits new output. If an Effect's dependencies have changed, React cleans up the previous synchronization and runs the Effect again.

Unmounting

Unmounting means the component is removed from the rendered UI. React runs the Effect's cleanup function if one was returned.

2.7 Why Does useEffect Sometimes Run Twice in Development?

If the application is wrapped in StrictMode, React performs an extra development-only setup-and-cleanup cycle to help reveal missing cleanup logic.

For example:

main.jsxJSX
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);

In development, you may see an Effect's setup run, then its cleanup, and then its setup again.

This does not mean that Effects should be written to run only once regardless of circumstances. Instead, write setup and cleanup logic that can safely handle React's lifecycle.

For an API request, that often means cancelling or ignoring obsolete requests. For an event listener, it means removing the listener correctly.

You generally should not disable Strict Mode simply to hide an Effect problem.

Official reference: https://react.dev/reference/react/useEffect

◆ Remember

useEffect synchronizes React with external systems. Understand when setup runs, which changes trigger re-synchronization, and how cleanup reverses the previous setup.

Topic 03

Dependency Arrays

Telling React which reactive values affect your synchronization.

3.1 What Is a Dependency Array?

A dependency array is the second argument passed to useEffect.

It specifies the reactive values that the Effect depends on.

For example:

dependencyJSX
useEffect(() => {
  console.log("Current room:", roomId);
}, [roomId]);

Here, the Effect uses roomId.

When the component commits and the roomId dependency differs from its previous value, React runs the Effect again after cleaning up the previous Effect if one returned cleanup.

3.2 Why Do We Need Dependencies?

Imagine a chat application where users can switch between chat rooms.

If the roomId changes, the application may need to disconnect from the old room and connect to the new one.

A dependency array tells React which reactive values determine when that synchronization needs to be repeated.

◆ Analogy: A Delivery Address

Imagine a delivery service that has been given an address.

If the address changes, the delivery instructions must be updated.

The dependency array serves a similar purpose: it lists the values that determine whether the Effect's synchronization needs to be refreshed.

3.3 Three Dependency Patterns

There are three common patterns to understand.

Pattern 1: No Dependency Array

no arrayJSX
useEffect(() => {
  console.log("Runs after every commit");
});

The Effect runs after every committed render of the component.

Use this pattern only when the synchronization genuinely needs that behavior. In many situations, no dependency array can cause unnecessary work.

Pattern 2: Empty Dependency Array

empty arrayJSX
useEffect(() => {
  console.log("Runs after initial commit");

  return () => {
    console.log("Cleanup");
  };
}, []);

The Effect does not re-synchronize merely because ordinary component state changes. Its setup runs after the initial commit, and cleanup runs when it is removed. In development Strict Mode, there can be an additional setup-and-cleanup cycle.

If an Effect reads reactive values, those values generally need to be represented in its dependency array. An empty array is not a way to ignore real dependencies.

Pattern 3: Specific Dependencies

specificJSX
useEffect(() => {
  console.log("Search term:", searchTerm);
}, [searchTerm]);

The Effect re-synchronizes when searchTerm changes.

For multiple dependencies:

multipleJSX
useEffect(() => {
  console.log("Room:", roomId);
  console.log("Server:", serverUrl);
}, [roomId, serverUrl]);

When either dependency changes, the Effect re-synchronizes.

3.4 A Complete Example with a Dependency

SearchMessage.jsxJSX
import { useEffect, useState } from "react";

function SearchMessage() {
  const [searchTerm, setSearchTerm] = useState("");

  useEffect(() => {
    console.log("Search term changed:", searchTerm);
  }, [searchTerm]);

  return (
    <input
      value={searchTerm}
      onChange={event => setSearchTerm(event.target.value)}
      placeholder="Enter a search term"
    />
  );
}

export default SearchMessage;

Explanation:

  1. The input is controlled by searchTerm.
  2. Every edit requests a state update.
  3. React renders the updated state.
  4. If searchTerm changed, the Effect runs after the commit.
  5. The console displays the latest search term.

This example is intended to illustrate dependencies. If you only need to react to a user's input event, an event handler may be more suitable than an Effect.

3.5 Which Values Belong in the Dependency Array?

Every reactive value used by the Effect's setup code generally belongs in the dependency array.

Reactive values include props and values or functions declared directly in the component body.

Example:

ChatRoom.jsxJSX
function ChatRoom({ roomId }) {
  const [serverUrl, setServerUrl] = useState(
    "https://example.com"
  );

  useEffect(() => {
    connectToRoom(serverUrl, roomId);
  }, [serverUrl, roomId]);
}

Here, both serverUrl and roomId are used by the Effect, so both belong in the dependency array.

This example assumes that connectToRoom represents a defined external connection function; an actual implementation would also need to disconnect during cleanup.

3.6 How Does React Compare Dependencies?

React compares each dependency with its previous value using Object.is.

For primitive values such as strings and numbers, this usually behaves as you would expect.

Objects and functions require more attention.

For example:

App.jsxJSX
function App() {
  const options = { theme: "dark" };

  useEffect(() => {
    console.log("Effect executed");
  }, [options]);

  return <h1>Hello</h1>;
}

The options object is created again every time the component renders. It therefore has a different object identity, so the Effect may run on every render.

One solution is to create the object inside the Effect when it does not need to be a separate reactive dependency:

App.jsx — fixedJSX
function App() {
  useEffect(() => {
    const options = { theme: "dark" };

    console.log(options);
  }, []);

  return <h1>Hello</h1>;
}

This simplified example has no reactive dependency in its Effect body.

For real external synchronization, determine which values genuinely need to affect the Effect, and restructure the code where appropriate. Do not remove dependencies merely to suppress repeated execution.

◆ Remember

The dependency array describes the reactive values that affect the Effect. Include the real dependencies instead of guessing when the Effect should run.

Official reference: https://react.dev/reference/react/useEffect

Topic 04

Cleanup Functions

Reversing what an Effect set up — timers, listeners, and requests.

4.1 What Is a Cleanup Function?

A cleanup function is an optional function returned by an Effect's setup function.

It allows you to undo or stop what the Effect established.

Typical cleanup tasks include:

  • Clearing timers.
  • Removing event listeners.
  • Disconnecting subscriptions.
  • Closing connections.
  • Cancelling or ignoring obsolete API requests.

Syntax:

cleanup syntaxJSX
useEffect(() => {
  // Setup logic

  return () => {
    // Cleanup logic
  };
}, [dependencies]);

4.2 Why Is Cleanup Important?

Imagine an application that starts a timer every time a component is rendered but never stops the previous timer.

Soon, multiple timers may run at once. They can continue using resources or attempting to update state after the relevant work is no longer needed.

Cleanup prevents such unwanted behavior.

◆ Analogy: Opening and Closing a Shop

When a shop opens, employees turn on the necessary equipment.

When the shop closes, someone must turn that equipment off.

The setup establishes the resource, and cleanup releases it.

4.3 Example: A Timer with setInterval

Timer.jsxJSX
import { useEffect, useState } from "react";

function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const intervalId = setInterval(() => {
      setSeconds(current => current + 1);
    }, 1000);

    return () => {
      clearInterval(intervalId);
    };
  }, []);

  return <h1>Seconds: {seconds}</h1>;
}

export default Timer;

Explanation

Step 1: Start the timer

intervalJSX
const intervalId = setInterval(() => {
  setSeconds(current => current + 1);
}, 1000);

This schedules an update every second.

Step 2: Retain the timer identifier

intervalId stores the identifier returned by setInterval.

Step 3: Clear the timer

cleanupJSX
return () => {
  clearInterval(intervalId);
};

When React needs to clean up this Effect, it clears the interval.

The updater form of setSeconds ensures that each update works with the latest queued state rather than relying on a potentially stale value captured by the Effect.

4.4 Example: Adding and Removing an Event Listener

Suppose you want to respond when the browser window changes size.

WindowWidth.jsxJSX
import { useEffect, useState } from "react";

function WindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    function handleResize() {
      setWidth(window.innerWidth);
    }

    window.addEventListener("resize", handleResize);

    return () => {
      window.removeEventListener("resize", handleResize);
    };
  }, []);

  return <p>Window width: {width}px</p>;
}

export default WindowWidth;

Explanation

  • The initial state reads the browser's current width.
  • The Effect registers a resize listener.
  • When the browser window changes size, the handler updates the state.
  • React renders the new width.
  • Cleanup removes the listener.

This example is for a client-rendered Vite application. In server-rendered applications, browser globals such as window are not available during server rendering, so initialization needs to account for that.

4.5 Example: Cleaning Up an API Request

When the component no longer needs a request, you can abort it using AbortController.

UserList.jsxJSX
import { useEffect, useState } from "react";

function UserList() {
  const [users, setUsers] = useState([]);

  useEffect(() => {
    const controller = new AbortController();

    async function loadUsers() {
      try {
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/users",
          { signal: controller.signal }
        );

        if (!response.ok) {
          throw new Error("Failed to load users");
        }

        const data = await response.json();
        setUsers(data);
      } catch (error) {
        if (error.name !== "AbortError") {
          console.error(error);
        }
      }
    }

    loadUsers();

    return () => {
      controller.abort();
    };
  }, []);

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}

controller.abort() requests cancellation of the fetch. The catch block ignores the expected cancellation error but reports other errors.

In a production implementation, you would normally also manage loading and error states, as shown in the practical project later.

4.6 Does Cleanup Run Only When a Component Unmounts?

No.

React can run cleanup:

  1. Before re-running an Effect whose dependencies changed.
  2. When the component unmounts.
  3. During the extra development-only Strict Mode setup-and-cleanup cycle.

This means that cleanup should correspond to the specific synchronization created by the Effect, not to assumptions that the component is disappearing permanently.

◆ Remember

Whenever an Effect sets up a timer, subscription, listener, or connection, ask how that work will be stopped when the synchronization is no longer needed.

Official reference: https://react.dev/learn/synchronizing-with-effects

Topic 05

Avoiding Infinite Effect Loops

Diagnosing and fixing runaway synchronization.

5.1 What Is an Infinite Effect Loop?

An infinite effect loop occurs when an Effect repeatedly triggers state updates that cause the Effect's dependencies to change again.

The cycle often looks like this:

This can cause excessive rendering, repeated network requests, or a browser that becomes very slow.

5.2 Incorrect Example: Updating State Without Dependencies

✕ IncorrectJSX
import { useEffect, useState } from "react";

function App() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    setCount(current => current + 1);
  });

  return <h1>{count}</h1>;
}

There is no dependency array.

The Effect runs after each commit and updates the state again. That causes another render, which creates another opportunity for the Effect to execute.

The result is an ongoing update cycle.

5.3 Fix 1: Remove the Unnecessary Effect

If your only goal is to increment the count when a user clicks a button, use an event handler.

App.jsx — fixedJSX
import { useState } from "react";

function App() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h1>{count}</h1>

      <button onClick={() => setCount(current => current + 1)}>
        Increase
      </button>
    </div>
  );
}

export default App;

Now the state changes because of the user interaction rather than because every render triggers an Effect.

5.4 Fix 2: Use Dependencies Correctly

Suppose you want an Effect to respond to changes in a search term.

dependencyJSX
useEffect(() => {
  console.log("Search:", searchTerm);
}, [searchTerm]);

The Effect re-synchronizes when the search term changes instead of after every commit.

However, adding an empty array or another dependency list is not a universal fix. The list must correspond to the reactive values used by the Effect.

5.5 Fix 3: Avoid Creating Unnecessary Objects or Functions as Dependencies

Consider:

problemJSX
function App() {
  const options = { theme: "dark" };

  useEffect(() => {
    console.log("Connecting", options);
  }, [options]);

  return <h1>Hello</h1>;
}

A new options object is created every render. Because the object identity changes, React treats it as a changed dependency.

One approach is to create the object inside the Effect if its values do not need to be reactive:

fixedJSX
function App() {
  useEffect(() => {
    const options = { theme: "dark" };

    console.log("Connecting", options);
  }, []);

  return <h1>Hello</h1>;
}

If the options depend on changing props or state, restructure the Effect to use those actual dependencies rather than hiding them.

5.6 Fix 4: Avoid Using Effects to Calculate Derived Values

Incorrect:

✕ IncorrectJSX
const [firstName, setFirstName] = useState("Rahul");
const [lastName, setLastName] = useState("Sharma");
const [fullName, setFullName] = useState("");

useEffect(() => {
  setFullName(`${firstName} ${lastName}`);
}, [firstName, lastName]);

This introduces a separate state variable that duplicates information already represented by the first and last names.

Prefer:

✓ CorrectJSX
const [firstName, setFirstName] = useState("Rahul");
const [lastName, setLastName] = useState("Sharma");

const fullName = `${firstName} ${lastName}`;

Now the full name is calculated directly during rendering, and no Effect is required.

◆ Remember

If an Effect causes an infinite loop, inspect the state updates and dependencies. Determine whether the Effect is truly synchronizing with an external system or whether the logic belongs in rendering or an event handler instead.

Official reference: https://react.dev/learn/you-might-not-need-an-effect

Topic 06

useRef and DOM References

Persistent values and DOM access without causing re-renders.

6.1 What Is useRef?

useRef is a Hook that lets a component retain a value between renders without requesting a new render when that value changes.

Its common uses include:

  • Accessing a DOM element.
  • Focusing an input programmatically.
  • Scrolling to an element.
  • Storing a timer identifier.
  • Keeping a mutable value that is not needed to calculate the rendered UI.

Basic syntax:

syntaxJSX
import { useRef } from "react";

const myRef = useRef(initialValue);

A ref object has a .current property that you can read or update.

6.2 Analogy: A Bookmark

Imagine reading a long book and inserting a bookmark to remember a particular page.

The bookmark lets you find that position again without changing the book itself.

A ref works similarly: it retains a reference to a value or DOM element that you can access later.

6.3 Focus an Input Using useRef

SearchBox.jsxJSX
import { useRef } from "react";

function SearchBox() {
  const inputRef = useRef(null);

  function focusInput() {
    inputRef.current.focus();
  }

  return (
    <div>
      <input
        ref={inputRef}
        type="text"
        placeholder="Enter a search term"
      />

      <button onClick={focusInput}>
        Focus Input
      </button>
    </div>
  );
}

export default SearchBox;

Explanation

Step 1: Create the ref

refJSX
const inputRef = useRef(null);

The initial value is null because the input has not yet been attached to the ref during the first render.

Step 2: Attach the ref to the input

attachJSX
<input ref={inputRef} />

After React commits the DOM element, it assigns the input's DOM node to inputRef.current.

Step 3: Access the DOM element

accessJSX
inputRef.current.focus();

The browser's focus() method gives the input keyboard focus.

Step 4: Trigger the handler through a click

When the user clicks the button, the handler accesses the input through the ref and focuses it.

This is a useful example of an appropriate, direct interaction with a DOM element.

6.4 State vs. Ref

Both state and refs can retain values between renders, but they have different purposes.

6.5 Example: Store a Value Without Rendering It

ClickTracker.jsxJSX
import { useRef } from "react";

function ClickTracker() {
  const clickCountRef = useRef(0);

  function handleClick() {
    clickCountRef.current += 1;

    alert(`Clicks: ${clickCountRef.current}`);
  }

  return (
    <button onClick={handleClick}>
      Track Clicks
    </button>
  );
}

export default ClickTracker;

Each click increases the value retained in the ref.

The alert reads that value, but changing the ref does not cause React to re-render the component.

That means you should not expect text such as {clickCountRef.current} in the JSX to update automatically when the ref changes.

If a value needs to appear and update in the interface, use state.

6.6 Important Ref Rule

Do not normally read or write ref.current during rendering.

Use refs in event handlers and Effects, where they serve a specific purpose outside calculating the rendered output.

◆ Remember

Use useRef when you need a persistent reference or mutable value that does not drive rendering. Use useState when changes to the value should appear in the UI.

Official reference: https://react.dev/learn/referencing-values-with-refs

Topic 07

useContext and Shared Values

Sharing a value with many descendants without prop drilling.

7.1 What Is Context?

Context allows a parent component to make a value available to descendant components without manually passing it through every intermediate component as props.

Common uses include:

  • Theme preferences.
  • Current user information.
  • Locale or language preferences.
  • Application-level settings.
  • Other values shared by many components in a subtree.

useContext reads the nearest provider's value for a particular context.

7.2 Why Do We Need Context?

Imagine an application with this component tree:

App └── Dashboard └── Sidebar └── UserProfile └── ThemeLabel

Suppose ThemeLabel needs the current theme.

Without Context, you might have to pass the theme through Dashboard, Sidebar, and UserProfile, even if those components do not use the value themselves.

Context helps avoid this unnecessary prop passing.

◆ Analogy: A Building-Wide Announcement

Imagine a building's management system announces a common setting to every department.

Each department that needs the announcement can access it without requiring every room in between to repeat it.

Context provides a similar way to make a shared value available throughout part of a component tree.

7.3 Step 1: Create a Context

Create a file named ThemeContext.jsx.

ThemeContext.jsxJSX
import { createContext } from "react";

const ThemeContext = createContext("light");

export default ThemeContext;

Here:

  • createContext creates a context object.
  • "light" is the default value used when there is no matching provider above a component.
  • The context is exported so other components can use it.

The default value is a fallback; it is not a shared state store that automatically changes.

7.4 Step 2: Provide a Value

App.jsxJSX
import { useState } from "react";
import ThemeContext from "./ThemeContext.jsx";
import Profile from "./Profile.jsx";

function App() {
  const [theme, setTheme] = useState("light");

  function toggleTheme() {
    setTheme(current =>
      current === "light" ? "dark" : "light"
    );
  }

  return (
    <ThemeContext.Provider value={theme}>
      <main>
        <button onClick={toggleTheme}>
          Toggle Theme
        </button>

        <Profile />
      </main>
    </ThemeContext.Provider>
  );
}

export default App;

The context provider makes the current theme available to descendant components.

When theme changes, React updates the provided value, and components reading the context receive the new value.

7.5 Step 3: Read the Context Using useContext

Create Profile.jsx:

Profile.jsxJSX
import { useContext } from "react";
import ThemeContext from "./ThemeContext.jsx";

function Profile() {
  const theme = useContext(ThemeContext);

  return (
    <section className={`profile ${theme}`}>
      <h1>Student Profile</h1>
      <p>Current theme: {theme}</p>
    </section>
  );
}

export default Profile;

Explanation:

  • useContext(ThemeContext) reads the nearest applicable theme value.
  • The class name changes according to the value.
  • The paragraph displays the current theme.
  • When the provider's value changes, the context-reading component updates accordingly.

The class names can be styled with CSS:

styles.cssCSS
.profile.light {
  background: white;
  color: #222;
}

.profile.dark {
  background: #222;
  color: white;
}

7.6 Does Context Replace Props?

No.

Props are still excellent when passing values directly between related components.

Context becomes useful when a value must be shared across many descendants or through a deeply nested component tree.

For example:

  • Use props to pass the title to a specific course card.
  • Use Context when many components need the same theme or application-level settings.

7.7 Does Context Automatically Manage State?

Context provides and distributes values. It does not automatically make a value changeable.

In the example, useState stores the theme, and Context distributes it. The event handler changes the state in the parent.

That distinction is important: state stores the value; Context makes the value available to descendants.

◆ Remember

Use Context to share values across a component tree without passing props through every intermediate component. Combine it with state when the shared value needs to change.

Official references:

  • https://react.dev/reference/react/useContext
  • https://react.dev/reference/react/createContext
Topic 08

useReducer for Complex State

Organizing state transitions around actions.

8.1 What Is useReducer?

useReducer is a React Hook for managing state through a reducer function.

It is useful when:

  • Several actions update the same state.
  • State transitions are becoming difficult to organize.
  • A component manages a complex object or collection.
  • You want to separate update logic from rendering logic.

Basic syntax:

syntaxJSX
const [state, dispatch] = useReducer(
  reducer,
  initialState
);

Here:

  • state is the current state.
  • dispatch sends an action to the reducer.
  • reducer receives the current state and action and returns the next state.
  • initialState provides the starting state.

8.2 Analogy: A Customer Service Desk

Imagine a service desk that receives different kinds of requests.

Examples include:

  • Create a ticket.
  • Close a ticket.
  • Reopen a ticket.
  • Delete a ticket.

The request is sent to a central handler, which decides what the new data should look like.

A reducer follows a similar idea. You describe the requested action, and the reducer determines the next state.

8.3 Understanding the Reducer Function

A reducer usually receives two parameters:

shapeJSX
function reducer(state, action) {
  // Determine and return the next state
}

For example:

counterReducerJSX
function counterReducer(state, action) {
  switch (action.type) {
    case "increment":
      return state + 1;

    case "decrement":
      return state - 1;

    case "reset":
      return 0;

    default:
      return state;
  }
}

Explanation:

  • The reducer receives the current count and an action.
  • It checks action.type.
  • Each case calculates a new state.
  • The default case returns the current state for an unknown action.

A reducer should be a pure function. It should not perform API requests, modify external variables, or mutate the existing state.

8.4 Build a Counter with useReducer

Counter.jsxJSX
import { useReducer } from "react";

function counterReducer(state, action) {
  switch (action.type) {
    case "increment":
      return state + 1;

    case "decrement":
      return state - 1;

    case "reset":
      return 0;

    default:
      return state;
  }
}

function Counter() {
  const [count, dispatch] = useReducer(
    counterReducer,
    0
  );

  return (
    <div>
      <h1>Count: {count}</h1>

      <button onClick={() => dispatch({ type: "increment" })}>
        Increase
      </button>

      <button onClick={() => dispatch({ type: "decrement" })}>
        Decrease
      </button>

      <button onClick={() => dispatch({ type: "reset" })}>
        Reset
      </button>
    </div>
  );
}

export default Counter;

How It Works

Step 1: Initialize state

initJSX
const [count, dispatch] = useReducer(counterReducer, 0);

The counter starts at 0.

Step 2: Dispatch an action

dispatchJSX
dispatch({ type: "increment" });

This sends the action { type: "increment" } to the reducer.

Step 3: Calculate the new state

caseJSX
case "increment":
  return state + 1;

The reducer calculates the next count.

Step 4: Render the next state

React stores the returned state and renders the component with the updated count.

8.5 Example: A Task Reducer

A task manager can use several action types.

taskReducerJSX
function taskReducer(state, action) {
  switch (action.type) {
    case "add":
      return [...state, action.task];

    case "delete":
      return state.filter(task => task.id !== action.id);

    case "toggle":
      return state.map(task =>
        task.id === action.id
          ? { ...task, completed: !task.completed }
          : task
      );

    default:
      return state;
  }
}

This reducer supports three operations.

Add

addJSX
dispatch({
  type: "add",
  task: {
    id: crypto.randomUUID(),
    title: "Learn useReducer",
    completed: false
  }
});

Delete

deleteJSX
dispatch({
  type: "delete",
  id: taskId
});

Toggle completion

toggleJSX
dispatch({
  type: "toggle",
  id: taskId
});

The action object communicates what should happen. The reducer determines how the state changes.

8.6 useState vs. useReducer

Use caseCommon choice
A single counteruseState
A simple input valueuseState
A boolean toggleuseState
Several related actions updating one state structureuseReducer
Complex state transitionsuseReducer
A task list with add, delete, and toggle actionsEither can work; useReducer can organize the transitions clearly

useReducer is not automatically better for every application. Choose it when the reducer makes your state-update logic easier to understand and maintain.

◆ Remember

useReducer centralizes state-transition logic. Dispatch actions that describe what happened, and let a pure reducer calculate the next state.

Official reference: https://react.dev/reference/react/useReducer

Topic 09

Custom Hooks

Packaging reusable stateful logic into your own Hooks.

9.1 What Is a Custom Hook?

A custom Hook is a JavaScript function that combines React Hooks into reusable logic.

Custom Hooks let you extract repeated behavior from components without copying the same state, Effects, or event handlers into multiple places.

Examples include:

  • useUsers
  • useOnlineStatus
  • useLocalStorage
  • useForm
  • useWindowWidth

A custom Hook's name must begin with use, followed by a capital letter.

9.2 Why Do We Need Custom Hooks?

Imagine that three components need to fetch user information from an API.

Each component might require:

  • State for the response data.
  • Loading state.
  • Error handling.
  • A useEffect call.
  • Request cleanup.

Duplicating the same logic in all three components makes the code harder to maintain.

A custom Hook lets you organize the shared behavior in one place.

◆ Analogy: A Reusable Machine

Imagine an office needs the same printing process in several departments.

Rather than asking every department to build its own printer, they can use the same type of machine.

A custom Hook similarly packages reusable logic behind a function call.

9.3 Create a Simple useCounter Hook

Create useCounter.js:

useCounter.jsJSX
import { useState } from "react";

function useCounter(initialValue = 0) {
  const [count, setCount] = useState(initialValue);

  function increment() {
    setCount(current => current + 1);
  }

  function decrement() {
    setCount(current => current - 1);
  }

  return {
    count,
    increment,
    decrement
  };
}

export default useCounter;

Now use it inside a component:

Counter.jsxJSX
import useCounter from "./useCounter.js";

function Counter() {
  const { count, increment, decrement } = useCounter(10);

  return (
    <div>
      <h1>{count}</h1>
      <button onClick={increment}>Increase</button>
      <button onClick={decrement}>Decrease</button>
    </div>
  );
}

export default Counter;

The component uses the Hook without needing to define the counter logic itself.

9.4 Do Custom Hooks Share the Same State?

No. This distinction is important.

If two components each call useCounter(), each call creates its own state.

The logic is reusable, but the state is independent.

For example:

App.jsxJSX
function App() {
  return (
    <>
      <Counter />
      <Counter />
    </>
  );
}

Each counter manages its own count.

If multiple components need to share the same count, lift the state up to a common parent or use an appropriate shared-state pattern such as Context.

9.5 Example: A Custom Hook for Fetching Users

Create useUsers.js:

useUsers.jsJSX
import { useEffect, useState } from "react";

function useUsers() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    const controller = new AbortController();

    async function loadUsers() {
      setLoading(true);
      setError("");

      try {
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/users",
          { signal: controller.signal }
        );

        if (!response.ok) {
          throw new Error("Failed to fetch users");
        }

        const data = await response.json();

        setUsers(data);
      } catch (err) {
        if (err.name !== "AbortError") {
          setError(err.message);
        }
      } finally {
        if (!controller.signal.aborted) {
          setLoading(false);
        }
      }
    }

    loadUsers();

    return () => {
      controller.abort();
    };
  }, []);

  return {
    users,
    loading,
    error
  };
}

export default useUsers;

Explanation

State

The Hook manages three values:

  • users: the received data.
  • loading: whether the request is in progress.
  • error: the error message, if something goes wrong.

Effect

The Effect starts the request when the component using this Hook first commits.

Cleanup

The AbortController cancels the request when the Effect is cleaned up.

Return value

The Hook returns the three values to the component using it.

9.6 Use the Custom Hook in a Component

UserDirectory.jsxJSX
import useUsers from "./useUsers.js";

function UserDirectory() {
  const { users, loading, error } = useUsers();

  if (loading) {
    return <p>Loading users...</p>;
  }

  if (error) {
    return <p>Error: {error}</p>;
  }

  return (
    <div>
      <h1>User Directory</h1>

      {users.map(user => (
        <article key={user.id} key={user.id}>
          <h2>{user.name}</h2>
          <p>{user.email}</p>
        </article>
      ))}
    </div>
  );
}

export default UserDirectory;

Use the corrected article opening tag in your actual code:

✓ CorrectedJSX
<article key={user.id}>

The component now focuses on displaying the UI rather than implementing the request and its lifecycle.

9.7 When Should You Create a Custom Hook?

Custom Hooks are useful when you have a meaningful unit of reusable stateful logic.

Examples:

  • A reusable API request pattern.
  • Online/offline status tracking.
  • Repeated form input behavior.
  • Synchronizing a browser event listener.
  • Shared timer logic.

Do not create a custom Hook for every small calculation. A regular utility function is usually better for logic that does not use Hooks.

◆ Remember

Custom Hooks let you reuse stateful logic. They do not automatically share a single state value among components that call them.

Official reference: https://react.dev/learn/reusing-logic-with-custom-hooks

Topic 10

When Not to Use useEffect

Knowing when ordinary calculations and event handlers are the better answer.

This topic is just as important as learning how to use useEffect.

A common beginner mistake is to use an Effect whenever a value changes. However, Effects are mainly for synchronizing React with external systems, not for coordinating every part of your application's data flow.

10.1 Do Not Use Effects to Calculate Derived Values

Imagine two state variables:

stateJSX
const [firstName, setFirstName] = useState("Rahul");
const [lastName, setLastName] = useState("Sharma");

You want to display the full name.

Unnecessary approach

✕ UnnecessaryJSX
const [fullName, setFullName] = useState("");

useEffect(() => {
  setFullName(`${firstName} ${lastName}`);
}, [firstName, lastName]);

The fullName value is redundant because it can be calculated from two existing values.

Better approach

✓ BetterJSX
const fullName = `${firstName} ${lastName}`;

Now the full name is calculated during rendering. No additional state or Effect is required.

10.2 Do Not Use Effects to Handle User Events

Imagine a user clicks a purchase button.

The purchase action happens because of a specific interaction. That logic generally belongs in the event handler.

Unnecessary approach

✕ UnnecessaryJSX
const [shouldBuy, setShouldBuy] = useState(false);

useEffect(() => {
  if (shouldBuy) {
    // Process purchase
  }
}, [shouldBuy]);

This introduces an extra piece of state and an Effect to respond to something already known in the event handler.

Better approach

✓ BetterJSX
function handlePurchase() {
  // Validate the form and begin the purchase flow.
}

Connect it directly:

JSXJSX
<button onClick={handlePurchase}>
  Purchase
</button>

This is simpler because the action is directly connected to the user interaction.

In a real application, the purchase handler would need appropriate validation, server communication, and error handling.

10.3 Do Use Effects to Synchronize with External Systems

An Effect is appropriate for work that must be synchronized with something outside React.

Examples:

  • Connecting and disconnecting from a chat service.
  • Registering and removing a browser listener.
  • Managing a timer.
  • Fetching data when an appropriate reactive dependency changes.
  • Synchronizing a third-party widget.

Example:

external syncJSX
useEffect(() => {
  const controller = new AbortController();

  async function loadData() {
    // Request data using controller.signal.
  }

  loadData();

  return () => {
    controller.abort();
  };
}, []);

This example is a sketch of an external request synchronization. A complete request should also handle loading states and errors.

10.4 Should You Use an Effect for Every State Update?

No.

Use ordinary JavaScript calculations for derived values and event handlers for actions initiated by users.

Use an Effect when the component must synchronize with an external system.

RequirementTypical approach
Display a full name derived from two valuesCalculate during rendering
Filter an array based on the selected filterCalculate during rendering
Increase a counter after a clickEvent handler and state setter
Submit a form after the user submits itForm event handler
Fetch data in response to a reactive parameterEffect or a suitable data-fetching abstraction
Register a browser listenerEffect with cleanup
Focus an input after the user clicks a buttonEvent handler using a ref
Share a theme through nested componentsContext

10.5 How Can You Decide Whether an Effect Is Necessary?

Ask yourself:

  1. Am I synchronizing with something outside React?
  2. Does the task need to happen because of rendering or a changed reactive value?
  3. Could I calculate the required output directly from state or props instead?
  4. Is this action better handled directly by an event handler?
  5. If I set up an external process, how will I clean it up?

These questions will help you avoid unnecessary Effects and make your components easier to maintain.

◆ Remember

useEffect is a synchronization tool, not a replacement for event handling, derived calculations, or ordinary application logic.

Official reference: https://react.dev/learn/you-might-not-need-an-effect

Topic 11

Choosing the Right Hook

A decision guide for matching the Hook to the problem.

Now that you have studied the major Hooks, let's learn how to choose among them.

11.1 Why Do We Need to Choose the Right Hook?

Two Hooks may appear to solve similar problems, but they serve different purposes.

For example, both useState and useRef can remember information between renders. However, updating state can trigger a render, while updating a ref does not.

Choosing the wrong Hook can lead to stale UI, unnecessary Effects, or confusing state management.

11.2 Hook Selection Table

ProblemAppropriate toolWhy
Remember an input valueuseStateThe UI must reflect changes
Toggle a modal or dropdownuseStateThe open/closed state affects rendering
Synchronize with an external systemuseEffectSetup and cleanup manage synchronization
Focus an inputuseRefThe browser DOM node must be accessed
Store a timer IDuseRefThe ID usually does not drive rendering
Share a theme across descendantsuseContextDeeply nested components can read one shared value
Manage several related state transitionsuseReducerActions and reducer logic organize updates
Reuse complex stateful logicCustom HookThe behavior can be extracted and reused
Display a calculated countOrdinary variableIt can be derived directly from existing values
Filter data for displayOrdinary variable during renderThe filtered result can be recalculated from current inputs

11.3 useState vs. useReducer

Choose useState for straightforward values such as a selected tab, input text, or counter.

Choose useReducer when the update logic is complicated enough that a separate reducer with named actions makes the code easier to understand.

11.4 useState vs. useRef

Choose useState when a change should affect the rendered UI.

Choose useRef for persistent values that do not need to trigger a render or when you need a reference to a DOM node.

For example, if the user changes the selected theme, use state. If the user clicks a button that focuses an input, use a ref.

11.5 useEffect vs. an Event Handler

Use an event handler when a particular user action triggers the work.

Use an Effect when the work needs to synchronize with an external system as a consequence of rendering and reactive values.

For example:

  • Click the button → run a button handler.
  • Update a selected room ID → synchronize the chat connection with that room using an Effect.

11.6 Context vs. Props

Use props to pass data to a direct child or through a small component hierarchy.

Use Context when a value is needed by many descendants and passing it through every intermediate component becomes cumbersome.

Remember that Context distributes values; it does not automatically replace the need to decide where state should live.

11.7 Built-in Hooks vs. Custom Hooks

Use built-in Hooks such as useState, useEffect, and useRef for their intended React features.

Create a custom Hook when you want to package meaningful stateful behavior so it can be reused across components.

For example:

custom hook callJSX
const { users, loading, error } = useUsers();

This is easier to read than repeating a large block of fetching and cleanup logic in each component that needs the same behavior.

◆ Remember

The best Hook is the one that matches the problem. Do not introduce a more complex Hook when a simple state variable, event handler, or derived value is sufficient.

    });
  }

  function focusSearch() {
    searchInputRef.current?.focus();
  }

  return (
    <ThemeContext.Provider value={theme}>
      <main className={`app ${theme}`}>
        <header className="app-header">
          <div>
            <h1>User Directory</h1>
            <p>Find users and manage your favourites.</p>
          </div>

          <button
            onClick={() =>
              setTheme(current =>
                current === "light" ? "dark" : "light"
              )
            }
          >
            Switch Theme
          </button>
        </header>

        <section className="search-section">
          <input
            ref={searchInputRef}
            value={searchTerm}
            onChange={event =>
              setSearchTerm(event.target.value)
            }
            placeholder="Search users by name"
          />

          <button onClick={focusSearch}>
            Focus Search
          </button>

          <button onClick={reload}>
            Reload Users
          </button>
        </section>

        <p>Total users: {users.length}</p>
        <p>Visible users: {visibleUsers.length}</p>
        <p>Favourites: {favoriteIds.length}</p>

        <button onClick={() => dispatch({ type: "clear" })}>
          Clear Favourites
        </button>

        {loading && <p>Loading users...</p>}

        {error && (
          <div className="error">
            <p>Could not load users: {error}</p>
            <button onClick={reload}>Try Again</button>
          </div>
        )}

        {!loading && !error && visibleUsers.length === 0 && (
          <p>No users match your search.</p>
        )}

        {!loading && !error && (
          <section className="user-grid">
            {visibleUsers.map(user => (
              <UserCard
                key={user.id}
                user={user}
                isFavorite={favoriteIds.includes(user.id)}
                onToggleFavorite={toggleFavorite}
              />
            ))}
          </section>
        )}
      </main>
    </ThemeContext.Provider>
  );
}

export default App;

The parent passes user information and callback functions to each UserCard. The cards read the theme from Context and request favourite updates through the supplied callback.

Reference

Common Beginner Mistakes

Eight pitfalls every new React Hooks developer runs into — and how to fix them.

Mistake 1: Calling Hooks Conditionally

Incorrect:

✕ IncorrectJSX
if (isLoggedIn) {
  useEffect(() => {
    console.log("Logged in");
  }, []);
}

Correct:

✓ CorrectJSX
useEffect(() => {
  if (isLoggedIn) {
    console.log("Logged in");
  }
}, [isLoggedIn]);

The Hook remains at the top level, and the condition is inside the Effect.

However, if the only goal is to respond to a login click, an event handler may be more appropriate than an Effect.

Mistake 2: Forgetting Effect Dependencies

If the Effect reads a changing prop or state value, include the reactive value in the dependency array.

Do not suppress the Hooks linter to hide a missing dependency. Instead, adjust the code so the dependencies correctly represent the synchronization.

Mistake 3: Assuming Cleanup Runs Only Once

Cleanup can run before a changed Effect is re-executed, during unmount, and during the extra development-only Strict Mode cycle.

Write cleanup to undo the setup it belongs to.

Mistake 4: Using a Ref When State Is Required

If a changed value must update the visible interface, use state.

Updating ref.current does not trigger a render.

Mistake 5: Putting Every Shared Value in Context

Context is useful for values shared across many descendants. For values that only one component or a direct child needs, props are often simpler.

Mistake 6: Using useReducer for Every State Variable

A simple boolean or input value does not necessarily need a reducer. Choose useReducer when centralized state-transition logic improves clarity.

Mistake 7: Creating Custom Hooks That Do Nothing Useful

A custom Hook should package meaningful reusable logic. If a function only performs a simple calculation and does not use Hooks, a normal JavaScript function is usually sufficient.

Mistake 8: Using an Effect for a Derived Value

Calculate filtered lists, totals, and other values directly from the source data when possible. This avoids duplicated state and unnecessary rendering cycles.

Revision

Quick Revision Notes

One-sentence definitions for every concept in Phase 3.

Rules of Hooks

Call Hooks at the top level of function components or custom Hooks and keep the call order consistent.

useEffect

Synchronizes React with external systems.

Effect lifecycle

Setup runs after commits as needed; cleanup runs before re-synchronization and on unmount when provided.

Dependency array

Describes the reactive values that determine when an Effect needs to re-synchronize.

Cleanup function

Undoes or stops work established by an Effect.

Infinite effect loop

A repeated cycle where an Effect causes state changes that make the Effect execute again.

useRef

Retains a value or provides a reference to a DOM element without triggering a render when the ref changes.

useContext

Reads a value from the closest matching provider above a component.

useReducer

Manages state using a reducer function and dispatched actions.

Custom Hook

Reusable function that combines React Hooks to share stateful logic between components.

When not to use useEffect

Avoid using Effects for ordinary event handling and values that can be calculated during rendering.

Choosing the right Hook

Match the Hook to the requirement rather than introducing extra complexity.
