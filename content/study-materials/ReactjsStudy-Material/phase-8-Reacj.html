Section 01

CSS and CSS Modules

Styling React components with familiar CSS — and scoping it cleanly.

1.1 What is CSS?

CSS stands for Cascading Style Sheets. It controls how HTML elements look on the screen.

HTML defines the structure. CSS controls the appearance.

For example, a React component might display a button:

Welcome.jsxJSX
function Welcome() {
  return (
    <div>
      <h1>Welcome to my application</h1>
      <button>Get Started</button>
    </div>
  );
}

export default Welcome;

Without styling, the browser displays default styles. CSS allows us to control the colors, spacing, layout, borders, and other visual properties.

Create a file named App.css:

App.cssCSS
.welcome {
  padding: 24px;
  background-color: #f8fafc;
  color: #0f172a;
  border-radius: 12px;
}

.welcome h1 {
  font-size: 28px;
  margin-bottom: 16px;
}

.welcome button {
  background-color: #4f46e5;
  color: white;
  border: none;
  padding: 10px 18px;
  border-radius: 8px;
  cursor: pointer;
}

.welcome button:hover {
  background-color: #4338ca;
}

Import the stylesheet into App.jsx:

App.jsxJSX
import "./App.css";

function App() {
  return (
    <div className="welcome">
      <h1>Welcome to React</h1>
      <button>Get Started</button>
    </div>
  );
}

export default App;

Understand what happened

  • import "./App.css" loads the stylesheet into the application.
  • className="welcome" attaches a CSS class to the element.
  • .welcome selects elements with that class.
  • padding adds space inside the element.
  • border-radius rounds the corners.
  • :hover applies styles when the pointer hovers over the button.

Important: In React JSX, use className instead of HTML's class attribute.

1.2 How CSS connects to React

React components describe the UI. CSS styles that UI.

Think of building a house:

  • React components are the rooms and furniture.
  • CSS determines the paint, spacing, shapes, and arrangement.
  • Component props can change which content or styling is displayed.

React does not require a particular styling solution. You can use normal CSS, CSS Modules, Tailwind CSS, or a component system. You can also combine these approaches when there is a good reason.

1.3 The problem with ordinary CSS

Imagine you have a large application with many components.

Your ProfileCard.jsx contains:

ProfileCard.jsxJSX
<div className="card">Profile information</div>

Your ProductCard.jsx also contains:

ProductCard.jsxJSX
<div className="card">Product information</div>

And your global CSS contains:

styles.cssCSS
.card {
  padding: 20px;
  background-color: white;
  border-radius: 12px;
}

Both components will receive those styles, whether that was intended or not.

This can be perfectly acceptable when the class is deliberately shared. However, generic class names can create unwanted conflicts as an application grows.

One solution is CSS Modules.

1.4 What are CSS Modules?

CSS Modules let you write normal CSS while keeping class names locally scoped to a component's stylesheet.

For a typical Vite React project, name a stylesheet with the .module.css suffix:

ProfileCard.module.css

ProfileCard.module.cssCSS
.card {
  padding: 20px;
  background-color: white;
  border: 1px solid #e2e8f0;
  border-radius: 12px;
}

.title {
  font-size: 20px;
  font-weight: 700;
}

.description {
  color: #64748b;
  line-height: 1.6;
}

Create ProfileCard.jsx:

ProfileCard.jsxJSX
import styles from "./ProfileCard.module.css";

function ProfileCard() {
  return (
    <article className={styles.card}>
      <h2 className={styles.title}>Rahul Sharma</h2>

      <p className={styles.description}>
        Frontend Developer
      </p>
    </article>
  );
}

export default ProfileCard;

How does this work?

importJSX
import styles from "./ProfileCard.module.css";

The imported styles object gives you access to the locally scoped class names.

classNameJSX
className={styles.card}

This applies the generated class associated with .card in that module.

The final class name in the browser is transformed by the build tooling, helping avoid accidental collisions with a different module's class name.

For a class with a hyphen, use bracket notation:

.profile-cardCSS
.profile-card {
  padding: 20px;
}
JSXJSX
<div className={styles["profile-card"]}>
  Profile
</div>

1.5 Conditional CSS Module classes

Sometimes a component has more than one visual state.

For example, an alert can be successful or display an error.

Alert.module.css:

Alert.module.cssCSS
.alert {
  padding: 12px 16px;
  border-radius: 8px;
}

.success {
  background-color: #dcfce7;
  color: #166534;
}

.error {
  background-color: #fee2e2;
  color: #991b1b;
}

Alert.jsx:

Alert.jsxJSX
import styles from "./Alert.module.css";

function Alert({ type = "success", children }) {
  const typeClass =
    type === "error" ? styles.error : styles.success;

  return (
    <div className={`${styles.alert} ${typeClass}`} role="status">
      {children}
    </div>
  );
}

export default Alert;

Usage:

usageJSX
<Alert type="success">
  Your profile has been saved.
</Alert>

<Alert type="error">
  Something went wrong.
</Alert>

The shared class handles the common layout. The conditional class controls the appearance.

For a production alert system, choose the appropriate ARIA role and announcement behavior for the kind of message being shown. For instance, urgent errors may require role="alert" rather than role="status".

1.6 When should you use CSS Modules?

CSS Modules are useful when:

  • You already know CSS and want to keep using it.
  • Components have custom or complicated styling.
  • You want to avoid accidental global class-name collisions.
  • You need selectors, pseudo-elements, or animations that are easier to maintain in CSS files.
  • A team prefers styling to live near its component.

They are not mandatory for every component. Choose a styling approach based on the application, team, and complexity of the UI.

Tailwind CSS with React

Utility-first styling composed directly in your JSX.

2.1 What is Tailwind CSS?

Tailwind CSS is a utility-first CSS framework.

Instead of writing a separate CSS class for every small styling decision, you combine utility classes directly in your JSX.

With ordinary CSS:

styles.cssCSS
.primary-button {
  background-color: #4f46e5;
  color: white;
  padding: 10px 18px;
  border-radius: 8px;
  font-weight: 600;
}
JSXJSX
<button className="primary-button">
  Save Changes
</button>

With Tailwind:

JSXJSX
<button className="rounded-lg bg-indigo-600 px-5 py-2.5 font-semibold text-white">
  Save Changes
</button>

You can read the Tailwind classes as a compact description of the element's style.

UtilityMeaning
bg-indigo-600Indigo background
text-whiteWhite text
px-5Horizontal padding
py-2.5Vertical padding
rounded-lgRounded corners
font-semiboldSemibold text
shadow-smSmall shadow
hover:bg-indigo-700Change background on hover

The exact colors and measurements follow Tailwind's theme unless you define custom tokens.

2.2 Install Tailwind CSS v4 in a React + Vite project

For a new React project:

terminalBash

cd my-react-app
npm install

Install Tailwind CSS v4 and its Vite plugin:

terminalBash

Update vite.config.js:

vite.config.jsJavaScript
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

  plugins: [
    react(),
    tailwindcss(),
  ],

In src/index.css, use:

src/index.cssCSS

Make sure the stylesheet is imported into your React entry file, normally src/main.jsx:

src/main.jsxJSX
import { StrictMode } from "react";

  <StrictMode>
    <App />

);

Start the development server:

terminalBash

2.4 Handling repeated Tailwind styles

Suppose 20 buttons in your app use the same set of classes.

Copying the same long class string into every location creates duplication. You can create a reusable React component:

PrimaryButton.jsxJSX
function PrimaryButton({ children, ...props }) {
  return (
    <button
      className="rounded-lg bg-indigo-600 px-5 py-2.5 font-semibold text-white hover:bg-indigo-700 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-indigo-600"
      {...props}
    >
      {children}
    </button>
  );
}

export default PrimaryButton;

Usage:

JSXJSX
<PrimaryButton onClick={() => console.log("Saved")}>
  Save
</PrimaryButton>

This improves consistency. A later change to the main button design can be made in one place.

2.5 Tailwind versus CSS Modules

SituationA practical choice
Quickly composing layoutsTailwind CSS
Styling many small UI elements consistentlyTailwind CSS
Highly custom animations and complex selectorsCSS or CSS Modules
Isolated, component-specific stylesheetCSS Modules
Existing application already built with ordinary CSSContinue with CSS where practical
Large application with shared componentsTailwind plus reusable components, or CSS Modules plus a design system

There is no rule that every project must use only one approach. However, using several styling methods without a clear convention can make the code harder to maintain.

Section 03

Conditional Classes and Reusable Styles

Adapting styles to state and props cleanly.

3.1 What are conditional classes?

A conditional class is a CSS class that you apply only when a condition is true.

Consider a button that should look different when it is disabled.

SaveButton.jsxJSX
function SaveButton({ disabled }) {
  return (
    <button
      disabled={disabled}
      className={
        disabled
          ? "cursor-not-allowed bg-slate-300 text-slate-600"
          : "cursor-pointer bg-indigo-600 text-white hover:bg-indigo-700"
      }
    >
      Save
    </button>
  );
}

When disabled is true, the button gets the disabled styling. Otherwise, it gets the enabled styling.

The real disabled attribute is important here. Changing the color alone would not disable the button's behavior.

3.2 Conditional classes using state

React state is useful when a style depends on user interaction.

FavoriteButton.jsxJSX
import { useState } from "react";

function FavoriteButton() {
  const [favorite, setFavorite] = useState(false);

  return (
    <button
      onClick={() => setFavorite((current) => !current)}
      aria-pressed={favorite}
      className={
        favorite
          ? "rounded-lg bg-rose-600 px-4 py-2 text-white"
          : "rounded-lg bg-slate-200 px-4 py-2 text-slate-900"
      }
    >
      {favorite ? "♥ Favorited" : "♡ Add to favorites"}
    </button>
  );
}

export default FavoriteButton;

This example combines state, behavior, and styling:

  • useState stores whether the item is a favorite.
  • The click handler toggles that state.
  • The conditional expression selects the classes.
  • The button text reflects the selected state.
  • aria-pressed exposes the toggle state to assistive technology.

3.3 Combining common and conditional styles

A component often has classes that never change and classes that depend on a condition.

StatusBadge.jsxJSX
function StatusBadge({ status }) {
  const statusClasses = {
    active: "bg-emerald-100 text-emerald-800",
    pending: "bg-amber-100 text-amber-800",
    inactive: "bg-slate-100 text-slate-700",
  };

  const colorClasses =
    statusClasses[status] ?? statusClasses.inactive;

  return (
    <span
      className={`inline-flex rounded-full px-3 py-1 text-sm font-medium ${colorClasses}`}
    >
      {status}
    </span>
  );
}

Usage:

usageJSX
<StatusBadge status="active" />
<StatusBadge status="pending" />
<StatusBadge status="inactive" />

The base classes define the common design; the selected status defines the color.

▲ Important rule about Tailwind class names

Avoid building utility classes from arbitrary fragments:

✕ AvoidJSX
const className = `bg-${color}-600`;

Tailwind may not detect dynamically assembled class names when it scans your source files. The resulting CSS can be missing from your production build.

Prefer a map containing complete utility strings:

✓ DoJSX
const colors = {
  blue: "bg-blue-600",
  green: "bg-green-600",
  red: "bg-red-600",
};

const className = colors[color] ?? colors.blue;

3.4 Making class conditions easier to read

As conditions multiply, a long nested ternary becomes difficult to understand.

Avoid:

✕ Hard to readJSX
<div className={error ? "red" : loading ? "yellow" : success ? "green" : "gray"}>
  Status
</div>

A clearer approach is:

✓ ReadableJSX
const statusClass = {
  error: "bg-red-100 text-red-800",
  loading: "bg-amber-100 text-amber-800",
  success: "bg-emerald-100 text-emerald-800",
  idle: "bg-slate-100 text-slate-700",
};

const className = statusClass[state] ?? statusClass.idle;

Then render:

renderJSX
<div className={`rounded-lg px-3 py-2 ${className}`}>
  {state}
</div>

3.5 Useful class composition utilities

When a project grows, two commonly used tools are:

  • clsx combines class names conditionally.
  • tailwind-merge resolves conflicting Tailwind utility classes.

Install them when needed:

terminalBash
npm install clsx tailwind-merge

Create src/lib/utils.js:

src/lib/utils.jsJavaScript
import { clsx } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs) {
  return twMerge(clsx(inputs));
}

Usage:

Button.jsxJSX
import { cn } from "./lib/utils";

function Button({ compact, className = "", children, ...props }) {
  return (
    <button
      className={cn(
        "rounded-lg bg-indigo-600 px-4 py-2 text-white",
        compact && "px-2 py-1 text-sm",
        className
      )}
      {...props}
    >
      {children}
    </button>
  );
}

This is useful because a caller may want to pass additional styling:

usageJSX
<Button className="w-full">
  Continue
</Button>

Use class-merging utilities when conflicts are a real concern; they are not mandatory for every simple button.

Section 04

Responsive Layouts

A UI that adapts to every screen and every input method.

4.1 What is responsive design?

Responsive design means a UI adapts to different screen sizes and input methods.

The same application should be usable on:

  • A mobile phone
  • A tablet
  • A laptop
  • A large desktop monitor

For example, a dashboard might show three cards in one row on desktop but stack them on mobile.

Responsive design involves more than shrinking the text. It includes adapting layouts, spacing, navigation, image sizes, and how controls are arranged.

4.2 Mobile-first design

Tailwind follows a mobile-first model.

An unprefixed utility applies by default. A breakpoint-prefixed utility applies at that breakpoint and above.

Example:

gridJSX
<div className="grid grid-cols-1 gap-4 md:grid-cols-2 lg:grid-cols-3">
  <div className="rounded-xl bg-white p-5 shadow">Card 1</div>
  <div className="rounded-xl bg-white p-5 shadow">Card 2</div>
  <div className="rounded-xl bg-white p-5 shadow">Card 3</div>
</div>

Interpretation:

  • Small screens: one column.
  • Medium screens and above: two columns.
  • Large screens and above: three columns.

Tailwind's default breakpoint values are configurable. Common defaults are:

PrefixDefault minimum width
No prefixAll screen sizes
sm:640px
md:768px
lg:1024px
xl:1280px
2xl:1536px

These are minimum-width breakpoints, not fixed screen sizes. See Tailwind responsive design.

4.3 Responsive navigation

A simple navigation row can wrap or stack on smaller screens:

Navigation.jsxJSX
function Navigation() {
  return (
    <nav className="flex flex-col gap-4 sm:flex-row sm:items-center sm:justify-between">
      <h1 className="text-xl font-bold">My Dashboard</h1>

      <div className="flex flex-wrap gap-3">
        <a href="#overview">Overview</a>
        <a href="#projects">Projects</a>
        <a href="#settings">Settings</a>
      </div>
    </nav>
  );
}

On small screens the main elements are stacked. From the sm breakpoint upward, the heading and links can share a row.

This pattern is appropriate when a simple responsive row is enough. A full mobile menu that opens and closes needs real interaction, appropriate semantics, and keyboard support.

4.4 Responsive sizing

Fixed widths can create horizontal scrolling on mobile.

Avoid:

✕ AvoidJSX
<div className="w-[900px]">
  Dashboard content
</div>

Prefer a flexible width with a maximum:

✓ PreferJSX
<div className="mx-auto w-full max-w-6xl px-4 sm:px-6 lg:px-8">
  Dashboard content
</div>

Here:

  • w-full allows the element to use the available width.
  • max-w-6xl prevents it from growing indefinitely.
  • mx-auto centers the container when space is available.
  • The padding utilities add responsive horizontal spacing.

4.5 Responsive tables and overflow

Wide tables may not fit on mobile. A common option is to make the table container horizontally scrollable.

tableJSX
<div className="overflow-x-auto rounded-xl border">
  <table className="min-w-[640px] w-full text-left">
    <thead>
      <tr>
        <th className="p-3">Project</th>
        <th className="p-3">Owner</th>
        <th className="p-3">Status</th>
      </tr>
    </thead>

    <tbody>
      <tr>
        <td className="p-3">Website refresh</td>
        <td className="p-3">Priya</td>
        <td className="p-3">In progress</td>
      </tr>
    </tbody>
  </table>
</div>

The table keeps a useful minimum width, but its wrapper can scroll horizontally. For important data tables, consider whether a simpler mobile presentation would be better.

4.6 Responsive design checklist

Before accepting a page, test:

  • Does it work at a narrow mobile width?
  • Is any content unintentionally clipped?
  • Are buttons and links easy to tap?
  • Do images preserve their proportions?
  • Can navigation and dialogs be used with a keyboard?
  • Does text remain readable when zoomed?
  • Does the layout work without horizontal scrolling, except where scrolling is intentional?

Do not design exclusively for a single laptop width.

Section 05

Component Variants and Composition

One component, many appearances — without duplication.

5.1 What is a component variant?

A variant is a different appearance or configuration of the same component.

A button could have these variants:

  • Primary: the main action.
  • Secondary: an alternative action.
  • Outline: a bordered action.
  • Destructive: an action such as deleting a record.

It may also have sizes such as small, medium, and large.

Without a variant system, you may end up creating separate button components for each appearance:

✕ Without variantsJSX
<BlueButton>Save</BlueButton>
<GrayButton>Cancel</GrayButton>
<RedButton>Delete</RedButton>

A variant-based component keeps the shared behavior and structure in one place:

✓ With variantsJSX
<Button variant="primary">Save</Button>
<Button variant="secondary">Cancel</Button>
<Button variant="danger">Delete</Button>

5.2 Creating a reusable button with variants

Create Button.jsx:

Button.jsxJSX
const baseStyles =
  "inline-flex items-center justify-center rounded-lg font-semibold transition-colors focus-visible:outline-2 focus-visible:outline-offset-2 disabled:cursor-not-allowed disabled:opacity-50 motion-reduce:transition-none";

const variants = {
  primary:
    "bg-indigo-600 text-white hover:bg-indigo-700 focus-visible:outline-indigo-600",

  secondary:
    "bg-slate-100 text-slate-900 hover:bg-slate-200 focus-visible:outline-slate-600",

  outline:
    "border border-slate-300 bg-transparent text-slate-900 hover:bg-slate-50 focus-visible:outline-slate-600",

  danger:
    "bg-red-600 text-white hover:bg-red-700 focus-visible:outline-red-600",
};

const sizes = {
  sm: "px-3 py-1.5 text-sm",
  md: "px-4 py-2 text-sm",
  lg: "px-6 py-3 text-base",
};

export function Button({
  variant = "primary",
  size = "md",
  className = "",
  type = "button",
  children,
  ...props
}) {
  const variantStyles = variants[variant] ?? variants.primary;
  const sizeStyles = sizes[size] ?? sizes.md;

  return (
    <button
      type={type}
      className={`${baseStyles} ${variantStyles} ${sizeStyles} ${className}`}
      {...props}
    >
      {children}
    </button>
  );
}

Usage:

Actions.jsxJSX
import { Button } from "./Button";

function Actions() {
  return (
    <div className="flex flex-wrap gap-3">
      <Button variant="primary">Save</Button>

      <Button variant="secondary">Cancel</Button>

      <Button variant="outline" size="lg">
        Preview
      </Button>

      <Button variant="danger">Delete</Button>
    </div>
  );
}

Why is this better?

You define a consistent base style once, provide named variants, and allow the caller to choose an appropriate size.

You can improve the component further with clsx and tailwind-merge if callers need to override individual utilities. For TypeScript projects, define the accepted variant and size names as types to catch invalid values at build time.

5.3 What is component composition?

Composition means building larger UI elements by combining smaller components.

For example, a product page might combine:

  • Card
  • Badge
  • Button
  • Price
  • ProductImage

Rather than making one large component with every option built into it, you can let components receive children through the children prop.

Card.jsxJSX
function Card({ children }) {
  return (
    <section className="rounded-xl border border-slate-200 bg-white p-5 shadow-sm">
      {children}
    </section>
  );
}

Usage:

compositionJSX
<Card>
  <h2 className="text-xl font-bold">Frontend Course</h2>

  <p className="mt-2 text-slate-600">
    Learn React from the fundamentals.
  </p>

  <Button className="mt-4">View Course</Button>
</Card>

The Card supplies the shared visual container, while its children supply the content.

5.4 Composition versus too many props

Consider this complicated component:

✕ Too many propsJSX
<Card
  showTitle
  showImage
  showFooter
  compact
  horizontal
  centered
  dangerMode
  showDivider
/>

Some configurable components are useful, but too many unrelated boolean props can create a confusing API.

An alternative is composition:

✓ CompositionJSX
<Card>
  <CardHeader>
    <CardTitle>Frontend Course</CardTitle>
  </CardHeader>

  <CardContent>
    Learn React with practical projects.
  </CardContent>

  <CardFooter>
    <Button>Enroll Now</Button>
  </CardFooter>
</Card>

In this approach, the consumer chooses the structure by combining smaller parts.

Use variants for intentional alternatives in a component's design. Use composition when callers need control over which elements appear and how they are arranged.

Design Tokens and Theme Systems

Centralizing design decisions so the whole app stays consistent.

6.1 What are design tokens?

Design tokens are named values that represent decisions in your design system.

For example, instead of choosing a different shade of blue for every button, link, and selected navigation item, you can define a shared primary color.

Typical tokens include:

  • Colors
  • Typography sizes and weights
  • Spacing
  • Border radii
  • Shadows
  • Animation durations
  • Layout widths

Think of tokens as the design rules of your application.

Without tokens, each component may have slightly different shades, spacing, and corner shapes. With tokens, your application can feel consistent.

6.2 Define reusable CSS variables

In src/index.css:

src/index.cssCSS
@import "tailwindcss";

:root {
  --app-background: #f8fafc;
  --app-surface: #ffffff;
  --app-text: #0f172a;
  --app-muted: #64748b;
  --app-border: #e2e8f0;
  --app-primary: #4f46e5;
}

Use those variables in custom CSS:

CSS variablesCSS
.page {
  background-color: var(--app-background);
  color: var(--app-text);
}

.panel {
  background-color: var(--app-surface);
  border: 1px solid var(--app-border);
}

Your React component can use the corresponding classes:

JSXJSX
<div className="page min-h-screen p-6">
  <section className="panel rounded-xl p-5">
    <h1>Dashboard</h1>
  </section>
</div>

Changing a token can update multiple components that use it.

6.3 Tailwind CSS v4 theme tokens

Tailwind v4 also supports theme values through @theme.

@themeCSS
@import "tailwindcss";

@theme {
  --color-brand-500: #6366f1;
  --radius-panel: 1rem;
  --font-display: "Inter", sans-serif;
}

These theme variables can make utilities available, such as:

theme utilitiesJSX
<div className="rounded-panel bg-brand-500 p-6 font-display text-white">
  Custom theme styles
</div>

Theme tokens and ordinary CSS custom properties solve related but different problems.

  • Use Tailwind theme values to generate consistent utility classes.
  • Use semantic CSS variables when an application's meaning-based colors need to change with a theme.

For example, a surface token communicates a role in the UI, whereas a fixed gray color simply communicates a particular shade.

6.4 Semantic tokens

Consider the following tokens:

semantic tokensCSS
:root {
  --surface: #ffffff;
  --text: #0f172a;
  --muted: #64748b;
}

.dark {
  --surface: #111827;
  --text: #f8fafc;
  --muted: #9ca3af;
}

The same CSS variable has a different value depending on the active theme.

A card can use the variables without needing to know which theme is active:

.themed-cardCSS
.themed-card {
  background: var(--surface);
  color: var(--text);
}

This separates the component's job from the specific color values of a theme.

6.5 Why design tokens matter in professional projects

Imagine that a client asks you to change the primary color across an entire product.

If 50 components have independent hard-coded color values, you have a lot of manual work and more room for inconsistency.

If components use a shared token, the change becomes much easier.

Tokens are especially useful for:

  • Large dashboards
  • Admin panels
  • Learning management systems
  • E-commerce applications
  • Multi-brand products
  • Applications with light and dark themes

A design token is only helpful when components actually use it consistently. Naming conventions and documentation matter too.

Open component source and accessible building blocks.

7.1 What is shadcn/ui?

shadcn/ui is a collection of UI components and a way to distribute their source code into your own application.

It is not the same as a traditional component library where you only import an opaque, prebuilt component package.

The source for the selected components is added to your project, so you can inspect and customize it. Its approach emphasizes open component code and composition. See the official shadcn/ui introduction and its component setup guide.

7.2 Why developers use it

Building every visual component from scratch takes time.

Many applications need common building blocks:

  • Buttons
  • Cards
  • Inputs
  • Labels
  • Dialogs
  • Dropdown menus
  • Tabs
  • Tooltips
  • Select menus

A component system gives you a starting implementation. You can then focus more on the application-specific logic and customize the design to match your product.

Remember that installing a component does not complete the whole feature. For example, a form still requires appropriate validation, error messages, and submission logic.

7.4 What are accessible primitives?

An accessible UI component is designed to work for people with different abilities and interaction needs, including people who use keyboards or screen readers.

Primitive components generally provide lower-level functionality and behavioral building blocks that can be composed into a more complete UI.

Depending on the chosen integration, an accessible primitive may help manage:

  • Keyboard interactions
  • Focus movement
  • Open and closed states
  • Accessible names and descriptions
  • ARIA attributes
  • Dialog and menu behavior

An accessible primitive does not automatically make an entire application accessible. The markup, labels, content, color contrast, focus handling, and interaction behavior still need to be correct.

The W3C ARIA Authoring Practices Guide provides practical patterns for building accessible interface components. Its keyboard interface guidance emphasizes keyboard operation and predictable focus movement.

7.5 Accessibility basics to remember

Use semantic HTML

Prefer native elements when they already provide the required behavior.

semantic buttonJSX
<button type="button" onClick={handleSave}>
  Save
</button>

Do not imitate a button with a plain div unless you have a compelling reason and implement the required keyboard and accessibility behavior.

Provide labels for inputs

label inputJSX
<div>
  <label htmlFor="email" className="mb-1 block font-medium">
    Email address
  </label>

  <input
    id="email"
    type="email"
    autoComplete="email"
    className="w-full rounded-lg border border-slate-300 px-3 py-2"
  />
</div>

The label is associated with the input through matching htmlFor and id values.

Preserve visible focus

focusJSX
<button className="rounded-lg px-4 py-2 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-indigo-600">
  Continue
</button>

Keyboard users need to see which element currently has focus. Do not remove focus indicators without replacing them with an equally visible alternative.

Do not communicate status with color alone

For a payment, do not rely solely on green versus red. Include meaningful text such as “Paid” or “Payment failed.”

Test actual behavior

Use the keyboard to navigate the screen. Check menus, dialogs, form errors, and focus after closing an overlay. Test with accessibility tools where possible.

Animation and Transitions

Motion that helps people, not motion that distracts them.

8.1 What is a CSS transition?

A transition makes a style change happen smoothly over a period of time.

Without a transition, a background color might change immediately when a button is hovered.

transitionCSS
.button {
  background-color: #4f46e5;
  transition: background-color 200ms ease;
}

.button:hover {
  background-color: #4338ca;
}

With the transition, the color change is gradual.

With Tailwind:

hover transitionJSX
<button className="rounded-lg bg-indigo-600 px-5 py-2.5 text-white transition-colors duration-200 hover:bg-indigo-700">
  Hover over me
</button>

Useful utilities include:

  • transition-colors
  • transition-opacity
  • transition-transform
  • duration-200
  • ease-in-out

You can also use the general transition utility when several suitable properties need to transition.

8.2 Hover and press feedback

Buttons and cards can respond visually to user interaction.

lift buttonJSX
<button className="rounded-lg bg-indigo-600 px-5 py-3 font-semibold text-white transition-all duration-200 hover:-translate-y-0.5 hover:bg-indigo-700 active:translate-y-0">
  Explore Courses
</button>

This button changes color and moves up slightly on hover.

Use motion to communicate an interaction, not as a distraction. Frequent large movements can make interfaces harder to use.

8.3 CSS keyframe animations

A transition usually describes a change between states. A keyframe animation can describe a sequence of changes.

keyframesCSS
@keyframes fade-in {
  from {
    opacity: 0;
    transform: translateY(8px);
  }

  to {
    opacity: 1;
    transform: translateY(0);
  }
}

.fade-in {
  animation: fade-in 300ms ease-out both;
}

Use it in React:

WelcomeMessage.jsxJSX
function WelcomeMessage() {
  return (
    <div className="fade-in rounded-xl bg-white p-6 shadow">
      Welcome back!
    </div>
  );
}

Define keyframes in your stylesheet and apply a named class.

8.4 Reduce motion when appropriate

Some people prefer reduced movement because animations can cause discomfort or make interfaces more difficult to use.

Tailwind provides a reduced-motion variant:

reduced motionJSX
<div className="transition-transform duration-300 hover:scale-105 motion-reduce:transform-none motion-reduce:transition-none">
  Course card
</div>

The motion-reduce utilities respond to the operating system's reduced-motion preference.

For global custom animations, you can also write a reduced-motion media query:

@mediaCSS
@media (prefers-reduced-motion: reduce) {
  .fade-in {
    animation: none;
  }
}

Do not disable all motion indiscriminately when some transitions are important for orientation or feedback. Consider what is essential and provide the least distracting alternative.

8.5 Using Motion for React

For complex React animations, Motion for React provides declarative animation controls. It supports animation states and transitions, among other features.

Install it:

terminalBash
npm install motion

Example:

AnimatedCard.jsxJSX
import { motion } from "motion/react";

function AnimatedCard() {
  return (
    <motion.div
      initial={{ opacity: 0, y: 12 }}
      animate={{ opacity: 1, y: 0 }}
      transition={{ duration: 0.3 }}
      className="rounded-xl bg-white p-6 shadow"
    >
      <h2 className="text-xl font-bold">Welcome</h2>
      <p className="mt-2 text-slate-600">
        Your dashboard is ready.
      </p>
    </motion.div>
  );
}

export default AnimatedCard;

Here:

  • initial describes the starting visual state.
  • animate describes the target state.
  • transition controls how the change occurs.

Choose CSS for many simple hover effects and transitions. Use a dedicated animation library when you need more involved sequences or React-specific animation behavior.

Dark Mode

An alternate color scheme done right.

9.1 What is dark mode?

Dark mode changes the color scheme of an application to use darker surfaces and appropriately contrasting foreground text.

A light theme might use a white card with dark text. A dark theme might use a deep gray card with light text.

Dark mode requires more than changing the page background. Inputs, borders, dropdowns, muted text, focus states, and overlays all need suitable colors.

9.2 Dark mode with Tailwind

Tailwind provides the dark: variant for applying styles in dark mode. Its default behavior follows the operating system's color scheme, unless you configure a different activation method.

Example:

dark variantJSX
<div className="rounded-xl bg-white p-6 text-slate-900 dark:bg-slate-900 dark:text-white">
  <h2 className="text-xl font-bold">Dashboard</h2>

  <p className="mt-2 text-slate-600 dark:text-slate-300">
    Review your recent activity.
  </p>
</div>

When dark mode is active, the dark: classes change the background and foreground colors. See the Tailwind dark mode documentation.

9.3 Manual dark mode in Tailwind CSS v4

For a manual toggle, configure a class-based dark variant in src/index.css:

src/index.cssCSS
@import "tailwindcss";

@custom-variant dark (&:where(.dark, .dark *));

Now Tailwind's dark: utilities apply when the dark class is present on the root element or one of its ancestors, according to the configured selector.

For example, this enables the dark theme:

addJavaScript
document.documentElement.classList.add("dark");

And this removes it:

removeJavaScript
document.documentElement.classList.remove("dark");

Usually, your React application manages these changes through state and an effect instead of manually running unrelated DOM operations throughout the application.

9.4 Build a theme toggle with React

ThemeToggle.jsxJSX
import { useEffect, useState } from "react";

function ThemeToggle() {
  const [isDark, setIsDark] = useState(() => {
    return localStorage.getItem("theme") === "dark";
  });

  useEffect(() => {
    const root = document.documentElement;

    root.classList.toggle("dark", isDark);
    localStorage.setItem("theme", isDark ? "dark" : "light");
  }, [isDark]);

  return (
    <button
      type="button"
      onClick={() => setIsDark((current) => !current)}
      aria-pressed={isDark}
      className="rounded-lg border border-slate-300 px-4 py-2 dark:border-slate-700"
    >
      {isDark ? "Switch to light mode" : "Switch to dark mode"}
    </button>
  );
}

export default ThemeToggle;

This is a client-side example for a Vite React project. It assumes browser storage is available.

It works as follows:

  1. React initializes the state from the stored preference.
  2. The button switches the state.
  3. The effect adds or removes the dark class from the document root.
  4. The effect stores the preference so it can be used next time.

Because this example treats an unstored preference as light mode, it does not automatically follow the operating system when no preference has been saved. A more advanced implementation can support three settings: light, dark, and system.

9.5 Store preferences safely

Theme choice is an ordinary display preference, making it a reasonable candidate for localStorage.

Do not use browser storage for highly sensitive data or assume that data stored there is protected from JavaScript running on the page. Authentication and authorization must be designed separately.

For a larger application, centralize theme behavior in a theme provider or a dedicated custom hook rather than duplicating the theme effect in multiple components.

9.6 Dark mode testing checklist

  • Check foreground/background contrast.
  • Check muted text and placeholder text.
  • Check borders and separators.
  • Check disabled, error, success, and warning states.
  • Check dropdowns, modals, and popovers.
  • Check focus indicators.
  • Test switching modes without a full page reload.
  • Check whether the selected preference persists as intended.

const baseStyles =
  "inline-flex items-center justify-center rounded-lg font-medium transition-colors focus-visible:outline-2 focus-visible:outline-offset-2 disabled:cursor-not-allowed disabled:opacity-50 motion-reduce:transition-none";

  primary:
    "bg-indigo-600 text-white hover:bg-indigo-700 focus-visible:outline-indigo-600",

  secondary:
    "bg-slate-100 text-slate-900 hover:bg-slate-200 focus-visible:outline-slate-500 dark:bg-slate-800 dark:text-slate-100 dark:hover:bg-slate-700",

};

  sm: "px-3 py-1.5 text-sm",
  md: "px-4 py-2 text-sm",
  lg: "px-5 py-3 text-base",
};

export function Button({
  variant = "primary",
  size = "md",
  className = "",
  type = "button",
  children,
  ...props
}) {

  1. Using global class names for every component. Use CSS Modules or a shared naming convention when global CSS becomes difficult to manage.
  2. Repeating the same long Tailwind class string everywhere. Extract a reusable component when the structure and design are repeated.
  3. Constructing utility classes dynamically. Use a map of complete Tailwind class strings so the required utilities can be detected during the build.
  4. Using color as the only indication of status. Include readable status text and maintain appropriate contrast.
  5. Designing for desktop only. Test small screens and fix overflow rather than assuming the layout will scale automatically.
  6. Using too many unrelated boolean props. Prefer a clear variant API or component composition.
  7. Removing keyboard focus indicators. Preserve visible focus and test keyboard navigation.
  8. Adding animations to everything. Animate meaningful changes, keep effects subtle, and respect reduced-motion preferences.
  9. Changing only the page background for dark mode. Also review text, borders, controls, alerts, menus, and cards.
  10. Building components that are too generic. Reuse components when the behavior or design is genuinely shared. Avoid creating complicated abstractions for one-off elements without a clear benefit.

Practical Assignments

Five exercises to test your styling and component-building skills.

Assignment 1: Profile card

Build a profile card with an avatar, name, role, description, and action button.

Requirements:

  • Use a React component.
  • Style it using Tailwind CSS.
  • Keep the layout responsive.
  • Add a hover state.
  • Use clear focus styles on interactive elements.

Assignment 2: Status system

Build a status badge that supports Success, Pending, Error, and Inactive.

Requirements:

  • Use a reusable component.
  • Use an explicit mapping of status values to class names.
  • Display status text.
  • Make text readable in both light and dark themes.

Assignment 3: Button system

Build a button component with primary, secondary, outline, and danger variants.

Requirements:

  • Include small, medium, and large sizes.
  • Support disabled, onClick, and normal button attributes.
  • Ensure the variants have consistent padding, typography, border radius, and focus behavior.
  • Use type="button" as the default.

Assignment 4: Theme toggle

Add a light, dark, and system theme mode to your dashboard.

Requirements:

  • Save explicit user preferences.
  • Use system preference when the user selects System.
  • Update the root theme class or attribute.
  • Test that every reusable component works in both themes.
  • Handle an unset or invalid saved preference.

Assignment 5: UI component library

Create a components/ui directory and build five shared components:

  • Button
  • Card
  • Badge
  • Input
  • Modal or Dialog

Document each component's variants and expected props. Check semantics, keyboard interactions, and disabled/error states.
