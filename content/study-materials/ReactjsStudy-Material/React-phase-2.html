Event Handling and Event Objects

1.1 What Is Event Handling?

Simple Definition

An event is an action or occurrence that a program can respond to. Event handling means writing code that runs when a particular event occurs.

In a web application, events include:

  • Clicking a button
  • Typing into an input field
  • Submitting a form
  • Moving the mouse over an element
  • Focusing on an input field

For example, when a student clicks the Login button, the application might validate the form or begin a login process.

React lets you connect JavaScript functions to events through JSX event-handler props.

1.2 Analogy: A Doorbell

Real-Life Analogy

Imagine someone presses a doorbell.

The button press is the event. The sound produced by the bell is the response.

In a React application:

• User action = event
• Event-handler function = response logic
• Updated interface or other action = result

For example, clicking a button can display a welcome message.

1.3 Create Your First Click Event

JSX 
function App() {
  function handleClick() {
    alert("Button clicked!");
  }

  return (
    <button onClick={handleClick}>
      Click Me
    </button>
  );
}

export default App;

Explanation

Step 1: Define a function

JSX 
function handleClick() {
  alert("Button clicked!");
}

This function contains the work you want to perform when the button is clicked.

Step 2: Connect the function to the button

JSX 
<button onClick={handleClick}>
  Click Me
</button>

The onClick prop tells React which event handler to use for a click.

Step 3: The user clicks the button

React invokes the handler, and the browser displays an alert.

Watch the Parentheses

Notice that we write onClick={handleClick}, not onClick={handleClick()}. The first passes the function for React to call later; the second calls the function immediately while rendering.

1.4 Why Does React Use onClick Instead of onclick?

In regular HTML, an event may be written as an HTML attribute such as onclick. In React JSX, event-handler props use camelCase.

JSX 
<button onClick={handleClick}>Click</button>

Similarly, a text input commonly uses onChange:

JSX 
<input onChange={handleChange} />

And a form commonly uses onSubmit:

JSX 
<form onSubmit={handleSubmit}>
  {/* Form controls */}
</form>

React event handlers are functions passed to JSX elements.

1.5 Common React Events

Event handlerWhen it runs
onClickAn element is clicked
onChangeThe value of an input changes
onSubmitA form is submitted
onFocusAn element receives focus
onBlurAn element loses focus
onMouseEnterThe mouse enters an element

You do not need to memorize every event now. Learn the commonly used ones first.

1.6 What Is an Event Object?

Simple Definition

When an event occurs, its handler receives an event object containing information about that event.

JSX 
function App() {
  function handleClick(event) {
    console.log(event.type);
    console.log(event.currentTarget);
  }

  return (
    <button onClick={handleClick}>
      Inspect Event
    </button>
  );
}

export default App;

When the user clicks the button, the console shows information about the click event and the button to which the handler is attached.

In the example, event is a parameter. You could also name it e.

Understanding event.target

event.target refers to the element where the event originated. For example, it can identify the input element whose value changed.

Understanding event.currentTarget

event.currentTarget refers to the element on which the current handler is registered. This distinction is useful when events bubble from nested elements.

1.7 Read the Value of an Input

JSX 
function App() {
  function handleChange(event) {
    console.log(event.target.value);
  }

  return (
    <input
      type="text"
      placeholder="Enter your name"
      onChange={handleChange}
    />
  );
}

export default App;

Explanation:

  1. The user types into the input.
  2. React calls handleChange.
  3. The handler receives the event object.
  4. event.target.value provides the current input value.
  5. console.log() prints that value.

For a React text input, onChange is normally used to respond as the user edits the value.

At this point, the example only prints the value. We will connect input values to React state in Topic 11.

1.8 Preventing the Default Form Action

A browser form may attempt to navigate or reload the page when submitted, depending on the form's setup.

In a React form, you often want to handle submission in JavaScript instead.

Use event.preventDefault() to prevent the browser's default submission behavior.

JSX 
function App() {
  function handleSubmit(event) {
    event.preventDefault();

    alert("Form submitted!");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input type="text" placeholder="Enter your name" />

      <button type="submit">
        Submit
      </button>
    </form>
  );
}

export default App;

Explanation:

  • onSubmit={handleSubmit} connects the form to a handler.
  • The browser creates a submit event when the user submits the form.
  • event.preventDefault() prevents the default page submission.
  • The alert displays a message.

Preventing the default action does not automatically validate the form or send its data to a server. Those tasks require additional logic.

1.9 What Is Event Bubbling?

Event bubbling occurs when an event on a nested element propagates to ancestor elements that have handlers.

JSX 
function App() {
  return (
    <div onClick={() => console.log("Parent clicked")}>
      <button onClick={() => console.log("Button clicked")}>
        Click Me
      </button>
    </div>
  );
}

Clicking the button normally logs:

Output 
Button clicked
Parent clicked

The click handler attached to the button runs, and the event bubbles to the parent div.

If you need to stop the event from propagating further, the event object provides stopPropagation().

JSX 
function App() {
  function handleButtonClick(event) {
    event.stopPropagation();
    console.log("Button clicked");
  }

  return (
    <div onClick={() => console.log("Parent clicked")}>
      <button onClick={handleButtonClick}>
        Click Me
      </button>
    </div>
  );
}

Now clicking the button does not trigger the parent's click handler through that bubbling path.

Use stopPropagation() only when you have a specific reason to prevent propagation. It is not needed for ordinary button clicks.

Remember

An event handler is a function that responds to user interaction. The event object provides information about what happened and methods for controlling event behavior.

The event object is a goldmine of information — coordinates, key presses, the element that fired it, and more. For Phase 2, the three methods you'll use most often are event.target.value, event.preventDefault(), and (occasionally) event.stopPropagation().

useState and State Updates

2.1 What Is State in React?

Simple Definition

State is information that a component remembers between renders.

Examples include:

  • A counter's current number
  • Whether a dropdown is open
  • The text entered into an input
  • A list of tasks
  • Whether a task is completed
  • A selected filter

When the state changes, React can render the component again so its interface reflects the new value.

2.2 What Is the useState Hook?

Simple Definition

useState is a React Hook that lets a functional component store and update state.

Basic syntax:

JSX 
const [state, setState] = useState(initialValue);

Here:

  • state is the current state value for that render.
  • setState is the function used to request a state update.
  • initialValue is the starting value.

The variable names are up to you. For example, for a counter you might use count and setCount.

2.3 Your First Counter

JSX 
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h1>Count: {count}</h1>

      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>
    </div>
  );
}

export default Counter;

Step-by-Step Explanation

Step 1: Import useState

JSX 
import { useState } from "react";

This imports the React Hook used to declare state.

Step 2: Create a state variable

JSX 
const [count, setCount] = useState(0);

The initial count is 0.

Step 3: Display the state

JSX 
<h1>Count: {count}</h1>

The current value of count is inserted into the heading.

Step 4: Update the state

JSX 
<button onClick={() => setCount(count + 1)}>
  Increase
</button>

When the button is clicked, the setter requests an update that increments the count by one. React then renders the updated value.

Progression 
Initial value:     Count: 0
After one click:   Count: 1
After two clicks:  Count: 2
After three clicks: Count: 3

2.4 Analogy: A Notebook

Analogy

Imagine keeping a notebook of your daily expenses.

You write the total in the notebook, and whenever you add an expense, you update the total.

In React:

• The current total is state.
• useState stores that value for the component.
• The setter updates it.
• React renders the new total in the interface.

An ordinary local variable does not provide this same persistent, rendering-aware behavior.

2.5 useState Can Store Different Types of Values

Number

JSX 
const [age, setAge] = useState(18);

String

JSX 
const [name, setName] = useState("Rahul");

Boolean

JSX 
const [isVisible, setIsVisible] = useState(true);

Array

JSX 
const [courses, setCourses] = useState([
  "React",
  "JavaScript"
]);

Object

JSX 
const [student, setStudent] = useState({
  name: "Priya",
  course: "React"
});

State can contain any JavaScript value, including numbers, strings, booleans, arrays, objects, and other values appropriate to the application.

2.6 What Happens When State Changes?

Consider this simplified flow:

User clicks button | v Event handler runs | v State setter is called | v React schedules an update | v Component renders again | v Updated UI is committed to the DOM

For example, if the current count is 4, then setCount(5) asks React to update the state to 5. A subsequent render will use the updated value.

Calling the setter does not immediately change the state variable in the currently executing render. We will explore that behavior in the next topic.

2.7 State Updates Using the Previous Value

You can update state using a function:

JSX 
setCount(previousCount => previousCount + 1);

The updater function receives the previous state value and returns the next value. This is particularly useful when the next value depends on the previous value.

JSX 
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  function increaseThreeTimes() {
    setCount(current => current + 1);
    setCount(current => current + 1);
    setCount(current => current + 1);
  }

  return (
    <div>
      <h1>{count}</h1>

      <button onClick={increaseThreeTimes}>
        Increase by 3
      </button>
    </div>
  );
}

export default Counter;

Each updater function receives the result of the previous queued updater. Starting at 0, clicking the button produces 3.

When Should You Use a Functional Updater?

Use this form when the next state depends on the previous state, especially when several updates may be queued together.

JSX 
setCount(current => current + 1);

For a simple update where the next value does not depend on the previous value, a direct setter may be enough:

JSX 
setName("Priya");

2.8 Rules for Using useState

  1. Import the Hook when you need it.
  2. Call useState at the top level of a functional component or another custom Hook.
  3. Do not call Hooks inside loops, conditions, or nested functions.
  4. Use the setter to update state instead of assigning a new value directly to the state variable.
  5. Remember that state values are snapshots for the render in which they were read.
Remember

useState stores information for a component. Its setter requests an update, and React can render the new state in the interface.

Those five rules are not arbitrary — they are the reason Hooks work at all. React tracks your state by the order in which Hooks are called. Break the order, break the state.

State Versus Ordinary JavaScript Variables

This is one of the most important concepts for React beginners.

3.1 What Is an Ordinary Variable?

An ordinary JavaScript variable stores a value.

JS 
let count = 0;

count = count + 1;

console.log(count); // 1

This behaves exactly as you would expect in regular JavaScript.

However, changing an ordinary local variable does not itself tell React to render the component again.

3.2 What Happens If You Use a Variable in a Component?

JSX 
function Counter() {
  let count = 0;

  function increase() {
    count = count + 1;
    console.log(count);
  }

  return (
    <div>
      <h1>Count: {count}</h1>
      <button onClick={increase}>
        Increase
      </button>
    </div>
  );
}

export default Counter;

When you click the button, the console can log 1, then 2, and so on.

But the heading does not update as expected.

Why?

The variable changes, but no state update is requested. React therefore has no reason to render the updated value as a result of that assignment.

Even if another event causes the component to render, a local variable initialized inside the component starts from 0 again.

3.3 The Same Example with useState

JSX 
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  function increase() {
    setCount(count + 1);
  }

  return (
    <div>
      <h1>Count: {count}</h1>
      <button onClick={increase}>
        Increase
      </button>
    </div>
  );
}

export default Counter;

Now React is asked to update the count whenever the button is clicked. The new value appears in the heading after the component renders again.

3.4 Analogy: A Temporary Note Versus a Saved Record

Analogy

Imagine writing a number on a scrap of paper and then replacing the scrap each time you restart a task.

That is similar to a local variable initialized during a component render.

Now imagine saving the number in a persistent record that can be updated and displayed again. That is closer to React state.

This analogy highlights the main difference:

  • An ordinary local variable stores a value only within normal JavaScript execution and is recreated when the component function runs again.
  • React state is managed by React, retained between renders for that component, and updated through its setter.

3.5 Comparison Table

FeatureOrdinary local variableReact state
Stores a valueYesYes
Retained automatically between component rendersNo, not for a local variable initialized in the component bodyYes
Updating it requests a React renderNoYes, the setter requests an update
Appropriate for values displayed and changed in the UIUsually not by itselfYes
Suitable for a temporary calculation during renderingYesOften unnecessary

3.6 When Should You Use an Ordinary Variable?

Not every value needs to be stored in state.

JSX 
function Price() {
  const price = 1000;
  const tax = 180;

  const total = price + tax;

  return <h1>Total: ₹{total}</h1>;
}

Here, total is just a calculation based on two constant values. It does not need separate state.

You should use state when a value needs to persist across renders and its changes should influence the rendered interface.

Remember

An ordinary variable is useful for calculations and temporary values. React state is appropriate for information the component needs to remember and display across renders.

State Immutability

4.1 What Does Immutability Mean?

Simple Definition

Immutability means treating existing data as read-only rather than directly changing it.

JavaScript permits objects and arrays to be mutated. However, when objects or arrays are stored in React state, you should create updated copies rather than directly modifying the existing values.

This is important because React uses state values as inputs to rendering, and replacing them provides React with a clear new value to work with.

4.2 Analogy: Editing a Photocopy

Analogy

Imagine you have an original document that you need to preserve.

Instead of changing the original, you make a copy and edit the copy.

In React state:

• Existing state = original document
• New copied value = updated document
• State setter = request to use the new document

The old value remains unchanged, and React receives a new value.

4.3 The Wrong Way: Mutating State

JSX 
import { useState } from "react";

function Student() {
  const [student, setStudent] = useState({
    name: "Rahul",
    city: "Rajkot"
  });

  function changeCity() {
    student.city = "Ahmedabad";
  }

  return (
    <div>
      <p>Name: {student.name}</p>
      <p>City: {student.city}</p>
      <button onClick={changeCity}>
        Change City
      </button>
    </div>
  );
}

The handler directly modifies student.city, but it does not call the state setter. React is not asked to render again.

This is not the recommended way to update state.

4.4 The Correct Way: Create a New Object

JSX 
import { useState } from "react";

function Student() {
  const [student, setStudent] = useState({
    name: "Rahul",
    city: "Rajkot"
  });

  function changeCity() {
    setStudent(currentStudent => ({
      ...currentStudent,
      city: "Ahmedabad"
    }));
  }

  return (
    <div>
      <p>Name: {student.name}</p>
      <p>City: {student.city}</p>
      <button onClick={changeCity}>
        Change City
      </button>
    </div>
  );
}

export default Student;

Explanation

The expression:

JS 
{
  ...currentStudent,
  city: "Ahmedabad"
}

creates a new object.

The spread syntax copies the existing properties, and the city property is replaced by "Ahmedabad".

The setter then requests that React use the new object as the state value.

4.5 Why Is Direct Mutation a Problem?

Direct mutation can cause several issues:

  • React may not receive a new reference to the changed object or array.
  • The UI may not update when you expect it to.
  • Past state values can appear to have changed unexpectedly.
  • Debugging becomes more difficult.
  • Features that rely on comparing old and new values become harder to reason about.

Treating state as immutable makes updates more predictable.

4.6 What Does the Spread Operator Do?

For an object:

JS 
const original = {
  name: "Priya",
  course: "JavaScript"
};

const updated = {
  ...original,
  course: "React"
};

The updated object contains:

JS 
{
  name: "Priya",
  course: "React"
}

The original object remains unchanged.

Important

Object spread creates a shallow copy, not a full deep copy. Nested objects need to be copied separately when you update their contents. We will practise that in Topic 8.

Remember

Do not directly mutate an object or array stored in state. Create an updated value, then pass it to the state setter.

"Immutable" sounds intimidating, but it really means one rule: don't change the original; make a copy with your change baked in. Every array and object update in React follows this rule.

Conditional Rendering

5.1 What Is Conditional Rendering?

Simple Definition

Conditional rendering means showing different UI content according to a condition.

For example:

  • Show a welcome message when a user is logged in.
  • Show an empty-state message when no courses exist.
  • Display a badge if a student is active.
  • Show a warning when a form field is missing.
  • Display different buttons based on a task's completion status.

5.2 Analogy: A Traffic Light

Analogy

A traffic light displays different signals depending on the current condition.

• Red: Stop
• Yellow: Prepare
• Green: Go

Similarly, a React component can display one element when a condition is true and another when it is false.

5.3 Method 1: The if Statement

You can use a normal JavaScript condition before returning JSX.

JSX 
function LoginMessage() {
  const isLoggedIn = true;

  if (isLoggedIn) {
    return <h1>Welcome Back!</h1>;
  }

  return <h1>Please Log In</h1>;
}

export default LoginMessage;

Since isLoggedIn is true, the component returns the welcome heading.

An if statement is useful when a component has several possible outputs or when the condition is easier to understand outside JSX.

5.4 Method 2: The Ternary Operator

A ternary expression has this form:

JS 
condition ? valueIfTrue : valueIfFalse
JSX 
function AdmissionStatus() {
  const isAdmitted = false;

  return (
    <div>
      <h2>Admission Status</h2>

      <p>
        {isAdmitted ? "Admission Confirmed" : "Admission Pending"}
      </p>
    </div>
  );
}

Because isAdmitted is false, the paragraph displays Admission Pending.

The ternary operator is useful when you want to choose between two values or UI elements inside JSX.

5.5 Method 3: Logical AND (&&)

Sometimes, you want to display an element only when a condition is true.

JSX 
function Notification() {
  const hasNotification = true;

  return (
    <div>
      <h1>Student Dashboard</h1>

      {hasNotification && (
        <p>You have a new notification.</p>
      )}
    </div>
  );
}

When hasNotification is true, the paragraph appears. When it is false, the condition evaluates to false and the paragraph is not rendered.

Watch Out

Be careful when using numbers directly with &&. For instance, {0 && <p>Hello</p>} renders the number 0. For a count-based condition, use an explicit comparison: {notificationCount > 0 && <p>You have notifications.</p>}

5.6 Method 4: Render Nothing with null

A component can return null when it should display nothing.

JSX 
function Warning({ show }) {
  if (!show) {
    return null;
  }

  return <p>Please complete all required fields.</p>;
}

When show is false, the component does not render visible content.

5.7 Conditional Rendering with State

Conditional rendering becomes especially useful when combined with useState.

JSX 
import { useState } from "react";

function ToggleMessage() {
  const [isVisible, setIsVisible] = useState(false);

  return (
    <div>
      <button onClick={() => setIsVisible(current => !current)}>
        {isVisible ? "Hide Message" : "Show Message"}
      </button>

      {isVisible && <p>Hello! Welcome to React.</p>}
    </div>
  );
}

export default ToggleMessage;

Explanation:

  1. The initial value of isVisible is false.
  2. The message is initially hidden.
  3. Clicking the button changes the boolean to its opposite.
  4. React renders the updated button text.
  5. The paragraph appears or disappears according to the new state.

The expression:

JSX 
current => !current

returns the opposite boolean value.

Remember

Use if for separate rendering paths, a ternary for two alternatives, and && when an element should appear only if a condition is true.

Rendering Lists with map()

6.1 What Is List Rendering?

Simple Definition

List rendering means using a collection of data to display multiple UI elements.

Examples include:

  • A list of students
  • A list of available courses
  • A list of products
  • A table of CRM leads
  • A list of tasks or assignments

JavaScript's map() method is commonly used for this in React.

6.2 What Is map() in JavaScript?

The map() method creates a new array by calling a function for every element of an existing array.

JS 
const numbers = [1, 2, 3];

const doubled = numbers.map(number => number * 2);

console.log(doubled);
Output 
[2, 4, 6]

For every number, the function returns double its value.

In React, the returned array can contain JSX elements.

6.3 Display a List of Names

JSX 
function StudentList() {
  const students = ["Rahul", "Priya", "Aarav"];

  return (
    <ul>
      {students.map(student => (
        <li key={student}>{student}</li>
      ))}
    </ul>
  );
}

export default StudentList;
Output 
• Rahul
• Priya
• Aarav

Explanation

The expression:

JSX 
students.map(student => (
  <li key={student}>{student}</li>
))

runs once for every student in the array.

For each name, it returns a list item. The result is an array of JSX elements that React can render inside the ul.

A key is included because React needs a stable way to identify items in a rendered list. We will explore that in Topic 7.

6.4 Display Objects from an Array

In real applications, data usually contains several properties.

JSX 
function CourseList() {
  const courses = [
    { id: 1, title: "HTML and CSS", duration: "1 month" },
    { id: 2, title: "JavaScript", duration: "2 months" },
    { id: 3, title: "React", duration: "2 months" }
  ];

  return (
    <div>
      <h1>Available Courses</h1>

      {courses.map(course => (
        <article key={course.id}>
          <h2>{course.title}</h2>
          <p>Duration: {course.duration}</p>
        </article>
      ))}
    </div>
  );
}

export default CourseList;

Explanation:

  • courses is an array of course objects.
  • Each object contains an id, title, and duration.
  • map() goes through the array.
  • Each course produces an article.
  • Its values are displayed using JSX expressions.
  • course.id is used as the key.

6.5 Displaying Lists with a Component

You can also render a reusable child component for each item.

JSX 
function StudentCard({ name, course }) {
  return (
    <article>
      <h2>{name}</h2>
      <p>Course: {course}</p>
    </article>
  );
}

function StudentList() {
  const students = [
    { id: 1, name: "Rahul", course: "React" },
    { id: 2, name: "Priya", course: "JavaScript" }
  ];

  return (
    <div>
      {students.map(student => (
        <StudentCard
          key={student.id}
          name={student.name}
          course={student.course}
        />
      ))}
    </div>
  );
}

export default StudentList;

This combines the Phase 1 topics of components and props with the Phase 2 topic of list rendering.

React renders one StudentCard for each item, and the props customize each card.

Remember

map() transforms each item in an array into a new value. In React, that value is often JSX describing an element or a component instance.

Keys and Stable Identity

7.1 What Is a Key in React?

Simple Definition

A key is a special value that helps React identify an element within a list of sibling elements.

JSX 
const students = [
  { id: 101, name: "Rahul" },
  { id: 102, name: "Priya" }
];

function StudentList() {
  return (
    <ul>
      {students.map(student => (
        <li key={student.id}>
          {student.name}
        </li>
      ))}
    </ul>
  );
}

Here, each list item uses the student's unique ID as its key.

7.2 Why Does React Need Keys?

Imagine a list containing:

List 
Rahul
Priya
Aarav

Suppose Priya is removed.

React needs to recognize which data item was removed and how the remaining items correspond to the previous render.

Keys provide that identity information.

Without good keys, React may have trouble matching items correctly when elements are inserted, deleted, or rearranged.

7.3 Analogy: Student Roll Numbers

Analogy

Imagine an institute with hundreds of students.

If you identify students only by their current position in a list, a student can move from position three to position two when someone leaves.

A roll number identifies the student independently of their position.

React list keys serve a similar purpose.

7.4 What Makes a Good Key?

A good key should be:

  • Unique among sibling elements.
  • Stable across renders.
  • Associated with the actual data item.

For data from a database, the record's unique ID is usually a good choice.

For locally created items, an ID can be generated when the item is created and then stored with it.

7.5 Why Is key={index} Often a Bad Choice?

Consider:

JSX 
{students.map((student, index) => (
  <li key={index}>{student.name}</li>
))}

This uses an item's current position as its identity.

If items are added, removed, or reordered, their indexes can change. That can cause React to associate a rendered item with the wrong identity, particularly when list elements contain local state or user input.

Index keys can be acceptable for a truly static list that will not be reordered, inserted into, or deleted from. For lists that change, a stable data ID is usually preferable.

7.6 Do Not Generate Keys During Rendering

Avoid this:

JSX 
{students.map(student => (
  <li key={Math.random()}>{student.name}</li>
))}

The generated key changes every time the list renders. React then sees items as different elements rather than continuing identities, potentially recreating DOM elements and losing input state.

Generate an ID when the item is created, not every time it is rendered.

7.7 Is key Passed as a Normal Prop?

No. React uses key for its internal reconciliation process.

If the child component needs to use the ID, pass it as a separate prop:

JSX 
<StudentCard
  key={student.id}
  studentId={student.id}
  name={student.name}
/>

key identifies the list element to React. studentId is an ordinary prop that the component can read.

Remember

Keys help React match list items between renders. Use stable IDs when available, especially for dynamic lists.

A useful thought experiment: if you delete the second item and the third item's input value suddenly appears in the second row, your keys are wrong. That is the exact bug index-keys cause.

Updating Objects in State

8.1 Can State Contain an Object?

Simple Definition

Yes. React state can contain any kind of JavaScript value, including objects.

JSX 
const [student, setStudent] = useState({
  name: "Rahul",
  age: 21,
  city: "Rajkot"
});

This single state variable stores information about a student.

8.2 Why Would We Store an Object in State?

Imagine a student profile form.

A student has a name, age, city, and course. These values describe one entity, so an object is a natural way to organize them.

Using an object can also make it convenient to pass related properties together.

8.3 Updating One Property

Suppose you want to change the city while preserving the student's name and age.

The recommended pattern is:

JSX 
setStudent(currentStudent => ({
  ...currentStudent,
  city: "Ahmedabad"
}));

This:

  1. Reads the previous object.
  2. Copies its existing properties.
  3. Replaces city with the new value.
  4. Passes the new object to the setter.

8.4 Complete Example

JSX 
import { useState } from "react";

function StudentProfile() {
  const [student, setStudent] = useState({
    name: "Rahul",
    age: 21,
    city: "Rajkot"
  });

  function changeCity() {
    setStudent(currentStudent => ({
      ...currentStudent,
      city: "Ahmedabad"
    }));
  }

  function increaseAge() {
    setStudent(currentStudent => ({
      ...currentStudent,
      age: currentStudent.age + 1
    }));
  }

  return (
    <div>
      <h2>{student.name}</h2>
      <p>Age: {student.age}</p>
      <p>City: {student.city}</p>

      <button onClick={changeCity}>
        Change City
      </button>

      <button onClick={increaseAge}>
        Increase Age
      </button>
    </div>
  );
}

export default StudentProfile;

Both buttons update the state object immutably.

When the city changes, the name and age remain the same. When the age changes, the name and city remain the same.

8.5 Updating a Nested Object

Consider a state object containing another object:

JSX 
const [student, setStudent] = useState({
  name: "Priya",
  address: {
    city: "Rajkot",
    state: "Gujarat"
  }
});

Suppose you want to change the city inside address.

You must create a new address object and a new outer student object.

JSX 
setStudent(currentStudent => ({
  ...currentStudent,
  address: {
    ...currentStudent.address,
    city: "Ahmedabad"
  }
}));

Why Are Two Copies Needed?

Object spread only creates a shallow copy. Copying the outer object does not automatically create a new copy of every nested object.

The nested address object must also be copied because one of its properties is being changed.

This principle applies at every level of a nested structure that you need to update.

Remember

When updating state objects, copy the existing properties, replace the specific value, and submit the new object through the setter. For nested objects, copy each level that you need to change.

Updating Arrays in State

9.1 Why Do We Use Arrays in State?

Arrays are useful for storing collections that change over time.

Examples include:

  • Student records
  • Tasks
  • Selected courses
  • Shopping cart items
  • Notifications
  • Form entries

When the collection changes, the component may need to render the new list.

9.2 Creating an Array in State

JSX 
import { useState } from "react";

function CourseList() {
  const [courses, setCourses] = useState([
    "HTML",
    "CSS",
    "JavaScript"
  ]);

  return (
    <ul>
      {courses.map(course => (
        <li key={course}>{course}</li>
      ))}
    </ul>
  );
}

The array is held in state and transformed into list items using map().

9.3 Adding an Item

When adding an item, create a new array.

JSX 
setCourses(currentCourses => [
  ...currentCourses,
  "React"
]);

The spread syntax copies the existing items into a new array and adds "React" at the end.

Avoid changing the original state array with push().

Incorrect:

JSX 
courses.push("React");
setCourses(courses);

This directly mutates the existing array and passes the same array reference to the setter.

Correct:

JSX 
setCourses(currentCourses => [
  ...currentCourses,
  "React"
]);

9.4 Removing an Item

Use filter() to create a new array containing only the items you want to keep.

JSX 
setCourses(currentCourses =>
  currentCourses.filter(course => course !== "CSS")
);

Every course except "CSS" remains in the new array.

9.5 Updating an Item

Use map() when you want to replace one or more items based on a condition.

JSX 
setCourses(currentCourses =>
  currentCourses.map(course =>
    course === "CSS" ? "Advanced CSS" : course
  )
);

The expression checks each course:

  • If it is "CSS", the new item becomes "Advanced CSS".
  • Otherwise, the original value is returned.

The new array contains all the items, with the chosen item updated.

9.6 Complete Example: Course Management

JSX 
import { useState } from "react";

function CourseManager() {
  const [courses, setCourses] = useState([
    "HTML",
    "CSS",
    "JavaScript"
  ]);

  function addCourse() {
    setCourses(currentCourses => [
      ...currentCourses,
      "React"
    ]);
  }

  function removeCSS() {
    setCourses(currentCourses =>
      currentCourses.filter(course => course !== "CSS")
    );
  }

  function renameJavaScript() {
    setCourses(currentCourses =>
      currentCourses.map(course =>
        course === "JavaScript" ? "JavaScript Advanced" : course
      )
    );
  }

  return (
    <div>
      <h2>Courses</h2>

      <ul>
        {courses.map(course => (
          <li key={course}>{course}</li>
        ))}
      </ul>

      <button onClick={addCourse}>Add React</button>
      <button onClick={removeCSS}>Remove CSS</button>
      <button onClick={renameJavaScript}>Rename JavaScript</button>
    </div>
  );
}

export default CourseManager;

This component demonstrates three different array operations:

  • Add with spread syntax.
  • Remove with filter().
  • Update with map().
Note

The example is intended for learning. In a real application, courses would have unique IDs, because titles can be duplicated or changed. For a dynamic list, those IDs should be used as the keys instead of course names.

9.7 Quick Reference

OperationRecommended approach
Add an itemSpread syntax: [...items, newItem]
Remove an itemfilter()
Update an itemmap()

Remember

Treat arrays stored in state as read-only. Use methods that return new arrays, then call the state setter.

Three verbs, three tools. Add → spread. Remove → filter. Update → map. If you remember only this, you can handle almost any state array you'll ever meet.

Lifting State Up

10.1 What Is Lifting State Up?

Simple Definition

Lifting state up means moving state from a child component into the closest common parent component when multiple components need to share or coordinate that information.

Once the parent owns the state, it can pass the current value down through props and pass handler functions down so child components can request updates.

10.2 Why Do We Need It?

Imagine a course dashboard with two components:

  • A search input
  • A course list

The search input needs to tell the application what the user is searching for. The course list needs that search value so it can display the correct courses.

If the search value is stored only inside the input component, the course list does not automatically have access to it.

Moving the search state to a common parent lets both components work with the same information.

10.3 Analogy: A Manager Coordinating a Team

Analogy

Imagine a manager responsible for a team.

The manager keeps the current task status and communicates relevant information to different team members.

Similarly, a parent component can own a piece of state and pass the value and update functions to child components.

The children do not need separate copies of the same shared state.

10.4 Example: Two Components Showing the Same Name

First, we create a child component for an input.

JSX 
function NameInput({ name, onNameChange }) {
  return (
    <input
      value={name}
      onChange={event => onNameChange(event.target.value)}
    />
  );
}

Another component displays the name.

JSX 
function NameDisplay({ name }) {
  return <h2>Hello, {name}</h2>;
}

The parent keeps the shared state:

JSX 
import { useState } from "react";

function App() {
  const [name, setName] = useState("Rahul");

  return (
    <div>
      <NameInput name={name} onNameChange={setName} />
      <NameDisplay name={name} />
    </div>
  );
}

export default App;

What Happens Here?

  1. App owns the name state.
  2. App passes name to NameInput.
  3. It also passes setName as onNameChange.
  4. When the input changes, the child calls the handler with the updated string.
  5. The parent updates the state.
  6. React renders the parent and its children with the new name.
  7. The input and heading display the same value.

The data flows down through props, while the child invokes a callback to request an update.

10.5 What If Each Child Keeps Its Own State?

If the input stores its own name and the display separately stores its own name, they can get out of sync.

Lifting the state to the parent creates a single source of truth for the shared name.

This does not mean all state in a React application belongs at the top. State should normally live in the closest component that needs to own or coordinate it.

Remember

Lift state up when components need to share or coordinate the same information. Keep the shared state in their closest common parent, then pass the value and necessary handlers through props.

Controlled Inputs

11.1 What Is a Controlled Input?

Simple Definition

A controlled input is an input element whose displayed value is controlled by React state.

For a text input, the common pattern is:

JSX 
<input
  value={name}
  onChange={event => setName(event.target.value)}
/>

The value prop defines what the input displays. The onChange handler updates the state as the user types.

11.2 Analogy: A Form Connected to a Dashboard

Analogy

Imagine a control panel where every change you make is immediately reflected in its displayed values.

A controlled input works similarly:

• React state stores the current input value.
• The input displays that value.
• A user edit triggers onChange.
• The handler requests a state update.
• React renders the latest value into the input.

11.3 Create a Controlled Name Input

JSX 
import { useState } from "react";

function NameForm() {
  const [name, setName] = useState("");

  return (
    <div>
      <label htmlFor="student-name">Student Name</label>

      <input
        id="student-name"
        type="text"
        value={name}
        onChange={event => setName(event.target.value)}
        placeholder="Enter your name"
      />

      <p>Entered name: {name}</p>
    </div>
  );
}

export default NameForm;

Explanation

Initial state

JSX 
const [name, setName] = useState("");

The input begins with an empty string.

Controlled value

JSX 
value={name}

The input displays the current value of the state variable.

Update the value

JSX 
onChange={event => setName(event.target.value)}

When the user edits the input, the event handler requests a state update with the new input value.

Display the state

JSX 
<p>Entered name: {name}</p>

The paragraph shows the same state that controls the input.

11.4 Controlled Textareas

The same pattern works with a textarea.

JSX 
import { useState } from "react";

function FeedbackForm() {
  const [feedback, setFeedback] = useState("");

  return (
    <div>
      <label htmlFor="feedback">Your Feedback</label>

      <textarea
        id="feedback"
        value={feedback}
        onChange={event => setFeedback(event.target.value)}
      />

      <p>Characters entered: {feedback.length}</p>
    </div>
  );
}

Here, the paragraph displays a calculated value based on the current state.

11.5 Controlled Select Inputs

A select input can also be controlled with state.

JSX 
import { useState } from "react";

function CourseSelect() {
  const [course, setCourse] = useState("React");

  return (
    <div>
      <label htmlFor="course">Choose a course</label>

      <select
        id="course"
        value={course}
        onChange={event => setCourse(event.target.value)}
      >
        <option value="React">React</option>
        <option value="JavaScript">JavaScript</option>
        <option value="Node.js">Node.js</option>
      </select>

      <p>Selected course: {course}</p>
    </div>
  );
}

The selected option is reflected in the course state.

11.6 Handling a Form Submission

A controlled input often appears inside a form.

JSX 
import { useState } from "react";

function StudentForm() {
  const [name, setName] = useState("");

  function handleSubmit(event) {
    event.preventDefault();

    alert(`Welcome, ${name}!`);
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="name">Name</label>

      <input
        id="name"
        value={name}
        onChange={event => setName(event.target.value)}
      />

      <button type="submit">Submit</button>
    </form>
  );
}

export default StudentForm;

The form's input is connected to state. When it is submitted, the handler reads the current value of name.

For this simple example, the form displays an alert. A real application might validate the value and send it to a backend service.

11.7 Common Mistake: Forgetting onChange

Consider this:

JSX 
<input value={name} />

When an input is controlled by a fixed value without an appropriate update handler, the user cannot normally change the displayed value through typing.

A regular controlled text input should usually provide both:

  • value
  • onChange
JSX 
<input
  value={name}
  onChange={event => setName(event.target.value)}
/>
Remember

A controlled input displays a value from React state and updates that state through an event handler. This gives the application control over the input's current value.

If your input feels "frozen" and typing does nothing, the first thing to check is: do I have both value and onChange? Nine times out of ten, that's the bug.

Sharing Data Between Components

Lifting state up and sharing data between components are closely related, but sharing data can involve more than just a single input and display.

A parent component might share:

  • A selected student
  • A list of tasks
  • A search term
  • A selected course
  • Functions for updating or deleting records

12.1 Data Usually Flows Down; Update Requests Can Flow Up

Consider this component structure:

App ├── SearchInput ├── CourseList └── CourseSummary

If App owns the search term, it can pass the value to SearchInput, CourseList, and CourseSummary.

It can also pass functions to the child components.

App (owns search state) / | \ v v v SearchInput CourseList Summary | | calls a supplied handler v Parent updates its state

This is the normal parent-and-child pattern in React.

12.2 Example: A Search Input and Course List

JSX 
import { useState } from "react";

function SearchInput({ searchTerm, onSearchChange }) {
  return (
    <input
      value={searchTerm}
      onChange={event => onSearchChange(event.target.value)}
      placeholder="Search courses"
    />
  );
}

function CourseList({ courses, searchTerm }) {
  const filteredCourses = courses.filter(course =>
    course.toLowerCase().includes(searchTerm.toLowerCase())
  );

  return (
    <ul>
      {filteredCourses.map(course => (
        <li key={course}>{course}</li>
      ))}
    </ul>
  );
}

function App() {
  const [searchTerm, setSearchTerm] = useState("");

  const courses = [
    "React",
    "JavaScript",
    "Node.js",
    "MongoDB"
  ];

  return (
    <main>
      <h1>Course Directory</h1>

      <SearchInput
        searchTerm={searchTerm}
        onSearchChange={setSearchTerm}
      />

      <CourseList
        courses={courses}
        searchTerm={searchTerm}
      />
    </main>
  );
}

export default App;

Explanation

The parent owns the search state.

JSX 
const [searchTerm, setSearchTerm] = useState("");

This gives the application one source of truth for the current search term.

The input receives its value and handler.

JSX 
<SearchInput
  searchTerm={searchTerm}
  onSearchChange={setSearchTerm}
/>

When the user types, SearchInput calls the supplied function, allowing the parent to update the state.

The list receives the same term.

JSX 
<CourseList
  courses={courses}
  searchTerm={searchTerm}
/>

The list filters its data based on that shared value. As the term changes, the component renders the results that match the new term.

This example includes derived data, which will be explained more fully in Topic 13.

12.3 Sharing a Handler Through Props

A handler can be passed through several components when the UI structure requires it.

For example, a parent may provide:

JSX 
<DeleteButton onDelete={handleDelete} />

The child can invoke that callback when the user interacts with its button:

JSX 
function DeleteButton({ onDelete }) {
  return (
    <button onClick={onDelete}>
      Delete
    </button>
  );
}

The child does not need direct access to the parent's state. It invokes the function supplied by the parent.

This approach lets the parent decide how deletion should be handled.

12.4 Why Is One Source of Truth Important?

Imagine storing the same selected course independently in three different components.

Each component might change its own value without updating the other copies.

This can make the interface inconsistent.

A shared source of truth avoids that problem. The appropriate parent stores the value and distributes it to the components that need it.

Remember

Share values through props and share update behavior through callbacks. The component that owns the state controls how those values change.

Derived State and Avoiding Redundant State

13.1 What Is Derived State?

Simple Definition

Derived state is information that can be calculated from existing props or state.

For example:

  • The number of completed tasks
  • The number of active students
  • A filtered list of courses
  • The total price of items in a cart
  • The full name formed from a first name and last name

When such information can be calculated directly from values that already exist, it often does not need its own state variable.

13.2 Analogy: Calculating a Shopping Bill

Analogy

Imagine a shopping cart containing:

• Notebook — ₹50
• Pen — ₹20
• Bag — ₹500

The total is ₹570.

You do not need to separately maintain an unrelated total value if you can calculate it from the current items.

The same principle applies to a React component.

13.3 Example: Full Name

A student has a first name and a last name.

JSX 
function Student() {
  const firstName = "Rahul";
  const lastName = "Sharma";

  const fullName = `${firstName} ${lastName}`;

  return <h1>{fullName}</h1>;
}

fullName is calculated from two existing variables. It does not require a separate useState call.

13.4 Avoid Duplicating State

Consider a task list:

JSX 
const [tasks, setTasks] = useState([
  { id: 1, title: "Learn JSX", completed: true },
  { id: 2, title: "Learn useState", completed: false },
  { id: 3, title: "Practise events", completed: false }
]);

Suppose you also want to track the number of completed tasks.

A redundant approach would be to store both the task list and a separate completedCount state variable, then update both every time a task is completed or removed.

This is unnecessary for a simple calculation.

Instead, calculate the count:

JSX 
const completedCount = tasks.filter(task => task.completed).length;

Explanation:

  1. filter() selects the tasks whose completed property is true.
  2. .length counts the selected tasks.
  3. completedCount stores the result of this calculation for the current render.

Display it:

JSX 
<p>Completed tasks: {completedCount}</p>

When tasks changes and the component renders again, completedCount is recalculated.

13.5 Derived Lists

A filtered list is another example of derived data.

JSX 
const [filter, setFilter] = useState("all");

const visibleTasks = tasks.filter(task => {
  if (filter === "active") {
    return !task.completed;
  }

  if (filter === "completed") {
    return task.completed;
  }

  return true;
});

Here:

  • tasks is the source data.
  • filter records the selected filter option.
  • visibleTasks is calculated from those values.

The visibleTasks variable does not need its own state because it can be recalculated whenever the component renders.

13.6 What Is the Problem with Redundant State?

Imagine storing all three values separately:

JSX 
const [tasks, setTasks] = useState([]);
const [completedCount, setCompletedCount] = useState(0);
const [activeCount, setActiveCount] = useState(0);

Now imagine removing a completed task.

You would need to remember to update the task list, completed count, and active count correctly.

If one update is forgotten or the calculations differ, the values can become inconsistent.

A simpler approach is to store the essential data:

JSX 
const [tasks, setTasks] = useState([]);

Then calculate both counts from the list:

JSX 
const completedCount = tasks.filter(task => task.completed).length;
const activeCount = tasks.filter(task => !task.completed).length;

The counts now always describe the current task list whenever the component renders.

13.7 When Should Something Be State?

Ask yourself three questions:

  1. Can I calculate this value from current props or state?
  2. Does the value need to be remembered independently?
  3. Can storing it separately lead to inconsistent data?

If the value can be calculated directly and does not need independent storage, prefer a normal variable for that render.

Derived calculations can be repeated during rendering. If a calculation later becomes expensive, React provides optimization techniques that you can learn in a future phase. Do not introduce those techniques before you need them.

Remember

Store the essential changing information in state. Calculate values that depend on it, such as counts and filtered lists, during rendering instead of maintaining duplicate state unnecessarily.

Every time you're about to add a second useState that "tracks" something already in your first state, pause. Ask: could this be calculated instead? If yes, calculating is almost always the better choice.

JSX 
if (tasks.length === 0) {
  return <p>No tasks found for this filter.</p>;
}

If the current list is empty, the component returns an explanatory message.

Rendering a list

JSX 
tasks.map(task => (
  <li key={task.id}>
    {task.title}
  </li>
))

The component renders one list item for each task, using its stored ID as the key.

Updating task status

JSX 
<button onClick={() => onToggle(task.id)}>
  {task.completed ? "Mark Active" : "Complete"}
</button>

The child calls the function provided by the parent and supplies the task ID. The parent decides how to update the state.

Deleting a task

JSX 
<button onClick={() => onDelete(task.id)}>
  Delete
</button>

The delete handler is supplied through props, so the child does not directly modify the task array.

Step 4: Create App.jsx

The parent component owns the task list, form input, and filter.

JSX · App.jsx 
import { useState } from "react";
import TaskForm from "./components/TaskForm.jsx";
import TaskList from "./components/TaskList.jsx";
import "./App.css";

function App() {
  const [tasks, setTasks] = useState([
    {
      id: 1,
      title: "Practise JSX",
      completed: true
    },
    {
      id: 2,
      title: "Learn useState",
      completed: false
    },
    {
      id: 3,
      title: "Practise events",
      completed: false
    }
  ]);

  const [newTask, setNewTask] = useState("");
  const [filter, setFilter] = useState("all");

  function handleAddTask(event) {
    event.preventDefault();

    const title = newTask.trim();

    if (title === "") {
      return;
    }

    const task = {
      id: crypto.randomUUID(),
      title,
      completed: false
    };

    setTasks(currentTasks => [
      ...currentTasks,
      task
    ]);

    setNewTask("");
  }

  function handleToggleTask(taskId) {
    setTasks(currentTasks =>
      currentTasks.map(task =>
        task.id === taskId
          ? { ...task, completed: !task.completed }
          : task
      )
    );
  }

  function handleDeleteTask(taskId) {
    setTasks(currentTasks =>
      currentTasks.filter(task => task.id !== taskId)
    );
  }

  const visibleTasks = tasks.filter(task => {
    if (filter === "active") {
      return !task.completed;
    }

    if (filter === "completed") {
      return task.completed;
    }

    return true;
  });

  const completedCount = tasks.filter(
    task => task.completed
  ).length;

  const activeCount = tasks.length - completedCount;

  return (
    <main className="app">
      <h1>Student Task Tracker</h1>

      <p>Total Tasks: {tasks.length}</p>
      <p>Completed: {completedCount}</p>
      <p>Active: {activeCount}</p>

      <TaskForm
        value={newTask}
        onValueChange={setNewTask}
        onAdd={handleAddTask}
      />

      <div className="filter">
        <label htmlFor="task-filter">Filter Tasks</label>

        <select
          id="task-filter"
          value={filter}
          onChange={event => setFilter(event.target.value)}
        >
          <option value="all">All Tasks</option>
          <option value="active">Active Tasks</option>
          <option value="completed">Completed Tasks</option>
        </select>
      </div>

      <TaskList
        tasks={visibleTasks}
        onToggle={handleToggleTask}
        onDelete={handleDeleteTask}
      />
    </main>
  );
}

export default App;

Important Code Explanations

1. State for the Task List

JSX 
const [tasks, setTasks] = useState([...]);

This array contains the original task objects. Each task stores its ID, title, and completion status.

2. Adding a Task

JSX 
const title = newTask.trim();

if (title === "") {
  return;
}

trim() removes whitespace at the beginning and end of the input. If nothing remains, the handler exits without adding a task.

JSX 
const task = {
  id: crypto.randomUUID(),
  title,
  completed: false
};

The new task receives an ID when it is created, not when the UI is rendered.

In modern browsers, crypto.randomUUID() can generate a unique identifier in supported secure contexts, including localhost during development.

JSX 
setTasks(currentTasks => [
  ...currentTasks,
  task
]);

The updater produces a new array containing all existing tasks and the new task.

JSX 
setNewTask("");

After a successful addition, the controlled input is cleared.

3. Toggling Task Status

JSX 
setTasks(currentTasks =>
  currentTasks.map(task =>
    task.id === taskId
      ? { ...task, completed: !task.completed }
      : task
  )
);

This code creates a new array. For the matching task, it creates a new task object with the opposite completion value. Every other task is returned unchanged.

Both the array and the modified task object are updated immutably.

4. Deleting a Task

JSX 
setTasks(currentTasks =>
  currentTasks.filter(task => task.id !== taskId)
);

This creates a new array that excludes the selected task.

5. Calculating Visible Tasks

JSX 
const visibleTasks = tasks.filter(task => {
  if (filter === "active") {
    return !task.completed;
  }

  if (filter === "completed") {
    return task.completed;
  }

  return true;
});

The displayed list is calculated from the full task collection and the chosen filter. It is not stored as a separate state variable.

6. Calculating the Counters

JSX 
const completedCount = tasks.filter(
  task => task.completed
).length;

const activeCount = tasks.length - completedCount;

Both numbers are calculated directly from the current task list. This avoids maintaining duplicate state for the counts.

BUGS
Debugging

Common Beginner Mistakes

Mistake 1: Calling an Event Handler Immediately

Incorrect
JSX 
<button onClick={handleClick()}>
  Click Me
</button>

This calls handleClick() during rendering rather than passing the function for React to call when the button is clicked.

Correct
JSX 
<button onClick={handleClick}>
  Click Me
</button>

When you need to pass an argument, use a function:

JSX 
<button onClick={() => handleDelete(task.id)}>
  Delete
</button>

Mistake 2: Updating State by Direct Assignment

Incorrect
JSX 
count = count + 1;
Correct
JSX 
setCount(current => current + 1);

Use the state setter to request an update.

Mistake 3: Assuming State Changes Immediately

JSX 
setCount(count + 1);
console.log(count);

The console statement reads count from the current render. It does not necessarily show the new value.

React state is a snapshot for each render. The updated value becomes available to the component on a subsequent render.

Mistake 4: Mutating an Object

Incorrect
JSX 
student.city = "Ahmedabad";
setStudent(student);
Correct
JSX 
setStudent(current => ({
  ...current,
  city: "Ahmedabad"
}));

Mistake 5: Mutating an Array

Incorrect
JSX 
tasks.push(newTask);
setTasks(tasks);
Correct
JSX 
setTasks(currentTasks => [
  ...currentTasks,
  newTask
]);

Mistake 6: Forgetting Keys in a List

Incorrect
JSX 
items.map(item => <li>{item.name}</li>);
Correct
JSX 
items.map(item => (
  <li key={item.id}>{item.name}</li>
));

Use a stable ID when available.

Mistake 7: Storing Every Calculated Value in State

You normally do not need separate state for a count that can be derived from a task array.

Instead of maintaining several values independently, keep the essential state and calculate the result.

Mistake 8: Forgetting to Prevent Form Submission

When handling a form in JavaScript, remember:

JSX 
function handleSubmit(event) {
  event.preventDefault();
}

This prevents the browser's default submission behavior when that behavior is not desired.

REVI
NOTES
Recap

Revision Notes

Event handling: Connecting an event, such as a click, to a function.
Event object: An object that provides details about the event and methods such as preventDefault().
State: Information managed by React and retained between renders.
useState: A Hook that declares state and provides a setter to request updates.
State setter: The function used to request a new state value.
State versus variables: Local variables do not automatically trigger React renders; state setters request updates.
Immutability: Treat objects and arrays in state as read-only. Create updated copies instead of mutating existing state values.
Conditional rendering: Displaying different UI content based on conditions.
map(): Creating a new array, often used to convert data items into JSX elements.
Keys: Stable identifiers used by React to match sibling elements in lists.
Updating objects: Use object spread syntax to create an updated object.
Updating arrays: Use patterns such as spread syntax, map(), and filter() to create new arrays.
Lifting state up: Moving shared state into the closest common parent of components that need it.
Controlled input: An input whose displayed value is driven by React state.
Sharing data: Passing values and handler functions to child components through props.
Derived state: A value that can be calculated from current props or state without maintaining duplicate state.
