Project 1

Build a Task Manager with CRUD

Create, read, update, and delete — the foundation of every data-driven UI.

Real-life analogy: A digital notebook

Imagine maintaining a notebook of daily tasks. You write new tasks, read your list, edit details, and cross out completed tasks.

A task manager is the same idea implemented in React.

CRUD means:

  • Create: Add a new task.
  • Read: Display the tasks.
  • Update: Edit a task or mark it complete.
  • Delete: Remove a task.

This project revises React state, event handling, forms, list rendering, conditional UI, and TypeScript.

Analogy · The digital notebook
A task manager is a notebook you can rewrite with one tap. Create is a new line. Read is flipping the page. Update is an eraser. Delete is a tear. React state holds the current page; the DOM repaints the whole notebook cleanly.

1.1 Define the task model

TaskManager.tsxTSX
// TaskManager.tsx

interface Task {
  id: string;
  title: string;
  completed: boolean;
}

The Task interface specifies the structure of one task. Using this type helps ensure that every task has an identifier, title, and completion status.

1.2 Build the complete CRUD application

Create TaskManager.tsx:

TaskManager.tsxTSX
import { useMemo, useState } from "react";
import type { FormEvent } from "react";

interface Task {
  id: string;
  title: string;
  completed: boolean;
}

type Filter = "all" | "active" | "completed";

export default function TaskManager() {
  const [tasks, setTasks] = useState<Task[]>([]);
  const [title, setTitle] = useState("");
  const [editingId, setEditingId] = useState<string | null>(null);
  const [filter, setFilter] = useState<Filter>("all");
  const [error, setError] = useState("");

  function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();

    const cleanedTitle = title.trim();

    if (!cleanedTitle) {
      setError("Enter a task title.");
      return;
    }

    setError("");

    if (editingId !== null) {
      setTasks((previous) =>
        previous.map((task) =>
          task.id === editingId
            ? { ...task, title: cleanedTitle }
            : task
        )
      );

      setEditingId(null);
    } else {
      const newTask: Task = {
        id: crypto.randomUUID(),
        title: cleanedTitle,
        completed: false,
      };

      setTasks((previous) => [...previous, newTask]);
    }

    setTitle("");
  }

  function startEditing(task: Task) {
    setEditingId(task.id);
    setTitle(task.title);
    setError("");
  }

  function toggleTask(taskId: string) {
    setTasks((previous) =>
      previous.map((task) =>
        task.id === taskId
          ? { ...task, completed: !task.completed }
          : task
      )
    );
  }

  function deleteTask(taskId: string) {
    setTasks((previous) =>
      previous.filter((task) => task.id !== taskId)
    );

    if (editingId === taskId) {
      setEditingId(null);
      setTitle("");
    }
  }

  const visibleTasks = useMemo(() => {
    return tasks.filter((task) => {
      if (filter === "active") return !task.completed;
      if (filter === "completed") return task.completed;
      return true;
    });
  }, [tasks, filter]);

  const completedCount = tasks.filter(
    (task) => task.completed
  ).length;

  return (
    <main className="mx-auto max-w-2xl space-y-6 p-6">
      <header>
        <h1 className="text-3xl font-bold">Task Manager</h1>
        <p className="mt-2 text-slate-600">
          Organize your daily work.
        </p>
      </header>

      <section className="rounded-xl border p-5">
        <form onSubmit={handleSubmit} className="space-y-3">
          <label
            htmlFor="task-title"
            className="block font-medium"
          >
            Task title
          </label>

          <div className="flex flex-col gap-3 sm:flex-row">
            <input
              id="task-title"
              value={title}
              onChange={(event) => setTitle(event.currentTarget.value)}
              placeholder="Enter a task..."
              className="min-w-0 flex-1 rounded-lg border p-3"
            />

            <button
              type="submit"
              className="rounded-lg bg-indigo-600 px-4 py-3 text-white"
            >
              {editingId !== null ? "Update Task" : "Add Task"}
            </button>
          </div>

          {error && (
            <p role="alert" className="text-sm text-red-700">
              {error}
            </p>
          )}

          {editingId !== null && (
            <button
              type="button"
              onClick={() => {
                setEditingId(null);
                setTitle("");
                setError("");
              }}
              className="text-sm underline"
            >
              Cancel editing
            </button>
          )}
        </form>
      </section>

      <section className="flex flex-wrap items-center justify-between gap-3">
        <p>
          Total: {tasks.length} · Completed: {completedCount}
        </p>

        <label className="flex items-center gap-2">
          <span>Filter</span>

          <select
            value={filter}
            onChange={(event) =>
              setFilter(event.currentTarget.value as Filter)
            }
            className="rounded-lg border p-2"
          >
            <option value="all">All</option>
            <option value="active">Active</option>
            <option value="completed">Completed</option>
          </select>
        </label>
      </section>

      <ul className="space-y-3">
        {visibleTasks.map((task) => (
          <li
            key={task.id}
            className="flex flex-wrap items-center justify-between gap-3 rounded-xl border p-4"
          >
            <label className="flex min-w-0 flex-1 items-center gap-3">
              <input
                type="checkbox"
                checked={task.completed}
                onChange={() => toggleTask(task.id)}
              />

              <span
                className={
                  task.completed
                    ? "break-words text-slate-500 line-through"
                    : "break-words"
                }
              >
                {task.title}
              </span>
            </label>

            <div className="flex gap-2">
              <button
                type="button"
                onClick={() => startEditing(task)}
                className="rounded-lg border px-3 py-2"
              >
                Edit
              </button>

              <button
                type="button"
                onClick={() => deleteTask(task.id)}
                className="rounded-lg border border-red-300 px-3 py-2 text-red-700"
              >
                Delete
              </button>
            </div>
          </li>
        ))}
      </ul>

      {visibleTasks.length === 0 && (
        <p role="status" className="text-center text-slate-500">
          No tasks to display.
        </p>
      )}
    </main>
  );
}

Understand the important decisions

Creating a task

CreateTSX
setTasks((previous) => [...previous, newTask]);

The new task is added without mutating the existing array. The functional updater is useful because it works with the latest queued state.

Updating a task

UpdateTSX
previous.map((task) =>
  task.id === editingId
    ? { ...task, title: cleanedTitle }
    : task
)

Only the matching task is replaced. The other task objects are preserved.

Deleting a task

DeleteTSX
previous.filter((task) => task.id !== taskId)

The filter returns an array without the deleted task.

Filtering

visibleTasks is calculated from the original tasks and selected filter. It is not kept in a separate state variable because it is derived data.

The useMemo in this example is not necessary for a small task list. It is included to let you practice Phase 9 concepts; profile the application before deciding whether you would keep it in a small production component.

This application stores data in memory, so refreshing the page clears the task list. Persistent storage and backend synchronization are optional extensions.

Project 2

Build a Weather App Using an API

Two requests, one user experience: geocoding, forecast, loading, errors.

Real-life analogy: A weather station

Imagine a weather station observes the current temperature, wind, and humidity at a location. A weather app requests those observations from a weather service and presents them in a user-friendly format.

This project revises asynchronous JavaScript, API integration, controlled forms, loading states, errors, and data validation.

For this learning example, use Open-Meteo. It provides a geocoding API for looking up coordinates from a place name and a forecast API for requesting weather data. Check its API documentation and usage terms before using it in a commercial product.

Analogy · The weather station
A weather app is a two-step conversation with the sky. First you ask where (geocoding). Then you ask what (forecast). Each request can fail, take time, or return unexpected data — so the app must show every state clearly.

2.1 How the API flow works

The app needs two requests:

  1. Search for a city and retrieve its latitude and longitude.
  2. Request weather information for those coordinates.

The endpoints used in this example are:

Endpoints
https://geocoding-api.open-meteo.com/v1/search
https://api.open-meteo.com/v1/forecast

The geocoding endpoint accepts a place name, while the forecast endpoint accepts coordinates and the requested weather variables. See the Open-Meteo geocoding documentation.

2.2 Build the weather app

Create WeatherApp.tsx:

WeatherApp.tsxTSX
import { useState } from "react";
import type { FormEvent } from "react";

interface LocationResult {
  id: number;
  name: string;
  country?: string;
  latitude: number;
  longitude: number;
}

interface GeocodingResponse {
  results?: LocationResult[];
}

interface CurrentWeather {
  temperature_2m: number;
  relative_humidity_2m: number;
  weather_code: number;
  wind_speed_10m: number;
}

interface ForecastResponse {
  current?: CurrentWeather;
  current_units?: {
    temperature_2m?: string;
    wind_speed_10m?: string;
  };
}

interface WeatherData {
  location: LocationResult;
  current: CurrentWeather;
  temperatureUnit: string;
  windSpeedUnit: string;
}

function weatherDescription(code: number): string {
  const descriptions: Record<number, string> = {
    0: "Clear sky",
    1: "Mainly clear",
    2: "Partly cloudy",
    3: "Overcast",
    45: "Fog",
    48: "Depositing rime fog",
    51: "Light drizzle",
    53: "Moderate drizzle",
    55: "Dense drizzle",
    61: "Slight rain",
    63: "Moderate rain",
    65: "Heavy rain",
    71: "Slight snowfall",
    73: "Moderate snowfall",
    75: "Heavy snowfall",
    95: "Thunderstorm",
  };

  return descriptions[code] ?? `Weather code ${code}`;
}

export default function WeatherApp() {
  const [city, setCity] = useState("");
  const [weather, setWeather] = useState<WeatherData | null>(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  async function handleSearch(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();

    const query = city.trim();

    if (!query) {
      setError("Enter a city name.");
      return;
    }

    setLoading(true);
    setError("");
    setWeather(null);

    try {
      const geocodingUrl =
        "https://geocoding-api.open-meteo.com/v1/search?" +
        new URLSearchParams({
          name: query,
          count: "1",
          language: "en",
          format: "json",
        });

      const geocodingResponse = await fetch(geocodingUrl);

      if (!geocodingResponse.ok) {
        throw new Error("Unable to search for this location.");
      }

      // The assertion describes the expected shape. For production,
      // validate external JSON at runtime before trusting it.
      const geocodingData =
        (await geocodingResponse.json()) as GeocodingResponse;

      const location = geocodingData.results?.[0];

      if (!location) {
        throw new Error("No matching city was found.");
      }

      const forecastUrl =
        "https://api.open-meteo.com/v1/forecast?" +
        new URLSearchParams({
          latitude: String(location.latitude),
          longitude: String(location.longitude),
          current:
            "temperature_2m,relative_humidity_2m,weather_code,wind_speed_10m",
          timezone: "auto",
        });

      const forecastResponse = await fetch(forecastUrl);

      if (!forecastResponse.ok) {
        throw new Error("Unable to load the weather forecast.");
      }

      const forecastData =
        (await forecastResponse.json()) as ForecastResponse;

      if (!forecastData.current) {
        throw new Error("Weather data is unavailable.");
      }

      setWeather({
        location,
        current: forecastData.current,
        temperatureUnit:
          forecastData.current_units?.temperature_2m ?? "°C",
        windSpeedUnit:
          forecastData.current_units?.wind_speed_10m ?? "km/h",
      });
    } catch (error: unknown) {
      setError(
        error instanceof Error
          ? error.message
          : "Something went wrong."
      );
    } finally {
      setLoading(false);
    }
  }

  return (
    <main className="mx-auto max-w-xl space-y-6 p-6">
      <header>
        <h1 className="text-3xl font-bold">Weather App</h1>
        <p className="mt-2 text-slate-600">
          Search for a city to see its current weather.
        </p>
      </header>

      <form onSubmit={handleSearch} className="flex gap-3">
        <label htmlFor="city" className="sr-only">
          City name
        </label>

        <input
          id="city"
          value={city}
          onChange={(event) => setCity(event.currentTarget.value)}
          placeholder="For example, Jaipur"
          className="min-w-0 flex-1 rounded-lg border p-3"
        />

        <button
          type="submit"
          disabled={loading}
          className="rounded-lg bg-indigo-600 px-4 py-3 text-white disabled:opacity-50"
        >
          {loading ? "Searching..." : "Search"}
        </button>
      </form>

      {error && <p role="alert">{error}</p>}

      {loading && <p role="status">Loading weather...</p>}

      {weather && (
        <section className="rounded-2xl border p-6 shadow-sm">
          <h2 className="text-2xl font-bold">
            {weather.location.name}
            {weather.location.country
              ? `, ${weather.location.country}`
              : ""}
          </h2>

          <p className="mt-3 text-4xl font-bold">
            {weather.current.temperature_2m}
            {weather.temperatureUnit}
          </p>

          <p className="mt-2 text-lg">
            {weatherDescription(weather.current.weather_code)}
          </p>

          <div className="mt-5 grid grid-cols-2 gap-4">
            <div>
              <p className="text-sm text-slate-500">Humidity</p>
              <p className="text-xl font-semibold">
                {weather.current.relative_humidity_2m}%
              </p>
            </div>

            <div>
              <p className="text-sm text-slate-500">Wind speed</p>
              <p className="text-xl font-semibold">
                {weather.current.wind_speed_10m}{" "}
                {weather.windSpeedUnit}
              </p>
            </div>
          </div>
        </section>
      )}
    </main>
  );
}

Understand the implementation

The first request finds the city. The app uses the location search response to obtain coordinates.

The second request retrieves the current conditions. The coordinates identify the location for which the forecast data is requested.

Loading and error states are explicit. The user can distinguish a pending request from a failed request.

The response types document expected fields. However, TypeScript assertions do not validate external JSON. A production app should validate the actual response schema, handle cancellations and stale requests, and display units supplied by the API.

Build a Searchable Product Catalogue

Filters, derived data, and component decomposition.

Real-life analogy: An online shop

Imagine an online shop with hundreds of products. Customers can type a product name, select a category, and limit the results to items that are in stock.

This project revises props, state, filtering, controlled inputs, derived data, and component decomposition.

The official React tutorial Thinking in React uses a searchable product table to explain how to identify components and choose where state should live.

Analogy · The online shop
A searchable catalogue is a shop assistant who can filter every shelf at once. Type a name, pick a category, tick "in stock only" — the assistant instantly narrows the list. The data stays in memory; the filters are derived, not duplicated.

3.2 Build the catalogue

ProductCatalogue.tsxTSX
import { useMemo, useState } from "react";

export default function ProductCatalogue() {
  const [query, setQuery] = useState("");
  const [category, setCategory] = useState("all");
  const [inStockOnly, setInStockOnly] = useState(false);

  const categories = [
    "all",
    ...new Set(products.map((product) => product.category)),
  ];

  const filteredProducts = useMemo(() => {
    return products.filter((product) => {
      const matchesName = product.name
        .toLowerCase()
        .includes(query.toLowerCase());

      const matchesCategory =
        category === "all" || product.category === category;

      const matchesStock =
        !inStockOnly || product.inStock;

      return matchesName && matchesCategory && matchesStock;
    });
  }, [query, category, inStockOnly]);

  return (
    <main className="mx-auto max-w-6xl space-y-6 p-6">
      <header>
        <h1 className="text-3xl font-bold">Product Catalogue</h1>
        <p className="mt-2 text-slate-600">
          Find products and compare prices.
        </p>
      </header>

      <section className="grid gap-3 sm:grid-cols-2 lg:grid-cols-3">
        <div>
          <label htmlFor="product-search" className="mb-1 block">
            Search products
          </label>
          <input
            id="product-search"
            value={query}
            onChange={(event) => setQuery(event.currentTarget.value)}
            className="w-full rounded-lg border p-3"
          />
        </div>

        <div>
          <label htmlFor="category" className="mb-1 block">
            Category
          </label>
          <select
            id="category"
            value={category}
            onChange={(event) => setCategory(event.currentTarget.value)}
            className="w-full rounded-lg border p-3"
          >
            {categories.map((item) => (
              <option key={item} value={item}>
                {item === "all" ? "All categories" : item}
              </option>
            ))}
          </select>
        </div>

        <label className="flex items-center gap-3">
          <input
            type="checkbox"
            checked={inStockOnly}
            onChange={(event) =>
              setInStockOnly(event.currentTarget.checked)
            }
          />
          In-stock products only
        </label>
      </section>

      <p role="status">
        Found {filteredProducts.length} products
      </p>

      {filteredProducts.length === 0 ? (
        <p>No products match your filters.</p>
      ) : (
        <div className="grid gap-4 sm:grid-cols-2 lg:grid-cols-3">
          {filteredProducts.map((product) => (
            <article key={product.id} className="rounded-xl border p-5">
              <h2 className="text-lg font-semibold">
                {product.name}
              </h2>

              <p className="mt-1 text-sm text-slate-500">
                {product.category}
              </p>

              <p className="mt-4 text-xl font-bold">
                {new Intl.NumberFormat("en-IN", {
                  style: "currency",
                  currency: "INR",
                  maximumFractionDigits: 0,
                }).format(product.price)}
              </p>

              <p className={product.inStock
                ? "mt-2 text-emerald-700"
                : "mt-2 text-red-700"
              }>
                {product.inStock ? "In stock" : "Out of stock"}
              </p>
            </article>
          ))}
        </div>
      )}
    </main>
  );
}

Project 4

Build an Authentication-Based Dashboard

Identity, roles, and the limits of frontend guards.

Real-life analogy: An office building

A security guard checks who may enter the building, while a separate access-control system determines which rooms each employee can enter.

Similarly, authentication establishes the user’s identity, and authorization determines the data or operations they may access.

This project combines protected UI routes, session status, role-aware navigation, and backend permissions.

▲ Security rule

A frontend route guard improves navigation and user experience. It does not secure an API or replace backend authorization.

Analogy · The office building
The lobby is a frontend route guard. The locks on each floor are the backend. The guard at the door (route guard) can point you toward the right elevator, but only the keycard reader on each floor (server authorization) decides whether the door opens.

4.1 Model the user and session

auth.tsTSX
type Role = "student" | "trainer" | "admin";

interface User {
  id: string;
  name: string;
  role: Role;
}

Your application also needs to represent an unresolved session check, not just "signed in" or "signed out."

For example:

AuthStateTSX

4.2 Protect frontend routes

The following example demonstrates a frontend route guard using React Router's declarative routing APIs.

RequireAuth.tsxTSX
import { Navigate, Outlet } from "react-router";

interface User {
  id: string;
  name: string;
  role: "student" | "trainer" | "admin";
}

type AuthState =
  | { status: "loading" }
  | { status: "anonymous" }
  | { status: "authenticated"; user: User };

function RequireAuth({
  auth,
}: {
  auth: AuthState;
}) {
  if (auth.status === "loading") {
    return <p role="status">Checking session...</p>;
  }

  if (auth.status === "anonymous") {
    return <Navigate to="/login" replace />;
  }

  return <Outlet />;
}

For a role-specific UI section:

RequireRole.tsxTSX
import type { ReactNode } from "react";

function RequireRole({
  user,
  allowedRoles,
  children,
}: {
  user: User;
  allowedRoles: User["role"][];
  children: ReactNode;
}) {
  if (!allowedRoles.includes(user.role)) {
    return <p>You do not have access to this section.</p>;

}

export interface Student {
  id: string;
  name: string;
  email: string;
  course: string;
}

const API_BASE_URL = import.meta.env.VITE_API_BASE_URL;

export async function getStudents(): Promise<Student[]> {
  const response = await fetch(`${API_BASE_URL}/students`, {
    credentials: "include",
    headers: {
      Accept: "application/json",
    },

The code illustrates an API contract and a centralized request function. The TypeScript assertion doesn't validate the response received over the network.

6.3 Consume the API in a component

StudentList.tsxTSX
import { useEffect, useState } from "react";
import { getStudents } from "./api/students";
import type { Student } from "./api/students";

function StudentList() {
  const [students, setStudents] = useState<Student[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    let active = true;

    getStudents()
      .then((data) => {
        if (active) setStudents(data);
      })
      .catch(() => {
        if (active) setError("Could not load students.");
      })
      .finally(() => {
        if (active) setLoading(false);
      });

    return () => {
      active = false;
    };
  }, []);

  if (loading) return <p role="status">Loading students...</p>;
  if (error) return <p role="alert">{error}</p>;

  return (
    <ul className="space-y-3">
      {students.map((student) => (
        <li key={student.id} className="rounded-lg border p-4">
          <h2 className="font-semibold">{student.name}</h2>
          <p>{student.email}</p>
          <p className="text-sm text-slate-500">{student.course}</p>
        </li>
      ))}
    </ul>
  );
}

export default StudentList;

This example handles a basic request lifecycle. For production, add runtime response validation, cancellation where appropriate, retry behavior if needed, and a robust data-fetching strategy. A library such as TanStack Query or RTK Query can help manage caching and request state.

Practice React Output and Debugging Questions

Reason about the code — not just recall the definition.

This topic tests your ability to reason about React code rather than only memorize definitions.

Analogy · The detective
Debugging is detective work, not guessing. Reproduce the bug, inspect the evidence, identify the root cause, fix it, and write a regression test so the same case cannot slip through twice.

Question 1 — State snapshot behavior

What happens when the user clicks this button?

Counter.tsxTSX
function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
  }

  return <button onClick={handleClick}>{count}</button>;
}
◆ Answer

The count increases by one, not three.

All three expressions use the state snapshot from the current render.

To increment by three:

Functional updatersTSX
setCount((value) => value + 1);
setCount((value) => value + 1);
setCount((value) => value + 1);

Functional updater functions allow React to process each update using the previous queued result.

Question 2 — Why does the list render incorrectly?

✕ Index keysTSX
{students.map((student, index) => (
  <StudentRow key={index} student={student} />
))}
◆ Answer

Index keys can cause incorrect component identity when items are reordered, inserted, or deleted.

Use a stable identifier:

Stable keyTSX
{students.map((student) => (
  <StudentRow key={student.id} student={student} />
))}

Question 3 — Why does this effect run repeatedly?

✕ Unstable dependencyTSX
const options = { courseId };

useEffect(() => {
  loadStudents(options);
}, [options]);
◆ Answer

If options is a new object on each render, its reference changes. The effect may rerun even when courseId is unchanged.

A simpler approach is:

Stable dependencyTSX
useEffect(() => {
  loadStudents({ courseId });
}, [courseId]);

This assumes loadStudents is safely referenced within the effect or is otherwise stable. If it is a reactive value defined in the component, handle its dependency correctly rather than suppressing dependency checks.

Question 4 — Why is this authorization check unsafe?

✕ Frontend-only checkTSX
if (user.role === "admin") {
  await fetch("/api/admin/books/release", {
    method: "POST",
  });
}
▲ Answer

The check only restricts normal UI behavior. A user can call the API independently.

The backend must verify the session and administrator permission on every protected request.

Question 5 — Why is this API request dangerous?

✕ Token in localStorageTSX
const token = localStorage.getItem("token");

await fetch("/api/profile", {
  headers: {
    Authorization: `Bearer ${token}`,
  },
});
▲ Answer

The code is not automatically vulnerable simply because it sends a bearer token, but storing sensitive authentication tokens in JavaScript-readable browser storage increases their exposure if XSS occurs.

The correct design depends on your authentication architecture. Consider an appropriate secure session-cookie or BFF-based design where suitable, and avoid assuming that localStorage protects credentials.

Explain Hooks, Rendering, State and Performance

A revision checkpoint for the most important concepts from the React roadmap.

This is a revision checkpoint for the most important concepts from the React roadmap.

Analogy · The system map
Being able to explain Hooks, rendering, state, and performance is like reading the system map. You know where each part lives, how the pieces connect, and where the bottlenecks are likely to appear. The interview tests the map, not the destination.

10.1 Explain React Hooks

A Hook lets a function component use React features or reuse stateful logic.

For example:

useStateTSX
const [count, setCount] = useState(0);

This state persists across renders of the component.

useRefTSX
const inputRef = useRef<HTMLInputElement | null>(null);

This ref persists a mutable reference without triggering a render when .current changes.

useMemoTSX
const filteredStudents = useMemo(() => {
  return filterStudents(students, query);
}, [students, query]);

This memoizes a calculation while its dependencies remain unchanged.

You should be able to explain the purpose of each Hook, when to use it, and its limitations.

10.2 Explain rendering

React rendering is the process of calculating the UI from a component's current props, state, and context.

A render does not necessarily change the DOM. React compares the new result with the previous output and commits the required changes.

In an interview, explain why:

  • A parent update may cause child components to render.
  • Context changes can cause consumers to render.
  • Rendering should be pure.
  • Memoization can reduce some work but is not needed everywhere.

10.3 Explain state management

State represents the information React must remember across renders because it changes over time.

For example:

Selected stateTSX
const [selectedStudentId, setSelectedStudentId] =
  useState<string | null>(null);

Do not store duplicate derived values without a reason.

If your application needs to display the number of selected students:

Derived valueTSX
const selectedCount = selectedStudents.length;

The count is derived from the array rather than maintained as separate state that could become inconsistent.

You should know when to use local state, context, reducers, Redux Toolkit, or a server-state library based on the problem's complexity and sharing requirements.

10.4 Explain performance optimization

Use an evidence-based sequence:

  1. Identify the slow interaction.
  2. Measure the relevant work.
  3. Find the underlying bottleneck.
  4. Choose an appropriate optimization.
  5. Test correctness.
  6. Measure again.

The optimization might be state localization, reduced computation, memoization, virtualization, pagination, image optimization, or code splitting. Each technique solves a different problem.

Analogy · The fork in the road
Every architecture decision is a fork in the road. Neither path is wrong — but you must know why you chose the one you did, and what you would have to give up to take the other.

11.1 Compare common architecture choices

DecisionPrefer this when...Watch out for...

useReducer vs multiple state settersState transitions have related logic or many actionsReducers can be excessive for tiny components

11.2 Real-life scenario: Should you use Redux?

Imagine a dashboard with three filters and one modal.

A component with useState may be enough.

Now imagine an LMS where student records, course enrollment, assignments, notifications, and admin actions share complex client-side state across many parts of the application.

A state-management library may provide better organization and debugging capabilities.

There is no universal rule that every professional React app needs Redux. Your decision should reflect the actual state-sharing and workflow requirements.

11.3 Real-life scenario: Should you use Next.js?

Imagine an internal dashboard used by authenticated employees that consumes an existing backend API.

React + Vite may be sufficient.

If the same product also needs public course pages, server rendering, server-side data access, framework-level routing, and streaming, Next.js may provide useful built-in features.

Neither option is always superior. Evaluate the requirements and operational trade-offs.

Suggested frontend architecture

src/ ├── app/ │ ├── App.tsx │ ├── router.tsx │ └── providers.tsx ├── features/ │ ├── auth/ │ ├── students/ │ ├── courses/ │ ├── books/ │ ├── attendance/ │ └── analytics/ ├── shared/ │ ├── components/ │ ├── hooks/ │ └── utilities/ ├── api/ ├── types/ └── styles/

This is an example structure, not a requirement to use every folder. Organize around actual features and maintain clear dependencies.

Final acceptance criteria

  • Components have clear responsibilities and typed APIs.
  • State is placed intentionally and derived data is not duplicated unnecessarily.
  • Search and filtering behave correctly.
  • API requests handle success, loading, errors, and empty responses.
  • Protected operations are authorized by the backend.
  • Inputs and dialogs are keyboard accessible.
  • Unit and component tests cover core workflows.
  • At least one critical end-to-end workflow is automated.
  • Performance optimizations are based on measurements.
  • The application builds and deploys successfully.
  • The README documents setup, architecture, and known limitations.
  • You can explain the trade-offs behind the important technical decisions.

Final React Interview Preparation Plan

What to be able to explain — clearly, with examples, without notes.

React fundamentals

Be able to explain props, state, conditional rendering, list keys, component composition, controlled inputs, forms, and effects.

Hooks and state management

Understand useState, useEffect, useRef, useContext, useReducer, useMemo, useCallback, transitions, and when shared state needs a dedicated store.

TypeScript

Be able to type props, events, state, children, generic components, API responses, and discriminated unions. Understand why types do not replace runtime validation.

Routing and architecture

Explain route layouts, dynamic routes, feature boundaries, Context, reducers, dependency injection, and the trade-offs between a standalone React SPA and a React framework such as Next.js.

Performance and accessibility

Explain profiling, memoization, virtualization, code splitting, Web Vitals, semantic HTML, keyboard navigation, ARIA, and focus management.

Testing and production readiness

Understand component tests, E2E testing, API mocking, error reporting, environment configuration, secure sessions, CI checks, deployment, and production debugging.
