Topic 01

fetch and Axios Integration

Talking to a backend — the fundamentals of HTTP in React.

1.1 What is an API?

API stands for Application Programming Interface.

In frontend development, an API commonly allows a React application to communicate with a backend server and exchange data.

For example, an LMS may need to retrieve students, courses, trainers, attendance records, and assignments.

React builds the interface, while the API provides a way to communicate with the backend.

1.2 Analogy: A Restaurant

Imagine ordering food at a restaurant.

  1. You choose a dish.
  2. You place your order with the waiter.
  3. The waiter communicates with the kitchen.
  4. The kitchen prepares the dish.
  5. The waiter brings the dish to you.

A typical web request works similarly:

RestaurantWeb application
CustomerWebsite user
MenuFrontend interface
WaiterAPI request
KitchenBackend server
Prepared foodAPI response
Customer receives foodReact displays data

1.3 What is an HTTP request?

An HTTP request asks a server to perform an operation or return information.

For example:

requestHTTP
GET https://jsonplaceholder.typicode.com/users

This requests a list of users from JSONPlaceholder, a public demonstration API.

A response might contain:

response.jsonJSON
[
  {
    "id": 1,
    "name": "Leanne Graham",
    "email": "leanne@example.com"
  },
  {
    "id": 2,
    "name": "Ervin Howell",
    "email": "ervin@example.com"
  }
]

This is JSON, a common format for transferring structured information between applications.

1.4 What is fetch?

fetch is a browser API that allows JavaScript to make HTTP requests.

It returns a Promise that resolves to a Response object. You can check the status of that response and then read its body.

getUsers.jsJavaScript
async function getUsers() {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/users"
  );

  if (!response.ok) {
    throw new Error("Failed to fetch users");
  }

  return response.json();
}

Explanation:

  • fetch() sends the request.
  • await waits for the response.
  • response.ok checks whether the HTTP status represents success.
  • response.json() parses the response body into JavaScript data.
▲ Important

fetch does not automatically throw when the server responds with an HTTP error status such as 404 or 500. You generally need to check response.ok.

1.5 What is Axios?

Axios is a Promise-based HTTP client that simplifies common HTTP operations.

Install it inside your Vite project:

terminalBash
npm install axios

Use it:

getUsers.jsJavaScript
import axios from "axios";

async function getUsers() {
  const response = await axios.get(
    "https://jsonplaceholder.typicode.com/users"
  );

  return response.data;
}

Axios commonly parses JSON responses automatically and exposes the result in response.data. By default, it also rejects responses with unsuccessful HTTP status codes.

1.7 Create a reusable Axios client

Create src/api/client.js:

src/api/client.jsJavaScript
import axios from "axios";

const apiClient = axios.create({
  baseURL: "https://jsonplaceholder.typicode.com",
  timeout: 10000,
  headers: {
    Accept: "application/json"
  }
});

Now you can write:

getUsers.jsJavaScript
import apiClient from "./client.js";

async function getUsers() {
  const response = await apiClient.get("/users");

  return response.data;
}

Instead of repeating the full URL, you can use endpoint paths such as /users, /posts, and /todos.

Topic 02

GET, POST, PUT, PATCH and DELETE

The five core HTTP verbs — what each one means and when to use it.

HTTP methods describe the operation a client is requesting.

2.1 GET — Retrieve information

GET requests retrieve information from a server.

Examples include retrieving a course list or fetching details for a particular student.

getCourses.jsJavaScript
async function getCourses() {
  const response = await fetch("/api/courses");

  if (!response.ok) {
    throw new Error("Unable to load courses");
  }

  return response.json();
}

The endpoint /api/courses is an example. Your backend must implement it.

Axios equivalent:

getCourses.jsJavaScript
async function getCourses() {
  const response = await apiClient.get("/courses");

  return response.data;
}

2.2 POST — Create or submit data

POST is commonly used to create resources or submit information for processing.

createCourse.jsJavaScript
async function createCourse(course) {
  const response = await fetch("/api/courses", {
    method: "POST",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify(course)
  });

  if (!response.ok) {
    throw new Error("Unable to create course");
  }

  return response.json();
}

Call the function:

callJavaScript
createCourse({
  title: "React Fundamentals",
  duration: 8
});

JSON.stringify() converts a JavaScript object into JSON text for the request body.

Axios equivalent:

axios postJavaScript
const response = await apiClient.post("/courses", {
  title: "React Fundamentals",
  duration: 8
});

2.3 PUT — Replace a resource

PUT generally expresses replacement of a resource representation.

replaceCourse.jsJavaScript
async function replaceCourse(id, course) {
  const response = await fetch(`/api/courses/${id}`, {
    method: "PUT",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify(course)
  });

  if (!response.ok) {
    throw new Error("Unable to update course");
  }

  return response.json();
}

The exact behavior for omitted fields depends on your API's contract. Follow your backend documentation to determine the required fields.

2.4 PATCH — Partially update a resource

PATCH is commonly used to update selected properties.

For example, you may want to change a course's duration without sending all the other course details.

updateCourse.jsJavaScript
async function updateCourse(id, updates) {
  const response = await fetch(`/api/courses/${id}`, {
    method: "PATCH",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify(updates)
  });

  if (!response.ok) {
    throw new Error("Unable to update course");
  }

  return response.json();
}

Example:

callJavaScript
updateCourse(10, {
  duration: 12
});

The API must support this partial-update format.

2.5 DELETE — Remove a resource

deleteCourse.jsJavaScript
async function deleteCourse(id) {
  const response = await fetch(`/api/courses/${id}`, {
    method: "DELETE"
  });

  if (!response.ok) {
    throw new Error("Unable to delete course");
  }
}

Axios equivalent:

axios deleteJavaScript
await apiClient.delete("/courses/10");

A successful DELETE request can return an empty response body. Do not assume every response can be parsed as JSON.

2.6 HTTP methods summary

GETRetrieve data

These are common conventions. The backend determines which operations and request formats are supported.

Topic 03

Promises and async/await in Components

Writing asynchronous logic correctly inside React.

3.1 What is asynchronous JavaScript?

Some operations take time to complete.

Examples include requesting data from a server, uploading a file, and communicating with a remote service.

JavaScript uses asynchronous APIs and Promises so that other work can continue while these operations are pending.

3.2 What is a Promise?

A Promise represents the eventual result of an asynchronous operation.

It can be:

  • Pending: the result is not available yet.
  • Fulfilled: the operation succeeded.
  • Rejected: the operation failed.

Example:

promise chainJavaScript
fetch("/api/courses")
  .then(response => {
    if (!response.ok) {
      throw new Error("Request failed");
    }

    return response.json();
  })
  .then(courses => console.log(courses))
  .catch(error => console.error(error));

Each .then() handles a successful result from the preceding Promise. .catch() handles a rejection or a thrown error in the chain.

3.3 What is async/await?

async/await offers a more sequential way to write asynchronous logic.

async/awaitJavaScript
async function getCourses() {
  const response = await fetch("/api/courses");

  if (!response.ok) {
    throw new Error("Failed to fetch courses");
  }

  const courses = await response.json();

  return courses;
}
  • async makes the function return a Promise.
  • await waits for a Promise inside the async function.
  • throw propagates a failure to the caller.

The caller should handle errors using try/catch or a Promise rejection handler.

3.4 Should a normal client-side React component be async?

In a typical client-rendered Vite React application, do not write:

✕ Don't do thisJSX
async function CourseList() {
  const courses = await getCourses();

  return <div>{courses.length} courses</div>;
}

A normal client component needs to return React-renderable output synchronously. Instead, perform asynchronous work in an event handler, a suitable Effect, a custom Hook, or a data-fetching library.

Some framework and server-component environments support asynchronous components under different rules.

3.5 Async function inside an Effect

CourseList.jsxJSX
import { useEffect, useState } from "react";

function CourseList() {
  const [courses, setCourses] = useState([]);
  const [error, setError] = useState("");

  useEffect(() => {
    async function loadCourses() {
      const response = await fetch(
        "https://jsonplaceholder.typicode.com/posts"
      );

      if (!response.ok) {
        throw new Error("Failed to fetch courses");
      }

      const data = await response.json();

      setCourses(data);
    }

    loadCourses().catch(err => setError(err.message));
  }, []);

  if (error) return <p>Error: {error}</p>;

  return (
    <ul>
      {courses.map(course => (
        <li key={course.id}>{course.title}</li>
      ))}
    </ul>
  );
}

The asynchronous function is declared inside the Effect and called from there.

The Effect setup itself should not be declared async, because React expects it to return nothing or a cleanup function, not a Promise.

For robust applications, add loading state, cancellation, and protection against stale responses.

3.6 Async event handlers

Sometimes the request should happen only after a user action.

handlerJSX
async function handleRefresh() {
  try {
    const response = await fetch("/api/courses");

    if (!response.ok) {
      throw new Error("Unable to refresh courses");
    }

    const data = await response.json();

    setCourses(data);
    setError("");
  } catch (error) {
    setError(error.message);
  }
}

Connect it to a button:

JSXJSX
<button onClick={handleRefresh}>
  Refresh Courses
</button>

This is appropriate when the action is specifically caused by a click.

Topic 04

Loading, Success, Empty and Error States

Telling the user what is really happening during a request.

4.1 What are request states?

Asynchronous operations take time and can fail. The application should explain what is happening instead of leaving the user with a blank screen.

Four common situations are:

  1. Loading.
  2. Successful response containing data.
  3. Successful response containing no data.
  4. Error.

4.2 Example with React state

UserList.jsxJSX
import { useEffect, useState } from "react";

function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    const controller = new AbortController();

    async function loadUsers() {
      setLoading(true);
      setError("");

      try {
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/users",
          { signal: controller.signal }
        );

        if (!response.ok) {
          throw new Error("Could not load users");
        }

        const data = await response.json();

        setUsers(data);
      } catch (err) {
        if (err.name !== "AbortError") {
          setError(err.message);
        }
      } finally {
        if (!controller.signal.aborted) {
          setLoading(false);
        }
      }
    }

    loadUsers();

    return () => controller.abort();
  }, []);

  if (loading) return <p>Loading users...</p>;

  if (error) return <p>Error: {error}</p>;

  if (users.length === 0) return <p>No users found.</p>;

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}

4.3 Why are empty and error states different?

An empty result is not the same as a failed request.

For instance:

  • Empty: the API returned a valid empty list.
  • Error: the request failed, the server returned an unsuccessful status, or the response could not be processed.

Provide a specific message for each situation.

With Tailwind CSS, these states can be visually clear:

states.jsxJSX
{loading && (
  <div className="rounded-lg bg-slate-100 p-4 text-slate-600">
    Loading users...
  </div>
)}

{error && (
  <div role="alert" className="rounded-lg bg-red-50 p-4 text-red-700">
    {error}
  </div>
)}
Topic 05

useEffect Data-Fetching Patterns

Fetching reliably when the request depends on reactive inputs.

5.1 The common pattern

A direct data-fetching Effect typically:

  1. Renders the initial interface.
  2. Starts the request after the commit.
  3. Saves successful data in state.
  4. Updates loading or error state.
  5. Renders the updated UI.
  6. Cleans up obsolete work when necessary.

5.2 Fetch when a parameter changes

Suppose a component shows details for a selected student.

dependencyJSX
useEffect(() => {
  // Load data for this studentId.
}, [studentId]);

When studentId changes, the Effect must synchronize with the new selected student.

A dependency array should include the reactive values that are used by the Effect.

5.3 Separate API functions from components

Create src/api/users.js:

src/api/users.jsJavaScript
export async function fetchUsers(signal) {
  const response = await fetch(
    "https://jsonplaceholder.typicode.com/users",
    { signal }
  );

  if (!response.ok) {
    throw new Error("Failed to fetch users");
  }

  return response.json();
}

Your component can now import fetchUsers, keeping the request logic outside the presentation.

5.4 When is an Effect appropriate?

An Effect is useful when the request needs to synchronize with a component's reactive inputs or lifecycle.

However, manually fetching inside Effects requires you to manage caching, deduplication, race conditions, and other concerns.

For applications with many API interactions, consider a data-fetching library such as TanStack Query.

Reference: React — useEffect.

Topic 06

Request Cancellation and AbortController

Stopping work that is no longer needed.

6.1 What is cancellation?

Request cancellation stops or interrupts work that is no longer needed.

For example, when the user navigates away from a screen before its API request finishes, cancelling the request can prevent unnecessary work.

6.2 Basic syntax

abortJavaScript
const controller = new AbortController();

fetch("/api/courses", {
  signal: controller.signal
});

// Cancel the request.
controller.abort();

6.3 Use cancellation in an Effect

effectJSX
useEffect(() => {
  const controller = new AbortController();

  async function loadCourses() {
    try {
      const response = await fetch("/api/courses", {
        signal: controller.signal
      });

      if (!response.ok) {
        throw new Error("Failed to load courses");
      }

      setCourses(await response.json());
    } catch (error) {
      if (error.name !== "AbortError") {
        setError(error.message);
      }
    }
  }

  loadCourses();

  return () => controller.abort();
}, []);

The cleanup cancels the fetch associated with the Effect.

Axios also supports AbortController:

axios abortJavaScript
const controller = new AbortController();

const response = await apiClient.get("/users", {
  signal: controller.signal
});

// Cancel when the request is no longer needed.
controller.abort();

References: MDN — AbortController, Axios — Cancellation.

Topic 07

Handling Stale Responses and Race Conditions

Preventing old requests from overwriting newer data.

7.1 What is a race condition?

Imagine the user searches for Rahul and immediately changes the search to Priya.

Two requests may start:

  1. Request Rahul.
  2. Request Priya.

If the Priya response arrives first and the Rahul response arrives later, the older response must not overwrite the newer result.

That is a race-condition problem.

7.2 Ignore stale results

React documents a straightforward pattern using a local flag.

StudentDetails.jsxJSX
import { useEffect, useState } from "react";

function StudentDetails({ studentId }) {
  const [student, setStudent] = useState(null);
  const [error, setError] = useState("");

  useEffect(() => {
    let ignore = false;

    async function loadStudent() {
      setStudent(null);
      setError("");

      try {
        const response = await fetch(
          `https://jsonplaceholder.typicode.com/users/${studentId}`
        );

        if (!response.ok) {
          throw new Error("Failed to load student");
        }

        const data = await response.json();

        if (!ignore) {
          setStudent(data);
        }
      } catch (err) {
        if (!ignore) {
          setError(err.message);
        }
      }
    }

    loadStudent();

    return () => {
      ignore = true;
    };
  }, [studentId]);

  if (error) return <p role="alert">{error}</p>;

  if (!student) return <p>Loading student...</p>;

  return <h2>{student.name}</h2>;
}

When the dependency changes, the previous cleanup marks its request result as obsolete. The older response cannot update the state.

7.3 Cancellation vs. stale-response protection

Cancellation asks the operation to stop.

Stale-response protection prevents an obsolete result from being applied.

Both approaches may be useful. Some asynchronous operations cannot be cancelled completely, so it is important to consider whether the eventual result is still relevant.

With TanStack Query, use query keys that include the request parameters, and use the query function's supplied signal where cancellation is appropriate.

Topic 08

Environment Variables in Vite

Configuring the app without hardcoding URLs — and without leaking secrets.

8.1 What are environment variables?

Environment variables let you configure settings separately from your source code.

Examples include an API base URL and a public application identifier.

8.2 Create .env

At the root of your Vite project:

.envENV
VITE_API_BASE_URL=https://jsonplaceholder.typicode.com
VITE_APP_TITLE=React API Dashboard

The VITE_ prefix makes custom variables available to client-side code.

8.3 Read the variable

read envJavaScript
const apiBaseUrl = import.meta.env.VITE_API_BASE_URL;

Create an Axios client:

client.jsJavaScript
import axios from "axios";

const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000
});

export default apiClient;

8.4 Development and production

Vite supports mode-specific files, such as .env.development and .env.production.

Development:

.env.developmentENV
VITE_API_BASE_URL=http://localhost:5000/api

Production:

.env.productionENV
VITE_API_BASE_URL=https://api.example.com

Replace the example production URL with your real endpoint.

Restart the development server if environment-file changes are not reflected.

8.5 Security rule

Anything exposed through VITE_ variables can be included in the public frontend bundle.

▲ Never

Do not put private database passwords, server secrets, private API credentials, or JWT signing keys into client-side environment variables. Keep secrets on the backend.

Topic 09

Pagination and Infinite Scrolling

Dividing large result sets into manageable slices.

9.1 What is pagination?

Pagination divides a large result set into smaller pages.

For example, a student table might display 20 records per page rather than loading thousands of records at once.

9.2 Client-side pagination

If all data is already loaded, you can use slice().

StudentPagination.jsxJSX
import { useState } from "react";

function StudentPagination({ students }) {
  const [page, setPage] = useState(1);

  const pageSize = 5;
  const totalPages = Math.ceil(students.length / pageSize);

  const start = (page - 1) * pageSize;

  const currentStudents = students.slice(
    start,
    start + pageSize
  );

  return (
    <div>
      {currentStudents.map(student => (
        <p key={student.id}>{student.name}</p>
      ))}

      <button
        disabled={page <= 1}
        onClick={() => setPage(current => current - 1)}
      >
        Previous
      </button>

      <span className="mx-3">
        Page {page} of {Math.max(totalPages, 1)}
      </span>

      <button
        disabled={page >= totalPages}
        onClick={() => setPage(current => current + 1)}
      >
        Next
      </button>
    </div>
  );
}

This is client-side pagination.

For a dynamic list, consider resetting or clamping the page if the number of records changes and the current page becomes invalid.

9.3 Server-side pagination

A server-side endpoint may accept:

endpointHTTP
GET /api/students?page=2&limit=20

The server returns the requested subset and perhaps metadata, such as the total number of records.

Server-side pagination is usually better when the dataset is too large to load in its entirety.

9.4 What is infinite scrolling?

Infinite scrolling requests additional records as the user reaches the end of the current list.

Instead of replacing the existing records, the application appends subsequent pages.

TanStack Query provides useInfiniteQuery for this pattern. It exposes data.pages, fetchNextPage, and hasNextPage.

Reference: TanStack Query — Infinite Queries.

Topic 10

Search, Sorting and Filtering

Turning raw arrays into useful, interactive views.

10.1 Searching

Searching finds records that match a query.

For example, entering rah may show names containing those letters.

10.2 Filtering

Filtering selects records based on a condition.

Examples include active students, available courses, and completed tasks.

10.3 Sorting

Sorting arranges the records into a specified order, such as alphabetical order or highest price first.

10.4 Complete example

StudentDirectory.jsxJSX
import { useState } from "react";

function StudentDirectory({ students }) {
  const [search, setSearch] = useState("");
  const [status, setStatus] = useState("all");
  const [sortOrder, setSortOrder] = useState("asc");

  const visibleStudents = students
    .filter(student =>
      student.name.toLowerCase().includes(search.toLowerCase())
    )
    .filter(student => {
      if (status === "active") return student.active;
      if (status === "inactive") return !student.active;
      return true;
    })
    .slice()
    .sort((a, b) => {
      const result = a.name.localeCompare(b.name);
      return sortOrder === "asc" ? result : -result;
    });

  return (
    <section className="space-y-4">
      <input
        className="w-full rounded-lg border border-slate-300 p-3"
        value={search}
        onChange={event => setSearch(event.target.value)}
        placeholder="Search students"
      />

      <select
        className="rounded-lg border p-2"
        value={status}
        onChange={event => setStatus(event.target.value)}
      >
        <option value="all">All students</option>
        <option value="active">Active students</option>
        <option value="inactive">Inactive students</option>
      </select>

      <select
        className="rounded-lg border p-2"
        value={sortOrder}
        onChange={event => setSortOrder(event.target.value)}
      >
        <option value="asc">Name A–Z</option>
        <option value="desc">Name Z–A</option>
      </select>

      {visibleStudents.map(student => (
        <article
          key={student.id}
          className="rounded-lg border border-slate-200 p-4"
        >
          <h2 className="font-semibold">{student.name}</h2>
          <p className="text-sm text-slate-500">
            {student.active ? "Active" : "Inactive"}
          </p>
        </article>
      ))}

      {visibleStudents.length === 0 && (
        <p className="text-slate-500">
          No students match your search.
        </p>
      )}
    </section>
  );
}

This example combines search, filtering, and sorting. It calculates the visible list during rendering rather than storing another copy of the filtered data.

For a large server-side dataset, put the filters and sort parameters into the API request instead.

Topic 11

Debouncing Search Inputs

Waiting for a pause in typing before doing work.

11.1 What is debouncing?

Debouncing delays an operation until a period of time has passed without a new triggering event.

Without debouncing, typing react could trigger five requests: r, re, rea, reac, and react.

Debouncing can wait for a pause in typing before starting the search.

11.2 Create a debounced value

SearchBox.jsxJSX
import { useEffect, useState } from "react";

function SearchBox() {
  const [search, setSearch] = useState("");
  const [debouncedSearch, setDebouncedSearch] = useState("");

  useEffect(() => {
    const timerId = setTimeout(() => {
      setDebouncedSearch(search.trim());
    }, 300);

    return () => clearTimeout(timerId);
  }, [search]);

  return (
    <div>
      <input
        className="rounded-lg border p-3"
        value={search}
        onChange={event => setSearch(event.target.value)}
        placeholder="Search courses"
      />

      <p>Search after typing pauses: {debouncedSearch}</p>
    </div>
  );
}

How it works

  1. The user types something.
  2. React updates the immediate input value.
  3. An Effect starts a timer.
  4. If the user types again, cleanup clears the timer.
  5. After 300 milliseconds without another change, the debounced value updates.

11.3 Use the debounced term for an API query

queryJSX
const query = useQuery({
  queryKey: ["users", { search: debouncedSearch }],
  queryFn: () => fetchUsers({ search: debouncedSearch })
});

The query is associated with the debounced term.

Debouncing reduces how often work is initiated, but you still need appropriate error handling and stale-response protection.

12.5 Use useQuery

Users.jsxJSX
import { useQuery } from "@tanstack/react-query";

function Users() {
  const {
    data: users = [],
    isPending,
    isError,
    error,
    refetch
  } = useQuery({
    queryKey: ["users"],
    queryFn: fetchUsers
  });

  if (isPending) return <p>Loading users...</p>;

  if (isError) {
    return (
      <div>
        <p>{error.message}</p>
        <button onClick={() => refetch()}>Retry</button>
      </div>
    );
  }

  if (users.length === 0) return <p>No users found.</p>;

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}

Important concepts

queryKey identifies the dataset.

queryFn defines how the data is fetched.

isPending represents a query that does not yet have successful data.

isError indicates that the request encountered an error.

refetch can explicitly request the data again.

keyJavaScript

12.7 What is a mutation?

A mutation represents a server-changing operation, such as creating a student, updating a course, or deleting a task.

Use useQuery primarily to retrieve server data and useMutation for operations that change server data.

CreateStudent.jsxJSX
import {
  useMutation,
  useQueryClient
} from "@tanstack/react-query";

function CreateStudent() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: async student => {
      const response = await apiClient.post("/students", student);
      return response.data;
    },

    onSuccess: async () => {
      await queryClient.invalidateQueries({
        queryKey: ["students"]
      });
    }
  });

  function handleCreate() {
    mutation.mutate({
      name: "Rahul",
      email: "rahul@example.com"
    });
  }

  return (
    <div>
      <button
        onClick={handleCreate}
        disabled={mutation.isPending}
        className="rounded-lg bg-blue-600 px-4 py-2 text-white disabled:opacity-50"
      >
        {mutation.isPending ? "Creating..." : "Create Student"}
      </button>

      {mutation.isError && (
        <p role="alert">{mutation.error.message}</p>
      )}

      {mutation.isSuccess && <p>Request succeeded.</p>}
    </div>
  );
}

This code assumes the backend implements POST /students.

12.8 How does mutation invalidation work?

After creating a student, the existing student list may be outdated.

This code marks the relevant query data as stale:

invalidateJavaScript
queryClient.invalidateQueries({
  queryKey: ["students"]
});

Active matching queries may then refetch automatically.

This avoids manually updating every cached list in every component.

Topic 13

Caching, Invalidation and Refetching

Keeping cached server data fresh and consistent.

13.1 What is caching?

Caching retains previously fetched data so it can be reused without necessarily sending a new request immediately.

For example, if a course list is already cached, an application may be able to show that data immediately on a subsequent visit.

13.2 What is invalidation?

Invalidation marks cached data as stale so the application knows that it may need to fetch newer information.

For example:

  1. Fetch the student list.
  2. Create a new student.
  3. Mark student-related queries as stale.
  4. Refetch active queries when appropriate.
  5. Display updated results.

13.3 What is refetching?

Refetching requests data again.

You can explicitly refetch a query:

refetchJSX
const { refetch } = useQuery({
  queryKey: ["students"],
  queryFn: fetchStudents
});

<button onClick={() => refetch()}>
  Refresh Students
</button>

TanStack Query can also refetch based on invalidation, configured lifecycle behavior, and other conditions.

13.4 staleTime

staleTime specifies how long a cached query result is considered fresh.

staleTimeJSX
useQuery({
  queryKey: ["students"],
  queryFn: fetchStudents,
  staleTime: 60_000
});

This sets one minute as the freshness duration.

13.5 gcTime

gcTime controls how long inactive cached data remains in memory before garbage collection.

gcTimeJSX
useQuery({
  queryKey: ["students"],
  queryFn: fetchStudents,
  staleTime: 60_000,
  gcTime: 300_000
});

This sets a one-minute freshness duration and a five-minute inactive-cache retention duration.

They solve different problems:

  • staleTime: when data becomes stale.
  • gcTime: how long unused cached data is retained.

function App() {
  const [search, setSearch] = useState("");
  const [sortOrder, setSortOrder] = useState("asc");
  const [page, setPage] = useState(1);

  const pageSize = 6;

  const {
    data: users = [],
    isPending,
    isError,
    error,
    isFetching,
    refetch
  } = useQuery({
    queryKey: ["users"],
    queryFn: ({ signal }) => fetchUsers({ signal }),
    staleTime: 60_000
  });

  const filteredUsers = useMemo(() => {
    return users
      .filter(user =>
        `${user.name} ${user.email} ${user.company.name}`
          .toLowerCase()
          .includes(search.toLowerCase().trim())
      )
      .slice()
      .sort((a, b) => {
        const result = a.name.localeCompare(b.name);

        return sortOrder === "asc" ? result : -result;

  const totalPages = Math.ceil(filteredUsers.length / pageSize);
  const safePage = Math.min(page, Math.max(totalPages, 1));

          >
            Try Again

        </div>
      </main>
    );
  }

  return (
    <main className="min-h-screen bg-slate-50 p-4 sm:p-8">
      <div className="mx-auto max-w-7xl">
        <header className="mb-8 flex flex-col gap-4 sm:flex-row sm:items-center sm:justify-between">

              User Directory
            </h1>

            <p className="mt-2 text-slate-600">
              Search and explore user information.
            </p>
          </div>

          <button

            {isFetching ? "Refreshing..." : "Refresh Users"}
          </button>
        </header>

        <section className="mb-6 grid gap-4 rounded-2xl border border-slate-200 bg-white p-4 sm:grid-cols-2 sm:p-6">

}

Common Beginner Mistakes

Nine pitfalls every API + Tailwind developer runs into — and how to fix them.

1. Forgetting to check response.ok

fetch can resolve successfully at the Promise level even when the HTTP status indicates failure. Check the status before parsing the response.

2. Treating fetch and Axios responses identically

With fetch, you typically use response.json(). With Axios, parsed response data is usually available as response.data.

3. Forgetting request cancellation

An obsolete request can finish after a component has stopped needing it. Consider cancellation and stale-result protection where appropriate.

4. Putting private credentials in VITE_ variables

Anything exposed to the browser must be treated as public configuration. Keep sensitive secrets on the server.

5. Using effects for every data calculation

Values such as filtered lists, totals, and derived labels can usually be calculated during rendering.

6. Forgetting to include changing parameters in query keys

If a query depends on search, page, or studentId, include those values in the query key. Otherwise, different requested datasets can be mixed up.

7. Mixing Tailwind CSS v3 and v4 setup instructions

For a new v4 Vite project, use @tailwindcss/vite and @import "tailwindcss";. Use the v3 configuration when maintaining an existing v3 application.

8. Building Tailwind classes dynamically without complete class strings

Tailwind may not detect classes assembled from partial strings. Prefer complete class names or explicit mappings.

9. Treating all Tailwind breakpoint prefixes as maximum widths

By default, md: applies at the medium breakpoint and above. Use maximum-width variants when you need to target a range.
