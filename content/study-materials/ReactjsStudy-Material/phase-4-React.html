Topic 01

Form Submission and preventDefault()

Collecting information from users — the right way in React.

1.1 What Is a Form in React?

A form is a part of an interface that collects information from a user.

Examples include:

  • Login forms
  • Student registration forms
  • Course admission forms
  • Contact forms
  • Feedback forms
  • Job application forms
  • File upload forms

A React form typically contains HTML elements such as input, select, textarea, and button.

React lets you handle form submissions using event handlers and manage the form's data using state or browser APIs.

1.2 Why Do We Need Form Handling?

Imagine a student registration form that asks for:

  • Student name
  • Email address
  • Course selection
  • Learning mode

When the student clicks Submit, your application should collect the information, validate it, and either show an error or process the submitted data.

React lets you control this process instead of simply allowing the browser to navigate away from the page.

1.3 Analogy: An Admission Form at an Institute

Imagine that a student fills out a physical admission form.

  1. The student enters personal information.
  2. The student selects a course.
  3. The student submits the form.
  4. The institute checks that the information is valid.
  5. The application is accepted or the student is asked to correct missing information.

A web form follows a similar process. The main difference is that JavaScript can manage the submitted data and update the interface without a full page reload.

1.4 Your First React Form

StudentForm.jsxJSX
function StudentForm() {
  function handleSubmit(event) {
    event.preventDefault();

    alert("Form submitted successfully!");
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="studentName">
        Student Name
      </label>

      <input
        id="studentName"
        name="studentName"
        type="text"
      />

      <button type="submit">
        Submit
      </button>
    </form>
  );
}

export default StudentForm;

Code Explanation

Step 1: Create a submit handler

handlerJSX
function handleSubmit(event) {
  event.preventDefault();

  alert("Form submitted successfully!");
}

The handler receives the submission event.

Step 2: Prevent the default behavior

preventDefaultJSX
event.preventDefault();

A normal browser form submission can navigate to a URL or reload the current page, depending on its configuration.

preventDefault() prevents that default submission behavior so your JavaScript can handle the submission.

It does not automatically validate, save, or upload the submitted information.

Step 3: Connect the handler

onSubmitJSX
<form onSubmit={handleSubmit}>

React calls the handler when the form is submitted.

Step 4: Use a submit button

submitJSX
<button type="submit">Submit</button>

Clicking this button submits the form.

Pressing Enter in an appropriate form field may also submit the form.

1.5 Why Should You Use onSubmit Instead of Only onClick?

Consider this:

onClick onlyJSX
<button onClick={handleSubmit}>Submit</button>

This responds to a click on the button. However, it does not represent the entire form submission event.

A better approach is:

onSubmitJSX
<form onSubmit={handleSubmit}>
  <input name="email" type="email" />

  <button type="submit">Submit</button>
</form>

Using onSubmit supports submission through the form itself, including appropriate keyboard-based submission.

It also allows browser-native form validation to participate in submission.

▲ Important

A <button> inside a form submits the form by default if you omit its type. Use type="button" for buttons that should perform another action without submitting the form.

1.6 Read Submitted Data with FormData

You do not always need a separate state variable for every field.

The browser provides a FormData API that can read values from named form controls.

StudentForm.jsxJSX
function StudentForm() {
  function handleSubmit(event) {
    event.preventDefault();

    const formData = new FormData(event.currentTarget);

    const name = formData.get("studentName");
    const email = formData.get("email");

    console.log({ name, email });
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="studentName">Name</label>
      <input id="studentName" name="studentName" required />

      <label htmlFor="email">Email</label>
      <input id="email" name="email" type="email" required />

      <button type="submit">Submit</button>
    </form>
  );
}

Explanation

createJSX
const formData = new FormData(event.currentTarget);

This creates a FormData object from the form that was submitted.

readJSX
formData.get("studentName");

This retrieves the form value associated with the studentName field.

The name attribute is important because it identifies a field in form submission data.

When several controls use the same name, such as checkboxes representing multiple selected options, use formData.getAll("fieldName") to retrieve all submitted values for that name.

1.7 Preventing Submission of Invalid Data

You can combine submission handling with validation:

LoginForm.jsxJSX
function LoginForm() {
  function handleSubmit(event) {
    event.preventDefault();

    const formData = new FormData(event.currentTarget);
    const email = formData.get("email");

    if (!email) {
      alert("Please enter your email.");
      return;
    }

    alert("Ready to continue!");
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="email">Email</label>
      <input id="email" name="email" type="email" required />

      <button type="submit">Continue</button>
    </form>
  );
}

The required attribute enables browser-native validation. If custom JavaScript validation is needed, you can add it inside your handler, as we will do in Topic 4.

◆ Remember

Use the form's onSubmit handler to process submissions. Call event.preventDefault() when you want to prevent the browser's default navigation or reload behavior, and use named controls or controlled state to read form data.

Topic 02

Input, Select, Checkbox and Radio Controls

Choosing the right control — and reading the right property.

Forms contain different types of controls, and each type can represent a different kind of information.

React follows the usual HTML control model, but some controls need different props depending on whether they are controlled.

2.1 Text Inputs

A text input collects short text, such as a name or username.

NameInput.jsxJSX
function NameInput() {
  return (
    <div>
      <label htmlFor="name">Full Name</label>
      <input
        id="name"
        name="name"
        type="text"
        placeholder="Enter your name"
      />
    </div>
  );
}

The important attributes are:

  • id: identifies the element.
  • name: identifies the field in submitted form data.
  • type: defines the type of input.
  • placeholder: provides an example or hint.

A placeholder does not replace a proper label.

2.2 Controlled Text Input

A controlled input receives its value from React state.

NameInput.jsx — controlledJSX
import { useState } from "react";

function NameInput() {
  const [name, setName] = useState("");

  return (
    <div>
      <label htmlFor="name">Full Name</label>

      <input
        id="name"
        name="name"
        value={name}
        onChange={event => setName(event.target.value)}
      />

      <p>Your name: {name}</p>
    </div>
  );
}

Here, the input displays the value of name.

When a user types, onChange calls setName, and React renders the updated value.

A controlled text input should normally receive a string value throughout its lifetime. Initialize it with "" rather than undefined or null.

2.3 Select Dropdown

A dropdown allows a user to choose one option from several choices.

CourseSelect.jsxJSX
import { useState } from "react";

function CourseSelect() {
  const [course, setCourse] = useState("");

  return (
    <div>
      <label htmlFor="course">Select Course</label>

      <select
        id="course"
        name="course"
        value={course}
        onChange={event => setCourse(event.target.value)}
      >
        <option value="">Choose a course</option>
        <option value="react">React</option>
        <option value="node">Node.js</option>
        <option value="mongodb">MongoDB</option>
      </select>

      <p>Selected course: {course || "None"}</p>
    </div>
  );
}

Explanation

  • value={course} sets the currently selected value.
  • onChange updates the state when the user selects an option.
  • Each option has a value used by the application.
  • The empty option encourages the user to make a selection.

Use a controlled select when the current selection should be reflected in React state.

2.4 Checkbox

A checkbox represents a yes/no choice or an individual selection.

For example, a registration form may ask whether the student agrees to the terms.

TermsCheckbox.jsxJSX
import { useState } from "react";

function TermsCheckbox() {
  const [agreed, setAgreed] = useState(false);

  return (
    <div>
      <label>
        <input
          type="checkbox"
          name="agreed"
          checked={agreed}
          onChange={event => setAgreed(event.target.checked)}
        />
        I agree to the terms and conditions.
      </label>

      <p>{agreed ? "Accepted" : "Not accepted"}</p>
    </div>
  );
}
▲ Important distinction

For checkboxes, read event.target.checked, not event.target.value, when you need to know whether the checkbox is selected.

In a controlled checkbox, checked is the state-driven prop.

Multiple Checkboxes

Imagine a student can choose several skills.

SkillSelector.jsxJSX
import { useState } from "react";

function SkillSelector() {
  const [skills, setSkills] = useState([]);

  function toggleSkill(skill) {
    setSkills(currentSkills =>
      currentSkills.includes(skill)
        ? currentSkills.filter(item => item !== skill)
        : [...currentSkills, skill]
    );
  }

  return (
    <fieldset>
      <legend>Select Your Skills</legend>

      {["HTML", "CSS", "JavaScript"].map(skill => (
        <label key={skill}>
          <input
            type="checkbox"
            checked={skills.includes(skill)}
            onChange={() => toggleSkill(skill)}
          />
          {skill}
        </label>
      ))}

      <p>Selected: {skills.join(", ") || "None"}</p>
    </fieldset>
  );
}

This example stores selected skills in an array. When a skill is selected, a new array includes it; when deselected, filter() creates an array without it.

2.5 Radio Buttons

Radio buttons allow a user to select one option from a group.

For example, a student may choose online or classroom learning.

LearningMode.jsxJSX
import { useState } from "react";

function LearningMode() {
  const [mode, setMode] = useState("online");

  return (
    <fieldset>
      <legend>Learning Mode</legend>

      <label>
        <input
          type="radio"
          name="mode"
          value="online"
          checked={mode === "online"}
          onChange={event => setMode(event.target.value)}
        />
        Online
      </label>

      <label>
        <input
          type="radio"
          name="mode"
          value="classroom"
          checked={mode === "classroom"}
          onChange={event => setMode(event.target.value)}
        />
        Classroom
      </label>

      <p>Selected mode: {mode}</p>
    </fieldset>
  );
}

Why Do Both Radio Buttons Use the Same name?

The shared name="mode" groups the radio buttons so that only one can be selected at a time by normal browser interaction.

The value of each radio identifies its choice, while the controlled checked prop determines whether that choice is selected.

Text inputs and selects usually use value. Checkboxes and radio buttons use checked when controlled. The event property you read depends on the control.

Topic 03

Controlled Versus Uncontrolled Forms

Choosing where the truth of an input value should live.

3.1 What Is a Controlled Form?

A controlled form uses React state as the source of truth for input values.

For example:

controlledJSX
const [email, setEmail] = useState("");

<input
  value={email}
  onChange={event => setEmail(event.target.value)}
/>

The displayed input value follows React state.

React receives every change through the handler, making the current value available for rendering, validation, and other application logic.

3.2 What Is an Uncontrolled Form?

An uncontrolled input keeps its current value in the DOM rather than being controlled by a React state variable.

Example:

uncontrolledJSX
<input
  name="email"
  type="email"
  defaultValue="student@example.com"
/>

defaultValue specifies the initial value. It does not continuously control the input's current value.

You can read an uncontrolled form's values at submission time using FormData.

3.3 Analogy: A Dashboard Versus a Paper Form

Imagine two ways of handling information.

Controlled approach: A dashboard updates its displayed information each time a value changes. The application knows the current value because it is stored in state.

Uncontrolled approach: The user writes on a form, and the information is collected when the form is submitted. The DOM maintains the current input value until you read it.

Both approaches are useful. Choose based on what the application needs to do with the values.

3.4 Controlled Form Example

LoginForm.jsxJSX
import { useState } from "react";

function LoginForm() {
  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");

  function handleSubmit(event) {
    event.preventDefault();

    console.log({ email, password });
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="email">Email</label>
      <input
        id="email"
        name="email"
        type="email"
        value={email}
        onChange={event => setEmail(event.target.value)}
      />

      <label htmlFor="password">Password</label>
      <input
        id="password"
        name="password"
        type="password"
        value={password}
        onChange={event => setPassword(event.target.value)}
      />

      <button type="submit">Log In</button>
    </form>
  );
}

Advantages

  • The current values are available in React state.
  • You can validate fields as the user interacts with them.
  • You can display conditional content based on field values.
  • You can enable or disable other controls according to the form state.

Disadvantages

  • Each field needs the appropriate state and change handler.
  • Many controlled inputs can make a large form more verbose.
  • If too much of the application depends on each keystroke, rendering performance may need attention.

3.5 Uncontrolled Form Example

ContactForm.jsxJSX
function ContactForm() {
  function handleSubmit(event) {
    event.preventDefault();

    const formData = new FormData(event.currentTarget);

    const name = formData.get("name");
    const email = formData.get("email");

    console.log({ name, email });
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="name">Name</label>
      <input id="name" name="name" defaultValue="" />

      <label htmlFor="email">Email</label>
      <input
        id="email"
        name="email"
        type="email"
        defaultValue=""
      />

      <button type="submit">Submit</button>
    </form>
  );
}

The browser keeps the input values. On submission, FormData collects them.

Advantages

  • Less state-management code for simple forms.
  • Useful when you only need values at submission time.
  • Works naturally with browser form APIs.

Disadvantages

  • The latest field values are not automatically available as React state.
  • Real-time validation and conditional interfaces can require additional DOM access or a different form approach.

3.6 Can You Mix the Two Approaches?

Yes. A form may have controlled text inputs and an uncontrolled file input, for example.

However, an individual input should not switch back and forth between controlled and uncontrolled during its lifetime.

For controlled inputs:

  • Text input: value and onChange.
  • Checkbox and radio: checked and onChange.

For uncontrolled inputs:

  • Text input: optionally defaultValue.
  • Checkbox or radio: optionally defaultChecked.

Do not pass both value and defaultValue to the same input as competing ways of setting its value.

Which Approach Should You Choose?

Choose controlled fields when their values need to affect the UI or validation as the user types.

Choose uncontrolled fields when it is sufficient to collect their values at submission time.

A controlled form is common in interactive React applications, but uncontrolled inputs can be simpler for straightforward data collection.

Topic 04

Form Validation

Helping users provide complete and correct information.

4.1 What Is Form Validation?

Form validation checks whether the submitted data meets the rules required by the application.

Examples:

  • Name must not be empty.
  • Email must have a reasonable email format.
  • Password must meet the application's password requirements.
  • Course must be selected.
  • Terms must be accepted.
  • File size must remain within the permitted limit.

Validation helps users correct incomplete or invalid information before submission.

4.2 Analogy: An Admission Checklist

An institute may require a completed admission form, an eligible course selection, and necessary documents.

If an important field is missing, the form should identify the missing information instead of silently proceeding.

Web form validation follows the same principle.

4.3 Native HTML Validation

HTML has built-in validation attributes.

RegistrationForm.jsxJSX
function RegistrationForm() {
  return (
    <form>
      <label htmlFor="name">Full Name</label>
      <input
        id="name"
        name="name"
        type="text"
        required
        minLength={3}
      />

      <label htmlFor="email">Email</label>
      <input
        id="email"
        name="email"
        type="email"
        required
      />

      <label htmlFor="age">Age</label>
      <input
        id="age"
        name="age"
        type="number"
        min={18}
        max={60}
        required
      />

      <button type="submit">Register</button>
    </form>
  );
}

Explanation:

  • required means the field must be filled in.
  • minLength={3} requires at least three characters for the name.
  • type="email" provides basic email-format checking.
  • min={18} establishes the minimum age.
  • max={60} establishes the maximum age.

React uses camelCase for DOM props such as minLength.

If the data fails these browser constraints, the browser normally prevents submission and displays its validation feedback.

4.4 What Are the Limitations of Native Validation?

Native validation is useful for common input rules, but it is not enough for every application.

For example, you might need to check whether:

  • Two password fields match.
  • A selected course is available.
  • A user has accepted a specific policy.
  • A date is within a business-defined range.
  • An email address is already registered.

These rules often require custom JavaScript and sometimes a server request.

4.5 Custom Validation with React

RegistrationForm.jsxJSX
import { useState } from "react";

function RegistrationForm() {
  const [name, setName] = useState("");
  const [email, setEmail] = useState("");
  const [errors, setErrors] = useState({});
  const [submitted, setSubmitted] = useState(false);

  function handleSubmit(event) {
    event.preventDefault();

    const nextErrors = {};

    if (name.trim().length < 3) {
      nextErrors.name = "Name must contain at least 3 characters.";
    }

    if (!/^\S+@\S+\.\S+$/.test(email)) {
      nextErrors.email = "Enter a valid email address.";
    }

    setErrors(nextErrors);

    if (Object.keys(nextErrors).length > 0) {
      setSubmitted(false);
      return;
    }

    setSubmitted(true);
  }

  return (
    <form onSubmit={handleSubmit} noValidate>
      <label htmlFor="name">Name</label>
      <input
        id="name"
        value={name}
        onChange={event => setName(event.target.value)}
        aria-invalid={Boolean(errors.name)}
        aria-describedby={errors.name ? "name-error" : undefined}
      />

      {errors.name && (
        <p id="name-error" role="alert">
          {errors.name}
        </p>
      )}

      <label htmlFor="email">Email</label>
      <input
        id="email"
        type="email"
        value={email}
        onChange={event => setEmail(event.target.value)}
        aria-invalid={Boolean(errors.email)}
        aria-describedby={errors.email ? "email-error" : undefined}
      />

      {errors.email && (
        <p id="email-error" role="alert">
          {errors.email}
        </p>
      )}

      <button type="submit">Register</button>

      {submitted && <p>Form submitted successfully!</p>}
    </form>
  );
}

Explanation

Step 1: Store the field values

The controlled inputs use name and email state variables.

Step 2: Create an error object

errorsJSX
const nextErrors = {};

This object will contain messages for invalid fields.

Step 3: Validate the name

nameJSX
if (name.trim().length < 3) {
  nextErrors.name = "Name must contain at least 3 characters.";
}

trim() removes leading and trailing whitespace before the length is checked.

Step 4: Validate the email

emailJSX
if (!/^\S+@\S+\.\S+$/.test(email)) {
  nextErrors.email = "Enter a valid email address.";
}

This is a simple example check, not a complete implementation of every valid email format. Real applications should choose validation rules appropriate to their requirements.

Step 5: Stop when errors exist

stopJSX
if (Object.keys(nextErrors).length > 0) {
  setSubmitted(false);
  return;
}

The handler exits if any validation messages were generated.

Step 6: Show success

If validation passes, the component displays the success message.

The noValidate attribute disables the browser's automatic form-validation UI for this form, allowing this example to show its custom messages.

4.6 Client-Side Validation Is Not Security

Client-side validation improves the user experience, but it can be bypassed.

For example, a user might modify browser code or send a request directly to an API.

The backend must independently validate submitted data and enforce security rules. This is particularly important for payments, authentication, uploads, and other sensitive operations.

Reference: MDN — Constraint Validation.

◆ Remember

Use native HTML constraints for basic checks and custom JavaScript validation when the application needs more specific rules. Always validate untrusted data on the server as well.

Topic 05

Dynamic Form Fields

Letting the form grow with the user's needs.

5.1 What Are Dynamic Form Fields?

Dynamic form fields are inputs that can be added, removed, or changed while the application is running.

Examples include:

  • Adding multiple skills to a student profile.
  • Adding guardian contact details.
  • Adding multiple education records.
  • Adding product items to an invoice.
  • Adding several work-experience entries to a job application.

5.2 Why Do We Need Dynamic Fields?

Imagine a job application that asks for previous work experience.

One applicant may have one previous job, while another may have five.

A fixed form with exactly one experience field would not work well for everyone.

Dynamic fields allow the interface to match the user's needs.

5.3 Analogy: Adding Rows to a Spreadsheet

A spreadsheet lets you add rows as you need more information.

A React form can follow the same idea: maintain a list of fields in state and render one input for each item.

5.4 Example: Add and Remove Skill Fields

SkillForm.jsxJSX
import { useState } from "react";

function SkillForm() {
  const [skills, setSkills] = useState([
    { id: "skill-1", value: "" }
  ]);

  function addSkill() {
    setSkills(currentSkills => [
      ...currentSkills,
      {
        id: crypto.randomUUID(),
        value: ""
      }
    ]);
  }

  function updateSkill(id, value) {
    setSkills(currentSkills =>
      currentSkills.map(skill =>
        skill.id === id
          ? { ...skill, value }
          : skill
      )
    );
  }

  function removeSkill(id) {
    setSkills(currentSkills =>
      currentSkills.filter(skill => skill.id !== id)
    );
  }

  return (
    <div>
      <h2>Your Skills</h2>

      {skills.map((skill, index) => (
        <div key={skill.id}>
          <label htmlFor={skill.id}>
            Skill {index + 1}
          </label>

          <input
            id={skill.id}
            value={skill.value}
            onChange={event =>
              updateSkill(skill.id, event.target.value)
            }
          />

          <button
            type="button"
            onClick={() => removeSkill(skill.id)}
            disabled={skills.length === 1}
          >
            Remove
          </button>
        </div>
      ))}

      <button type="button" onClick={addSkill}>
        Add Skill
      </button>
    </div>
  );
}

export default SkillForm;

Explanation

Initial list

initialJSX
const [skills, setSkills] = useState([
  { id: "skill-1", value: "" }
]);

The form begins with one skill field.

Add a field

addJSX
setSkills(currentSkills => [
  ...currentSkills,
  {
    id: crypto.randomUUID(),
    value: ""
  }
]);

A new object is appended to a newly created array.

The ID is generated when the field is created, rather than on every render.

Update a field

updateJSX
currentSkills.map(skill =>
  skill.id === id
    ? { ...skill, value }
    : skill
)

map() replaces the matching skill with a new object while keeping the other fields intact.

Remove a field

removeJSX
currentSkills.filter(skill => skill.id !== id)

filter() creates a new array without the selected field.

Use a stable key

keyJSX
<div key={skill.id}>

The stable ID lets React associate each rendered field with the correct item when fields are inserted or removed.

5.5 Why Should You Avoid Array Indexes as Keys?

Suppose you create three inputs with keys 0, 1, and 2.

If the first input is removed, the remaining inputs shift positions. React can mistakenly associate an existing DOM input with a different data item.

Stable keys help prevent this problem.

This is especially important for dynamic inputs because each input may contain data the user has already entered.

◆ Remember

Represent dynamic fields as an array in state. Use immutable updates, stable IDs, and map() to render the current fields.

Topic 06

Reusable Form Components

Build the field once — configure it everywhere.

6.1 What Is a Reusable Form Component?

A reusable form component is a component designed to be used in multiple places with different values or configurations.

Examples include:

  • Text fields
  • Email inputs
  • Password inputs
  • Select controls
  • Validation messages
  • Submit buttons

Instead of repeating the same label, input, and error markup throughout an application, you can create one reusable component.

6.2 Why Is Reusability Important?

Imagine a CRM application with many forms:

  • Add lead
  • Edit student
  • Create course
  • Add trainer
  • Update profile

Many forms require a name, email, phone number, or other common fields.

Repeating the same markup can lead to inconsistent styling and validation behavior.

Reusable components help keep the appearance and interaction patterns consistent.

6.3 Analogy: A Standard Form Template

Imagine an institute using the same standard format for every student application.

The questions may differ, but the underlying structure and style remain consistent.

A reusable React form component provides a similar standard structure.

6.4 Create a Reusable TextField

Create TextField.jsx.

TextField.jsxJSX
function TextField({
  id,
  name,
  label,
  value,
  onChange,
  type = "text",
  error,
  ...inputProps
}) {
  const errorId = `${id}-error`;

  return (
    <div className="form-field">
      <label htmlFor={id}>{label}</label>

      <input
        id={id}
        name={name}
        type={type}
        value={value}
        onChange={onChange}
        aria-invalid={Boolean(error)}
        aria-describedby={error ? errorId : undefined}
        {...inputProps}
      />

      {error && (
        <p id={errorId} className="field-error" role="alert">
          {error}
        </p>
      )}
    </div>
  );
}

export default TextField;

Explanation

  • id identifies the input.
  • name identifies the field in submitted data.
  • label provides its visible description.
  • value and onChange control the input.
  • type lets the parent choose the input type.
  • error optionally displays a validation message.
  • ...inputProps lets the parent pass additional supported input attributes, such as required, autoComplete, or placeholder.

The component also connects the label to the input and connects the error message to the input.

6.5 Reuse the Component

ProfileForm.jsxJSX
import { useState } from "react";
import TextField from "./TextField.jsx";

function ProfileForm() {
  const [form, setForm] = useState({
    name: "",
    email: ""
  });

  function handleChange(event) {
    const { name, value } = event.target;

    setForm(current => ({
      ...current,
      [name]: value
    }));
  }

  return (
    <form>
      <TextField
        id="name"
        name="name"
        label="Full Name"
        value={form.name}
        onChange={handleChange}
        required
      />

      <TextField
        id="email"
        name="email"
        label="Email Address"
        type="email"
        value={form.email}
        onChange={handleChange}
        required
      />

      <button type="submit">Save Profile</button>
    </form>
  );
}

How Does the Generic Change Handler Work?

Suppose the user types an email address.

destructureJSX
const { name, value } = event.target;

The browser provides the input's name and value.

Then:

updateJSX
setForm(current => ({
  ...current,
  [name]: value
}));

If the input's name is "email", the handler updates the email property. If it is "name", the handler updates the name property.

The square brackets create a computed property name based on the current field's name.

6.6 Do All Inputs Use the Same Component?

Not always.

A text input, checkbox, radio group, and file input may require different props and behavior.

You can reuse components where the structure is genuinely similar, but do not force every control into one complicated component with dozens of conditional branches.

It is often cleaner to create separate components such as:

  • TextField
  • SelectField
  • CheckboxField
  • RadioGroup
  • FileField
◆ Remember

Reusable form components reduce duplication and support consistent labels, styles, validation messages, and behavior.

Topic 07

File Input and Upload Interfaces

Selecting a file is not the same as uploading it.

7.1 What Is a File Input?

A file input lets users select files from their device.

Examples include:

  • Uploading a résumé.
  • Selecting a profile image.
  • Attaching supporting documents.
  • Uploading an assignment.
  • Submitting a certificate.

HTML uses type="file" for this purpose.

7.2 Create a Basic File Input

ResumeUpload.jsxJSX

7.3 Read the Selected File

ResumeUpload.jsxJSX
import { useState } from "react";

function ResumeUpload() {
  const [file, setFile] = useState(null);

  function handleFileChange(event) {
    const selectedFile = event.target.files?.[0] ?? null;

  }

  return (

Explanation

read fileJSX
event.target.files?.[0] ?? null

The file input's files property contains the selected files.

For a single-file input, [0] retrieves the first selected file. If no file exists, the code uses null.

The application stores the selected File object in state and displays its name.

▲ Important

File inputs are a special case. Usually, keep the file input itself uncontrolled and store the selected File object separately if the application needs to display or validate it. Do not try to control the file input using a filename as its value.

7.4 Validate the File

You can validate a selection in your change handler.

ResumeUpload.jsxJSX
import { useState } from "react";

function ResumeUpload() {
  const [file, setFile] = useState(null);
  const [error, setError] = useState("");

  function handleFileChange(event) {
    const selectedFile = event.target.files?.[0] ?? null;

    if (!selectedFile) {
      setFile(null);
      setError("");
      return;
    }

    const maxSize = 5 * 1024 * 1024;
    const isPdf = selectedFile.type === "application/pdf";

    if (!isPdf) {
      setFile(null);
      setError("Please select a PDF file.");
      return;
    }

    if (selectedFile.size > maxSize) {
      setFile(null);
      setError("The file must be smaller than 5 MB.");
      return;
    }

    setFile(selectedFile);
    setError("");
  }

  return (
    <div>
      <label htmlFor="resume">Resume (PDF, up to 5 MB)</label>

      <input
        id="resume"
        type="file"
        accept=".pdf,application/pdf"
        onChange={handleFileChange}
        aria-invalid={Boolean(error)}
        aria-describedby={error ? "resume-error" : undefined}
      />

      {error && (
        <p id="resume-error" role="alert">
          {error}
        </p>
      )}

      {file && <p>Selected: {file.name}</p>}
    </div>
  );
}

This example checks the reported MIME type and file size on the client.

However, the browser-provided MIME type and file extension cannot be trusted as security guarantees. A backend must enforce upload restrictions and validate the received file appropriately.

7.5 Upload a File Using FormData

Selecting a file does not upload it to a server.

To upload it, your application must send a request to a backend endpoint that accepts the file.

uploadResume.jsJSX
async function uploadResume(file) {
  const formData = new FormData();

  formData.append("resume", file);

  const response = await fetch("/api/resumes", {
    method: "POST",
    body: formData
  });

  if (!response.ok) {
    throw new Error("Resume upload failed");
  }

  return response.json();
}

Explanation

createJSX
const formData = new FormData();

Creates a multipart form-data payload.

appendJSX
formData.append("resume", file);

Adds the selected file under the field name resume.

sendJSX
fetch("/api/resumes", {
  method: "POST",
  body: formData
});

Sends the file to the backend endpoint.

The URL "/api/resumes" is an example endpoint; your backend must implement it.

▲ Important

Do not manually set the Content-Type header to multipart/form-data when using FormData with fetch. The browser needs to generate the correct multipart boundary.

The server should authenticate and authorize the request as necessary and validate the file independently of client-side checks.

◆ Remember

File selection is not the same as file upload. Use type="file" to select a file, store the File object if needed, validate the input, and send it using FormData to a backend that supports uploads.

Topic 08

Accessible Labels and Error Messages

Forms that work for everyone.

8.1 What Is Form Accessibility?

Form accessibility means designing form controls so that people using different devices and assistive technologies can understand them and interact with them.

Examples include people who use screen readers, keyboard navigation, or other accessibility tools.

Accessible forms also help everyone by making instructions and validation messages clearer.

8.2 Why Are Labels Important?

A label communicates the purpose of a form control.

Consider an email input.

Without a proper label, a user may see a box and a placeholder. When the placeholder disappears after typing, its meaning may be less obvious.

A proper label gives the field a clear, persistent description.

8.3 Connect Labels to Inputs

Use htmlFor in JSX and make it match the input's id.

EmailField.jsxJSX
function EmailField() {
  return (
    <div>
      <label htmlFor="email">Email Address</label>

      <input
        id="email"
        name="email"
        type="email"
      />
    </div>
  );
}

The htmlFor="email" value associates the label with the input whose ID is email.

When practical, clicking the label also focuses the associated input.

8.4 Group Related Controls with fieldset and legend

Checkbox groups and radio-button groups often benefit from a shared label.

groupJSX
<fieldset>
  <legend>Preferred Learning Mode</legend>

  <label>
    <input type="radio" name="mode" value="online" />
    Online
  </label>

  <label>
    <input type="radio" name="mode" value="classroom" />
    Classroom
  </label>
</fieldset>

The fieldset groups the related controls, while legend describes the group.

This is particularly useful when the choices cannot be understood completely from each individual option.

8.5 Associate an Error with Its Field

Imagine a registration form where the user enters an invalid email.

The interface should explain what went wrong and identify which field needs correction.

EmailField.jsxJSX
function EmailField({ email, setEmail, error }) {
  return (
    <div>
      <label htmlFor="email">Email Address</label>

      <input
        id="email"
        name="email"
        type="email"
        value={email}
        onChange={event => setEmail(event.target.value)}
        aria-invalid={Boolean(error)}
        aria-describedby={error ? "email-error" : undefined}
      />

      {error && (
        <p id="email-error" role="alert">
          {error}
        </p>
      )}
    </div>
  );
}

Important Attributes

aria-invalid

Indicates that a field currently has invalid data. It is commonly set to true when a validation error exists.

aria-describedby

Associates a control with additional explanatory text, such as its validation message.

role="alert"

Can announce a newly displayed error message to assistive technologies. Use it thoughtfully rather than making every informational message an alert.

These attributes do not replace the actual label. The interface should provide both a clear field label and a useful error message.

8.6 Show Clear Error Messages

A useful error message tells the user how to correct the problem.

Less helpful:

Less helpful
Invalid input.

More helpful:

More helpful
Enter an email address in the format name@example.com.

For a required field, you might say:

Required field
Enter your full name.

Error messages should identify the problem in a clear and respectful manner.

8.7 Do Not Rely on Color Alone

If an invalid field is highlighted in red, also provide textual feedback and appropriate accessibility attributes.

Not every user perceives color in the same way, and a color alone does not explain what needs to be corrected.

8.8 Use Appropriate HTML Semantics

Use:

  • label to name individual controls.
  • fieldset and legend to group related fields.
  • button type="submit" for form submission.
  • button type="button" for an action that should not submit the form.
  • required and suitable input types for basic native validation.
  • aria-describedby when additional field instructions or errors need to be associated with a control.
◆ Remember

Accessible forms have clear labels, meaningful groups, understandable errors, keyboard-friendly controls, and appropriate HTML semantics.

Step 3: Create App.jsx

src/App.jsxJSX
import { useState } from "react";
import TextField from "./components/TextField.jsx";
import "./App.css";

function App() {
  const [form, setForm] = useState({
    fullName: "",
    email: "",
    course: "",
    mode: "online",
    agree: false
  });

  const [skills, setSkills] = useState([
    { id: "skill-1", value: "" }
  ]);

  const [resume, setResume] = useState(null);
  const [errors, setErrors] = useState({});
  const [submitted, setSubmitted] = useState(false);

  function handleChange(event) {
    const { name, value, type, checked } = event.target;

    setForm(current => ({
      ...current,
      [name]: type === "checkbox" ? checked : value
    }));

    setErrors(current => ({
      ...current,
      [name]: ""
    }));

    setSubmitted(false);
  }

  function addSkill() {
    setSkills(current => [
      ...current,
      {
        id: crypto.randomUUID(),
        value: ""
      }
    ]);
  }

  function updateSkill(id, value) {
    setSkills(current =>
      current.map(skill =>
        skill.id === id
          ? { ...skill, value }
          : skill
      )
    );
  }

  function removeSkill(id) {
    setSkills(current =>
      current.filter(skill => skill.id !== id)
    );
  }

  function handleResumeChange(event) {
    const file = event.target.files?.[0] ?? null;

    setResume(null);
    setErrors(current => ({
      ...current,
      resume: ""
    }));
    setSubmitted(false);

    if (!file) {
      return;
    }

    if (file.type !== "application/pdf") {
      setErrors(current => ({
        ...current,
        resume: "Please select a PDF file."
      }));
      return;
    }

    if (file.size > 5 * 1024 * 1024) {
      setErrors(current => ({
        ...current,
        resume: "The file must be smaller than 5 MB."
      }));
      return;
    }

    setResume(file);
  }

  function handleSubmit(event) {
    event.preventDefault();

    const nextErrors = {};

    if (form.fullName.trim().length < 3) {
      nextErrors.fullName =
        "Enter a name containing at least 3 characters.";
    }

    if (!/^\S+@\S+\.\S+$/.test(form.email)) {
      nextErrors.email =
        "Enter a valid email address.";
    }

    if (!form.course) {
      nextErrors.course =
        "Please select a course.";
    }

    if (!form.agree) {
      nextErrors.agree =
        "You must accept the terms before continuing.";
    }

    if (errors.resume) {
      nextErrors.resume = errors.resume;
    }

    setErrors(nextErrors);

    if (Object.keys(nextErrors).length > 0) {
      setSubmitted(false);
      return;
    }

    setSubmitted(true);

    console.log({
      ...form,
      skills: skills
        .map(skill => skill.value.trim())
        .filter(Boolean),
      resumeName: resume?.name ?? null
    });
  }

  return (
    <main className="admission-page">
      <h1>Student Admission Form</h1>
      <p>Enter your details to register for a course.</p>

      <form onSubmit={handleSubmit} noValidate>
        <TextField
          id="fullName"
          name="fullName"
          label="Full Name"
          value={form.fullName}
          onChange={handleChange}
          error={errors.fullName}
          autoComplete="name"
          required
        />

        <TextField
          id="email"
          name="email"
          label="Email Address"
          type="email"
          value={form.email}
          onChange={handleChange}
          error={errors.email}
          autoComplete="email"
          required
        />

        <div className="form-field">
          <label htmlFor="course">Select Course</label>

          <select
            id="course"
            name="course"
            value={form.course}
            onChange={handleChange}
            aria-invalid={Boolean(errors.course)}
            aria-describedby={
              errors.course ? "course-error" : undefined
            }
            required
          >
            <option value="">Choose a course</option>
            <option value="react">React JS</option>
            <option value="node">Node.js</option>
            <option value="mern">MERN Stack</option>
          </select>

          {errors.course && (
            <p id="course-error" className="field-error" role="alert">
              {errors.course}
            </p>
          )}
        </div>

        <fieldset>
          <legend>Preferred Learning Mode</legend>

          <label>
            <input
              type="radio"
              name="mode"
              value="online"
              checked={form.mode === "online"}
              onChange={handleChange}
            />
            Online
          </label>

          <label>
            <input
              type="radio"
              name="mode"
              value="classroom"
              checked={form.mode === "classroom"}
              onChange={handleChange}
            />
            Classroom
          </label>
        </fieldset>

        <fieldset>
          <legend>Your Skills</legend>

          {skills.map((skill, index) => (
            <div className="skill-row" key={skill.id}>
              <label htmlFor={skill.id}>
                Skill {index + 1}
              </label>

              <input
                id={skill.id}
                type="text"
                value={skill.value}
                onChange={event =>
                  updateSkill(skill.id, event.target.value)
                }
              />

              <button
                type="button"
                onClick={() => removeSkill(skill.id)}
                disabled={skills.length === 1}
              >
                Remove
              </button>
            </div>
          ))}

          <button type="button" onClick={addSkill}>
            Add Skill
          </button>
        </fieldset>

        <div className="form-field">
          <label htmlFor="resume">
            Résumé (PDF, up to 5 MB)
          </label>

          <input
            id="resume"
            name="resume"
            type="file"
            accept=".pdf,application/pdf"
            onChange={handleResumeChange}
            aria-invalid={Boolean(errors.resume)}
            aria-describedby={
              errors.resume ? "resume-error" : undefined
            }
          />

          {errors.resume && (
            <p id="resume-error" className="field-error" role="alert">
              {errors.resume}
            </p>
          )}

          {resume && <p>Selected file: {resume.name}</p>}
        </div>

        <div className="form-field">
          <label>
            <input
              type="checkbox"
              name="agree"
              checked={form.agree}
              onChange={handleChange}
              aria-invalid={Boolean(errors.agree)}
              aria-describedby={
                errors.agree ? "agree-error" : undefined
              }
            />
            I agree to the terms and conditions.
          </label>

          {errors.agree && (
            <p id="agree-error" className="field-error" role="alert">
              {errors.agree}
            </p>
          )}
        </div>

        <button type="submit">Submit Application</button>
      </form>

      {submitted && (
        <section className="success-message" aria-live="polite">
          <h2>Application Ready</h2>
          <p>Name: {form.fullName}</p>
          <p>Email: {form.email}</p>
          <p>Course: {form.course}</p>
          <p>Learning Mode: {form.mode}</p>
          <p>
            Skills:{" "}
            {skills.map(skill => skill.value.trim())
              .filter(Boolean).join(", ") || "None entered"}
          </p>
          <p>Résumé: {resume?.name ?? "Not provided"}</p>
        </section>
      )}
    </main>
  );
}

export default App;

Common Beginner Mistakes

Eight pitfalls every new React form developer runs into — and how to fix them.

Mistake 1: Forgetting preventDefault()

If you use a normal form submission without intending to navigate or reload the page, the browser may reload or navigate away.

Use:

preventDefaultJSX
function handleSubmit(event) {
  event.preventDefault();
}

Mistake 2: Using value for a Controlled Checkbox

Incorrect:

✕ IncorrectJSX
<input type="checkbox" value={agreed} />

Correct:

✓ CorrectJSX
<input
  type="checkbox"
  checked={agreed}
  onChange={event => setAgreed(event.target.checked)}
/>

For checkboxes, checked represents the selected state.

Mistake 3: Forgetting onChange on a Controlled Input

Incorrect:

✕ IncorrectJSX
<input value={name} />

This input is controlled but cannot normally be edited by the user.

Correct:

✓ CorrectJSX
<input
  value={name}
  onChange={event => setName(event.target.value)}
/>

Mistake 4: Using Placeholder Text Instead of a Label

Incorrect:

✕ IncorrectJSX
<input placeholder="Enter your email" />

Better:

✓ BetterJSX
<label htmlFor="email">Email Address</label>
<input id="email" type="email" placeholder="name@example.com" />

A placeholder provides a hint; the label identifies the field.

Mistake 5: Using Array Indexes as Dynamic Field Keys

Use a stable ID assigned when the field is created, rather than an index that changes when fields are removed or reordered.

Mistake 6: Trusting Client-Side Validation Alone

A user can bypass client-side rules. Validate the submitted data again on the server.

Mistake 7: Assuming accept Makes File Uploads Safe

accept=".pdf" guides the browser's file picker. It is not a security guarantee. The server needs to validate the file and enforce suitable size and content restrictions.

Mistake 8: Forgetting Button Types

Inside a form, use:

button typesJSX
<button type="submit">Submit</button>
<button type="button">Add Another Field</button>

This makes each button's purpose explicit and prevents ordinary action buttons from unintentionally submitting the form.

Revision

Quick Revision Notes

One-sentence definitions for every concept in Phase 4.

Form submission

Use onSubmit to handle submission and preventDefault() when you need to prevent the browser's default behavior.

Input controls

Use value for controlled text inputs and selects; use checked for controlled checkboxes and radio buttons.

Controlled form

React state is the source of truth for the input value.

Uncontrolled form

The DOM maintains the current value, which can be read with FormData at submission time.

Validation

Use native HTML attributes and JavaScript validation for appropriate form rules.

Dynamic fields

Store fields in an array, use immutable updates, and assign stable IDs.

Reusable form components

Build common inputs and error displays once, then configure them through props.

File input

Read the selected File object and use FormData when sending it to a backend.

Accessibility

Use proper labels, group related controls, associate errors with fields, and explain how to correct invalid data.
