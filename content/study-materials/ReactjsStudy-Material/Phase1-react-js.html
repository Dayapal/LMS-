Topic 1: What Is React and Why Is It Used?

1.1 What is React?

React is a JavaScript library for building user interfaces (UIs).

A user interface is the part of an application a user sees and interacts with, including buttons, forms, navigation bars, product cards, dashboards, and profile sections.

React allows us to divide a large interface into small, reusable pieces called components.

For example, consider an education website containing:

  • A navigation bar
  • A course list
  • Course cards
  • A student profile
  • A footer

Instead of writing the entire interface as one large block of code, we can create separate components for the navbar, course cards, profile, and footer.

1.2 Analogy: Building a House

Analogy — A House

Imagine you are constructing a house.

A house contains different parts:

  • Doors
  • Windows
  • Walls
  • Rooms
  • A kitchen
  • A bathroom

You do not need to invent an entirely new type of door for every room. You can reuse a common design wherever appropriate.

React follows a similar idea.

HouseReact
DoorButton component
WindowImage component
RoomPage section component
Reusable room designReusable UI component
Complete houseComplete application

Main idea: React helps us build a large user interface using smaller pieces that can be maintained and reused.

1.3 Why Do We Need React?

First, consider how we might build a simple interface using HTML.

<!DOCTYPE html>
<html>
  <body>
    <h1>Welcome to My Website</h1>
    <p>Learn web development.</p>
    <button>Explore Courses</button>
  </body>
</html>

This code creates a heading, paragraph, and button.

For a small static page, HTML is sufficient. However, a modern application may contain hundreds of interface elements and frequently changing information.

For example, an online shopping website may need to display product cards, shopping cart details, filters, search results, and user information.

As an application grows, organizing and updating its interface manually can become complicated.

React helps by providing several useful capabilities.

A. Component-based development

We can separate the interface into manageable components.

function Welcome() {
  return <h1>Welcome to React!</h1>;
}

Here, Welcome is a component that describes a small part of the interface.

B. Reusability

We can use the same component multiple times.

function CourseCard() {
  return <article>React Fundamentals</article>;
}

function App() {
  return (
    <main>
      <CourseCard />
      <CourseCard />
      <CourseCard />
    </main>
  );
}

export default App;

The CourseCard component is defined once but used three times.

C. JavaScript integration

React lets us combine JavaScript expressions with UI descriptions.

function Welcome() {
  const studentName = "Rahul";

  return <h1>Welcome, {studentName}!</h1>;
}

export default Welcome;

Output:

Welcome, Rahul!

The value of studentName is inserted into the interface using curly braces.

D. Easier interface updates

React manages how the UI is updated when the output of a component changes.

You describe what the interface should look like. React then coordinates the necessary updates to the browser's DOM.

We will study rendering in Topic 12.

1.4 When Is React Useful?

React is commonly used to build:

  • Admin dashboards and CRM applications
  • E-commerce websites
  • Social media interfaces
  • Learning management systems
  • Booking applications
  • Interactive forms and portals

A static page does not necessarily need React. React becomes especially useful when an application has a complex interface, repeated UI patterns, and frequently changing content.

React is a library, not a programming language. You use JavaScript to write React applications.

Topic 2: SPA, Client-Side Rendering, and React's Role

Before learning how React creates interfaces, we need to understand how websites display pages.

2.1 What Is a Traditional Multi-Page Application?

In a traditional multi-page website, clicking a link often causes the browser to request a new HTML document from the server.

Imagine visiting an institute website:

  1. You open the home page.
  2. You click About Us.
  3. The browser requests and loads the About Us page.
  4. You click Courses.
  5. The browser requests and loads the Courses page.

Each navigation may involve loading a new document from the server.

This approach is still used by many websites and can work very well.

2.2 What Is a Single-Page Application (SPA)?

A Single-Page Application (SPA) is an application that loads an initial HTML document and then updates the displayed interface as the user interacts with it, without requiring a complete document reload for every internal navigation.

Think about using an application such as an email dashboard.

You might switch between Inbox, Sent, and Drafts while the main application remains loaded.

A SPA can replace the content of the current interface instead of loading a completely new HTML document for each navigation.

Analogy — A Restaurant

Imagine a restaurant with one dining area.

You can change your table arrangement, update a menu, or replace a dish without rebuilding the entire restaurant every time.

A SPA works in a similar way: the application remains in place while parts of the interface change.

2.3 What Is Client-Side Rendering (CSR)?

Client-side rendering means that the browser executes JavaScript to produce or update the user interface.

In a typical React SPA, the process looks like this:

  1. The browser requests the website.
  2. The server sends the initial HTML, JavaScript, and other required assets.
  3. The browser downloads and executes the JavaScript.
  4. React creates the interface and displays it.
  5. React updates the interface as the application runs.

A typical client-rendered React application starts with an HTML file containing a root element.

<div id="root"></div>

Initially, this element is the container into which React will render the application.

React connects to the element and displays the interface inside it.

2.4 How Does React Fit Into This Process?

Imagine building a student dashboard.

The browser provides the environment, JavaScript executes in that environment, and React manages the UI described by your components.

function StudentDashboard() {
  return (
    <main>
      <h1>Student Dashboard</h1>
      <p>Welcome to your learning portal.</p>
    </main>
  );
}

export default StudentDashboard;

This component describes the dashboard's interface. It does not, by itself, tell the browser where the application should be mounted. The React entry point performs that task.

A typical entry point looks like this:

import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <App />
);

What happens here?

  • createRoot creates a React root attached to the HTML element.
  • document.getElementById("root") finds the HTML container.
  • <App /> represents the root application component.
  • .render() asks React to render that component into the container.

We will examine the Vite project files in Topics 3 and 4.

2.5 Is Every React Application a SPA?

No.

React is a UI library. It can be used in a client-rendered SPA, but it can also be used with server rendering and other architectures.

A typical Vite React project is commonly configured as a client-rendered application. Frameworks such as Next.js can support server rendering and other rendering strategies.

For now, focus on this distinction:

TermMeaning
ReactA JavaScript library for creating interfaces
SPAAn application model that updates views without a full document reload for every internal navigation
CSRRendering or updating the UI in the browser using JavaScript
ViteA development and build tool used to set up React projects and other frontend applications

SPA and CSR are related, but they are not the same thing. An SPA describes an application structure and navigation experience; CSR describes where rendering work takes place.

Topic 3: Create a React Project Using Vite

3.1 What Is Vite?

Vite is a frontend development tool that helps you start and build modern web projects.

It provides a development server, fast feedback while coding, and a production build process.

Analogy — Setting Up a Classroom

Imagine you want to teach a class.

You could build the classroom, arrange the furniture, install lights, and prepare every item yourself.

Or you could use an already equipped classroom and start teaching.

Vite provides a ready-to-use project setup so you can focus on learning React instead of configuring every tool manually.

3.2 Step 1: Check Node.js and npm

Vite requires Node.js to run its development tools.

Open your terminal, Command Prompt, or VS Code terminal and execute:

node -v
npm -v

The first command displays your Node.js version. The second displays your npm version.

Use a Node.js version compatible with the current Vite requirements. Check the official Vite guide if you receive a version warning.

3.3 Step 2: Create the Project

Run:

npm create vite@latest

Vite asks you to enter or select the project name, framework, and variant.

Choose:

  • Project name: react-foundations
  • Framework: React
  • Variant: JavaScript

Choose JavaScript rather than TypeScript for this phase, because these lessons focus on React fundamentals using JavaScript.

You can also create the project directly with a command:

npm create vite@latest react-foundations -- --template react

Explanation:

  • npm create vite@latest runs the Vite project scaffolding tool.
  • react-foundations is the project directory name.
  • --template react selects the React JavaScript template.

3.4 Step 3: Enter the Project Directory

cd react-foundations

The cd command changes the current terminal directory to the newly created project.

3.5 Step 4: Install Dependencies

npm install

This installs the packages required by your project.

The project dependencies are declared in package.json. npm downloads the packages and creates a node_modules directory.

3.6 Step 5: Start the Development Server

npm run dev

Vite starts a local development server and displays a local URL, usually something similar to:

http://localhost:5173/

Open the URL in your browser to view your React application.

The exact port can differ if another application is already using the default port.

3.7 Step 6: Make Your First Change

Open src/App.jsx and replace its contents with:

function App() {
  return (
    <main>
      <h1>My First React Application</h1>
      <p>I am learning React step by step.</p>
    </main>
  );
}

export default App;

Save the file.

You should see the new heading and paragraph in the browser. Vite's development server supports hot updates, so you usually do not need to manually refresh the page after editing a source file.

3.8 What Did You Just Build?

You created a React project that uses:

  • Vite to run the development environment.
  • React to define and render the interface.
  • JSX to describe HTML-like UI structures.
  • A browser to display the resulting interface.

Common Setup Errors

Error: node or npm is not recognized.
Node.js may not be installed, or your terminal may not have the correct PATH configuration.

Error: Missing script: "dev".
You may be in the wrong directory. Check that the current folder contains the project's package.json.

The browser shows an error instead of your app.
Read the terminal and browser console errors. A misspelled import, missing file, or invalid JSX may prevent the project from running.

Topic 4: Understand the React Project Structure

When Vite creates a React project, it generates several files and directories.

A simplified structure looks like this:

react-foundations/
│
├── node_modules/
│
├── public/
│
├── src/
│   ├── assets/
│   ├── App.css
│   ├── App.jsx
│   ├── index.css
│   └── main.jsx
│
├── .gitignore
├── index.html
├── package.json
├── package-lock.json
└── vite.config.js

The exact structure may vary slightly with template versions.

4.1 The src Directory

src stands for source. It contains the code you normally work with while developing the application.

App.jsx

This file commonly contains the main application component.

function App() {
  return <h1>Hello, React!</h1>;
}

export default App;

App describes a UI element that the application can render.

main.jsx

This is usually the entry point of a Vite React application.

Example:

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);

Explanation:

  • The imports bring in React tools and the App component.
  • document.getElementById("root") finds the mounting element from index.html.
  • createRoot(...) creates the React root.
  • .render(...) renders the component tree.
  • StrictMode enables additional development checks. It does not create a visible UI element of its own.

Notice that App is imported from App.jsx. This is how components can be defined in one file and used in another.

App.css

This file is commonly used for styling the application component.

h1 {
  color: royalblue;
  text-align: center;
}

The CSS changes the appearance of matching headings.

index.css

This file often contains global styles, such as the page background, body font, and default margins.

body {
  margin: 0;
  font-family: Arial, sans-serif;
}

assets/

This directory is commonly used for assets imported by source code, such as images and other frontend resources.

4.2 The public Directory

The public directory is for static assets that need to be served directly.

For example, you might keep a file here:

public/logo.png

It can usually be referenced through the public URL:

function Logo() {
  return <img src="/logo.png" alt="Institute logo" />;
}

For source assets that you import into components, the src/assets directory is commonly appropriate.

4.3 The index.html File

Vite's index.html is the HTML entry point.

A simplified example:

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>React Foundations</title>
  </head>

  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>

The important parts are:

<div id="root"></div>

This element provides the container for the React application.

<script type="module" src="/src/main.jsx"></script>

This tells the browser to load the JavaScript module that initializes React.

4.4 package.json

This file stores project information, dependencies, and scripts.

A simplified example:

{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}

These scripts allow you to use:

npm run dev
npm run build
npm run preview
  • dev starts the development server.
  • build creates a production build.
  • preview serves the production build locally for inspection.

The complete generated package.json contains additional information and dependencies.

4.5 node_modules/

This directory contains installed dependencies used by the project.

Do not normally edit package files directly inside node_modules. Manage dependencies through npm instead.

4.6 vite.config.js

This file is used to configure Vite. You may not need to edit it during your first React lessons.

Understand the Complete Flow

The relationship among the main files can be summarized as:

index.html
    |
    | loads
    v
main.jsx
    |
    | renders
    v
App.jsx
    |
    | contains
    v
Other React components
    |
    v
Visible interface in the browser

index.html provides the root container, main.jsx initializes React, and App.jsx commonly describes the main application UI.

Topic 5: JSX Syntax and Expressions

5.1 What Is JSX?

JSX stands for JavaScript XML.

It is a syntax extension for JavaScript that lets you write HTML-like markup inside JavaScript code.

Without JSX, creating React elements involves more function calls.

With JSX, the interface is easier to read and write.

For example:

const heading = <h1>Hello, React!</h1>;

The markup looks similar to HTML, but it is JSX written within JavaScript.

JSX is transformed by the build tools into JavaScript that React can understand.

5.2 Why Do We Use JSX?

Imagine building an interface with many elements, including headings, images, paragraphs, and buttons.

Writing the interface using nested function calls would become difficult to read.

JSX lets us keep the UI structure close to the JavaScript logic that produces it.

Analogy — A Recipe

A recipe describes the ingredients and arrangement needed to make a dish.

JSX describes the UI elements and how they should be arranged.

For example:

function Profile() {
  return (
    <section>
      <h1>Student Profile</h1>
      <p>Name: Rahul</p>
    </section>
  );
}

The JSX describes a section containing a heading and a paragraph.

5.3 Basic JSX Syntax

function App() {
  return <h1>Welcome to React</h1>;
}

export default App;

Explanation:

  • function App() declares a JavaScript function.
  • return specifies the value that the function returns.
  • <h1>Welcome to React</h1> is JSX.
  • export default App makes the component available to other modules as the default export.

When React renders this component, the browser displays the heading.

5.4 JSX Can Contain Nested Elements

function Course() {
  return (
    <div>
      <h1>React Fundamentals</h1>
      <p>Learn components and props.</p>
      <button>Start Learning</button>
    </div>
  );
}

export default Course;

The div is the parent element. The heading, paragraph, and button are its children.

The parentheses allow you to format a multiline JSX expression across several lines when necessary. Parentheses do not create the UI themselves.

5.5 JSX Is Not Exactly HTML

JSX looks like HTML, but there are differences.

Use className instead of class

function App() {
  return <h1 className="title">Hello React</h1>;
}

In JSX, use className to specify a CSS class.

Use htmlFor instead of for

function LoginForm() {
  return (
    <div>
      <label htmlFor="email">Email address</label>
      <input id="email" type="email" />
    </div>
  );
}

Here, htmlFor associates the label with the input whose ID is email.

Close elements properly

function Example() {
  return (
    <div>
      <img src="/logo.png" alt="Logo" />
      <input type="text" />
    </div>
  );
}

The img and input elements are self-closing in JSX.

Use camelCase for many JSX attributes

<button onClick={handleClick}>Click Me</button>

onClick uses camelCase. In this example, handleClick would need to be a function defined within scope.

Event handling will be studied separately in a later phase; here, this is simply an illustration of JSX syntax.

5.6 Embedding JavaScript Expressions in JSX

One of JSX's most useful features is the ability to embed JavaScript expressions using curly braces {}.

function App() {
  const studentName = "Priya";
  const age = 21;

  return (
    <div>
      <h1>Hello, {studentName}</h1>
      <p>Age: {age}</p>
      <p>Next year: {age + 1}</p>
    </div>
  );
}

export default App;

Output:

Hello, Priya
Age: 21
Next year: 22

Explanation:

  • {studentName} displays the string stored in the variable.
  • {age} displays the age.
  • {age + 1} evaluates the JavaScript arithmetic expression and displays its result.

The key rule is that curly braces let you use JavaScript expressions within JSX.

5.7 JavaScript Expressions vs. Statements

An expression produces a value.

Examples:

{10 + 5}
{studentName}
{age >= 18}

A statement performs an action or controls program execution.

Examples:

const age = 21;

if (age >= 18) {
  console.log("Adult");
}

You cannot put a standard if statement directly inside JSX curly braces.

Instead, you can use an expression such as a ternary operator.

function AgeMessage() {
  const age = 21;

  return (
    <p>
      {age >= 18 ? "You are an adult." : "You are a minor."}
    </p>
  );
}

The ternary expression evaluates to one of two strings.

5.8 JSX Can Be Stored in Variables

function App() {
  const heading = <h1>Welcome to React</h1>;

  return (
    <main>
      {heading}
      <p>Let's begin learning.</p>
    </main>
  );
}

export default App;

The heading variable stores a JSX element, and {heading} places that element in the returned JSX.

JSX is the syntax used to describe the interface. Curly braces let you insert JavaScript expressions into that interface.

Topic 6: Embedding JavaScript in JSX

Topic 5 introduced JSX. Now let's focus on the different kinds of JavaScript values and expressions that you can display inside it.

6.1 Displaying Variables

function Student() {
  const name = "Aarav";
  const course = "Full Stack Development";

  return (
    <div>
      <h1>{name}</h1>
      <p>Course: {course}</p>
    </div>
  );
}

The curly braces insert the values of name and course into the JSX.

This avoids hardcoding the same values directly into the UI.

6.2 Using Arithmetic Expressions

function Price() {
  const price = 1000;
  const tax = 180;

  return (
    <div>
      <p>Price: ₹{price}</p>
      <p>Tax: ₹{tax}</p>
      <p>Total: ₹{price + tax}</p>
    </div>
  );
}

The expression price + tax evaluates to 1180.

This demonstrates that JSX can display the results of JavaScript calculations.

6.3 Calling Functions Inside JSX

A JavaScript function can calculate a value that is inserted into JSX.

function getGreeting() {
  return "Good morning!";
}

function App() {
  return <h1>{getGreeting()}</h1>;
}

export default App;

Explanation:

  • getGreeting() returns a string.
  • {getGreeting()} calls the function.
  • React renders the returned string as text within the heading.

The function should be safe to call during rendering. Components and functions used to calculate rendered output should not perform unrelated side effects.

6.4 Displaying Object Properties

Since React is built around JavaScript, you can use ordinary object properties.

function StudentProfile() {
  const student = {
    name: "Meera",
    course: "React",
    city: "Rajkot"
  };

  return (
    <div>
      <h2>{student.name}</h2>
      <p>Course: {student.course}</p>
      <p>City: {student.city}</p>
    </div>
  );
}

Output:

Meera
Course: React
City: Rajkot

You are inserting individual string values from the object. You generally cannot place an ordinary object directly into JSX and expect React to display it as readable text.

For example, {student} is not an appropriate way to display the entire object.

6.5 Conditional Output with a Ternary Operator

A ternary operator has this structure:

condition ? valueIfTrue : valueIfFalse

Example:

function AdmissionStatus() {
  const isAdmitted = true;

  return (
    <div>
      <h2>Admission Status</h2>
      <p>
        {isAdmitted ? "Admission confirmed" : "Admission pending"}
      </p>
    </div>
  );
}

Since isAdmitted is true, the displayed message is Admission confirmed.

This is useful for choosing what text or element to display based on a value.

6.6 Conditional Output with Logical AND (&&)

The logical AND operator can show something when a condition is true.

function Notice() {
  const showNotice = true;

  return (
    <div>
      <h1>Student Portal</h1>
      {showNotice && <p>Your classes begin on Monday.</p>}
    </div>
  );
}

When showNotice is true, the paragraph is included in the rendered output. When it is false, it is not shown.

Be careful when using numbers with &&. For example, {0 && <p>Notice</p>} evaluates to 0, and React displays that number. If the intention is to show a message only when a number is positive, use a condition such as {count > 0 && <p>Notice</p>}.

6.7 Understanding Values That Don't Display as You Might Expect

React does not render every JavaScript value as visible text.

Commonly:

  • A string displays as text.
  • A number displays as text.
  • A boolean by itself does not display visible text.
  • null and undefined do not display visible content.
  • A normal JavaScript object cannot be displayed directly as a React child.

Example:

function Values() {
  return (
    <div>
      <p>{"React"}</p>
      <p>{100}</p>
      <p>{true}</p>
      <p>{null}</p>
    </div>
  );
}

Visible output:

React
100

The boolean true and null do not create visible text.

You can use JavaScript variables, arithmetic, function calls, object properties, and conditional expressions inside JSX. The expression must produce a valid renderable result.

Topic 7: Fragments and JSX Rules

7.1 What Is a React Fragment?

A Fragment lets you group multiple JSX elements without adding an extra DOM element solely for the grouping.

React's shorthand syntax is:

<>
  {/* JSX elements */}
</>

The longer syntax is:

import { Fragment } from "react";

<Fragment>
  {/* JSX elements */}
</Fragment>

For ordinary grouping, the shorthand is usually sufficient.

7.2 Why Do We Need Fragments?

Consider this component:

function StudentInfo() {
  return (
    <h1>Student Profile</h1>
    <p>Name: Rahul</p>
  );
}

This is invalid JSX because a component cannot directly return two adjacent JSX elements without a shared enclosing structure.

One solution is to use a div:

function StudentInfo() {
  return (
    <div>
      <h1>Student Profile</h1>
      <p>Name: Rahul</p>
    </div>
  );
}

However, that creates an extra div in the DOM.

Another solution is a Fragment:

function StudentInfo() {
  return (
    <>
      <h1>Student Profile</h1>
      <p>Name: Rahul</p>
    </>
  );
}

This groups both elements without adding a wrapper element to the DOM.

Analogy — A Transparent Folder

Imagine putting two documents into a transparent folder.

The folder helps you group them, but it does not change the documents themselves.

A Fragment groups multiple JSX elements without creating an additional HTML wrapper.

7.3 Rule 1: Return One Enclosing JSX Structure

Incorrect:

function App() {
  return (
    <h1>Hello</h1>
    <p>Welcome</p>
  );
}

Correct:

function App() {
  return (
    <>
      <h1>Hello</h1>
      <p>Welcome</p>
    </>
  );
}

7.4 Rule 2: Close All Elements

Incorrect:

function App() {
  return <div><h1>Hello</div>;
}

Correct:

function App() {
  return (
    <div>
      <h1>Hello</h1>
    </div>
  );
}

Every opening element must have a matching closing tag, except self-closing elements.

7.5 Rule 3: Self-Close Empty Elements

function App() {
  return (
    <div>
      <img src="/logo.png" alt="Logo" />
      <input type="text" />
    </div>
  );
}

The img and input elements do not wrap other content, so they are written using self-closing syntax in JSX.

7.6 Rule 4: Use className

function App() {
  return <h1 className="main-heading">React Learning</h1>;
}

The className attribute specifies the CSS class.

7.7 Rule 5: Put JavaScript Expressions Inside Curly Braces

function App() {
  const name = "Aarav";

  return <h1>Hello, {name}!</h1>;
}

Without curly braces, React would treat the variable name as ordinary text.

7.8 Rule 6: Use Parentheses for Readable Multiline JSX

function App() {
  return (
    <main>
      <h1>Learning React</h1>
      <p>One concept at a time.</p>
    </main>
  );
}

The parentheses make the multiline return easier to read.

7.9 When Should You Use a Fragment or a div?

Use a Fragment when you only need to group multiple JSX elements.

Use a div or an appropriate semantic element such as main, section, or article when the wrapper represents a real structure in your page or needs to carry attributes or styling.

Fragments help keep your DOM clean. JSX must have valid nesting, properly closed tags, and one enclosing structure for adjacent returned elements.

Topic 8: Functional Components

8.1 What Is a Functional Component?

A functional component is a JavaScript function that returns React-renderable content, usually JSX.

Example:

function Welcome() {
  return <h1>Welcome to React!</h1>;
}

Here, Welcome is a React component.

Components are the building blocks of React applications.

8.2 Why Do We Need Components?

Imagine creating a page that contains a navbar, a profile, a course list, and a footer.

Writing the entire interface in one enormous component can make the code hard to understand and maintain.

By creating separate components, you can divide the interface according to its responsibilities.

For example:

function Navbar() {
  return <nav>My Institute</nav>;
}

function Profile() {
  return <h2>Student Profile</h2>;
}

function Footer() {
  return <footer>© 2026 My Institute</footer>;
}

function App() {
  return (
    <div>
      <Navbar />
      <Profile />
      <Footer />
    </div>
  );
}

export default App;

The App component combines the three smaller components.

8.3 Analogy: A Teaching Team

Analogy — A Teaching Team

Imagine an institute where:

  • One teacher handles React.
  • Another handles JavaScript.
  • Another manages student assignments.

Each teacher has a defined responsibility, but their combined work supports the institute.

Components work similarly. Smaller components can handle specific parts of an interface, while the main component combines them to create a complete page.

8.4 Component Naming Rules

React components should generally use PascalCase.

Correct:

function StudentProfile() {
  return <h1>Student Profile</h1>;
}

Then use the component as:

<StudentProfile />

Avoid defining your own component using a lowercase name such as studentProfile and expecting JSX to identify it as a React component.

In JSX, lowercase tags such as <div> refer to built-in HTML elements, while names such as <StudentProfile /> refer to components.

8.5 Components Can Be Stored in Separate Files

For example, create a file named Header.jsx.

function Header() {
  return <h1>My Learning Portal</h1>;
}

export default Header;

Then use it inside App.jsx:

import Header from "./Header.jsx";

function App() {
  return (
    <main>
      <Header />
      <p>Welcome to the portal.</p>
    </main>
  );
}

export default App;

The import statement brings in the exported component. The <Header /> expression tells React to render it at that position in the component tree.

This is a common way to organize larger projects.

8.6 A Component Is Not the Same as Calling an Ordinary Function

You might be tempted to call a component like this:

function Welcome() {
  return <h1>Welcome</h1>;
}

function App() {
  return <main>{Welcome()}</main>;
}

Although this can evaluate the function's returned JSX in a simple example, it is not the usual way to use React components.

The normal approach is:

function App() {
  return (
    <main>
      <Welcome />
    </main>
  );
}

Using <Welcome /> lets React manage the component as part of its component tree and rendering process.

8.7 Components Should Describe Their Output

A functional component should normally calculate and return its UI rather than manually manipulating the DOM.

function CourseTitle() {
  const title = "React Fundamentals";

  return <h2>{title}</h2>;
}

The component describes what should appear. React handles displaying the resulting UI.

A functional component is a reusable unit of UI defined using a JavaScript function. Use PascalCase names and render components with JSX syntax such as <Welcome />.

Topic 9: Component Composition and Reuse

9.1 What Is Component Composition?

Component composition means combining smaller components to create a larger interface.

A component can include other components inside its JSX. The result forms a component tree.

For example:

App
├── Navbar
├── MainContent
│   ├── CourseCard
│   ├── CourseCard
│   └── CourseCard
└── Footer

The main App component combines the navbar, main content, and footer. The main content combines multiple course cards.

9.2 Why Is Composition Useful?

Composition helps us:

  • Break large interfaces into smaller parts.
  • Reuse existing components.
  • Make code easier to understand.
  • Update one reusable design without duplicating it everywhere.
  • Give each component a clear purpose.

9.3 Example: Build a Course Card

First, create a reusable CourseCard component.

function CourseCard() {
  return (
    <article>
      <h2>React Fundamentals</h2>
      <p>Learn the basics of React.</p>
      <button>View Course</button>
    </article>
  );
}

Next, create a component that uses it several times.

function CourseSection() {
  return (
    <section>
      <h1>Available Courses</h1>

      <CourseCard />
      <CourseCard />
      <CourseCard />
    </section>
  );
}

Finally, use the section inside App.

function App() {
  return (
    <main>
      <CourseSection />
    </main>
  );
}

export default App;

The component tree looks like:

App
└── CourseSection
    ├── CourseCard
    ├── CourseCard
    └── CourseCard

The CourseCard is written once but composed into the page three times.

All three currently display the same content. We will make the content different using props in Topic 10.

9.4 Composition Does Not Require Repeating the Same Layout

A component can contain several different components.

function Navbar() {
  return <nav>My Institute</nav>;
}

function WelcomeMessage() {
  return <h1>Welcome, Student!</h1>;
}

function Footer() {
  return <footer>Keep Learning</footer>;
}

function App() {
  return (
    <>
      <Navbar />
      <WelcomeMessage />
      <Footer />
    </>
  );
}

The page is assembled from three components.

9.5 How Composition Helps in Real Projects

For a CRM dashboard, you might divide the page into:

  • Sidebar
  • Topbar
  • DashboardSummary
  • LeadCard
  • LeadTable
  • Footer

You can reuse small components wherever appropriate rather than copying their markup into multiple screens.

However, not every line of JSX needs to become its own component. Create components when they represent a useful unit of interface or behavior.

Composition is the practice of combining components. Reuse is the practice of using a component more than once. Both are fundamental to structuring maintainable React applications.

Topic 10: Props and One-Way Data Flow

10.1 What Are Props?

Props are short for properties.

Props allow a parent component to pass information to a child component.

They are similar to the attributes you write in HTML, but React props can also contain JavaScript values such as numbers, arrays, objects, and functions.

Consider this component:

function StudentCard(props) {
  return <h2>{props.name}</h2>;
}

The component receives a parameter called props. React supplies the props passed to that component.

Now use it:

function App() {
  return <StudentCard name="Rahul" />;
}

export default App;

Output:

Rahul

The parent passes the string "Rahul" through the name prop. The child reads it using props.name.

10.2 Analogy: An Order Form

Analogy — An Order Form

Imagine a restaurant order form.

The customer provides information:

  • Customer name
  • Food item
  • Quantity

The kitchen receives that information and prepares the requested food.

Similarly, a parent component provides values through props, and the child component uses them to determine its output.

10.3 Why Do We Need Props?

Without props, a reusable component might always display the same information.

For example:

function StudentCard() {
  return <h2>Rahul</h2>;
}

Every time you use this component, it displays Rahul.

Props let you reuse the same structure with different values.

function StudentCard(props) {
  return <h2>{props.name}</h2>;
}

function App() {
  return (
    <div>
      <StudentCard name="Rahul" />
      <StudentCard name="Priya" />
      <StudentCard name="Aarav" />
    </div>
  );
}

The output contains three different names.

10.4 Passing Multiple Props

function StudentCard(props) {
  return (
    <article>
      <h2>{props.name}</h2>
      <p>Course: {props.course}</p>
      <p>City: {props.city}</p>
    </article>
  );
}

function App() {
  return (
    <div>
      <StudentCard
        name="Rahul"
        course="React"
        city="Rajkot"
      />

      <StudentCard
        name="Priya"
        course="JavaScript"
        city="Ahmedabad"
      />
    </div>
  );
}

export default App;

Explanation:

  • The first card receives Rahul, React, and Rajkot.
  • The second receives Priya, JavaScript, and Ahmedabad.
  • Both cards use the same component structure but display different content.

10.5 Destructuring Props

You can read props using ordinary JavaScript destructuring.

Instead of:

function StudentCard(props) {
  return <h2>{props.name}</h2>;
}

You can write:

function StudentCard({ name }) {
  return <h2>{name}</h2>;
}

The object passed to the function is destructured, and the name property becomes a local variable.

For multiple props:

function StudentCard({ name, course, city }) {
  return (
    <article>
      <h2>{name}</h2>
      <p>Course: {course}</p>
      <p>City: {city}</p>
    </article>
  );
}

Destructuring changes how you access the properties, not how props work.

10.6 Passing Numbers and Boolean Values

A string prop can use quotation marks:

<StudentCard name="Rahul" />

To pass a number or a boolean, use curly braces:

function CourseCard({ title, duration, available }) {
  return (
    <article>
      <h2>{title}</h2>
      <p>Duration: {duration} months</p>
      <p>{available ? "Available" : "Unavailable"}</p>
    </article>
  );
}

function App() {
  return (
    <CourseCard
      title="React"
      duration={3}
      available={true}
    />
  );
}

export default App;

The value 3 is passed as a number, and true is passed as a boolean. These are not the same as the strings "3" and "true".

10.7 What Is One-Way Data Flow?

In normal React component relationships, data is passed from a parent to a child through props.

Parent Component
       |
       | passes props
       v
Child Component
       |
       v
Uses values to describe its UI

For example:

function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}

function App() {
  const studentName = "Meera";

  return <Greeting name={studentName} />;
}

export default App;

The parent component provides the value of studentName. The child receives it as name.

This is called one-way data flow because information is passed down through the component hierarchy.

10.8 Props Should Be Treated as Read-Only

A child should not directly change the props it receives.

Incorrect:

function Greeting(props) {
  props.name = "Priya";

  return <h1>Hello, {props.name}</h1>;
}

You should not mutate props. They are inputs provided by the parent.

Correct:

function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}

If an application needs to change shared information, React provides patterns for coordinating data and interactions between components. Those patterns will be covered in a later phase when you study state and event handling.

For now, remember that props provide input; a component uses that input to describe its output.

Props make components customizable. Data normally flows from parent to child, and child components should treat received props as read-only.

Topic 11: The children Prop

11.1 What Is the children Prop?

The special children prop represents the content placed between a component's opening and closing tags.

For example:

function Card({ children }) {
  return <div className="card">{children}</div>;
}

function App() {
  return (
    <Card>
      <h2>React Fundamentals</h2>
      <p>Learn the basics of React.</p>
    </Card>
  );
}

export default App;

The Card component receives the heading and paragraph as children.

They are rendered inside the card's div.

11.2 Analogy: A Reusable Container

Analogy — A Reusable Container

Imagine a box that can hold different objects.

The box has a consistent shape, but the contents may change.

The component is the reusable container. Its children are the contents placed inside it.

The same pattern works for cards, layouts, panels, and page sections.

11.3 Why Do We Need children?

Suppose you want to create several cards with the same border, padding, and background but different content.

Without children, you might need to add specific props for every possible type of content.

With children, you can pass different JSX structures into the same component.

function Panel({ children }) {
  return (
    <section className="panel">
      {children}
    </section>
  );
}

function App() {
  return (
    <main>
      <Panel>
        <h2>Student Details</h2>
        <p>Name: Rahul</p>
      </Panel>

      <Panel>
        <h2>Course Details</h2>
        <p>Course: React Fundamentals</p>
      </Panel>
    </main>
  );
}

export default App;

Both panels share the same wrapper, but each contains different JSX.

11.4 How Does children Get Its Value?

Consider:

<Card>
  <h2>Welcome</h2>
  <p>Learn React.</p>
</Card>

React makes the nested content available to the Card component through the children prop.

You can access it with destructuring:

function Card({ children }) {
  return <div>{children}</div>;
}

The children variable holds the nested content supplied to the component.

11.5 Props vs. Children

Compare the two approaches.

Passing content using a named prop

function Message({ text }) {
  return <p>{text}</p>;
}

function App() {
  return <Message text="Welcome to React!" />;
}

Here, the parent explicitly passes the content through the text prop.

Passing content using children

function Message({ children }) {
  return <div>{children}</div>;
}

function App() {
  return (
    <Message>
      <h2>Welcome to React!</h2>
      <p>Start learning today.</p>
    </Message>
  );
}

Here, the parent places the desired content between the component's opening and closing tags.

Both patterns are useful.

Use named props when a value has a specific meaning, such as name, title, or price. Use children when the component should wrap or display content supplied by its parent.

children is a prop that gives a component access to nested content. It makes reusable layout components much more flexible.

Topic 12: Rendering and the Virtual DOM Concept

This topic explains how your React components become visible on the screen.

12.1 What Is Rendering?

In React, rendering means React calls your components to determine what should appear in the UI.

Consider this component:

function Welcome() {
  return <h1>Hello, React!</h1>;
}

The function describes the element structure React should display.

However, declaring the function does not automatically put it into the browser. React must render it through a React root.

12.2 How Does React Render a Component?

A typical Vite React application contains the following code in main.jsx:

import { createRoot } from "react-dom/client";
import App from "./App.jsx";

const rootElement = document.getElementById("root");
const root = createRoot(rootElement);

root.render(<App />);

Let's examine each line.

Line 1

import { createRoot } from "react-dom/client";

This imports the function used to create a React root for a DOM container.

Line 2

import App from "./App.jsx";

This imports the application's root component.

Line 3

const rootElement = document.getElementById("root");

This asks the browser to locate the HTML element with the ID root.

Line 4

const root = createRoot(rootElement);

This creates the React root associated with that element.

Line 5

root.render(<App />);

This tells React to render the App component into the root container.

The browser can then display the resulting UI.

12.3 Three Stages: Trigger, Render, and Commit

React's rendering process can be understood through three stages.

Stage 1: Trigger

Something causes React to perform a render.

The initial render happens when the application starts. Later renders may happen when component state or other relevant inputs change.

State is outside the current phase, but it is important to know that rendering can occur more than once.

Stage 2: Render

React calls the relevant components to calculate what the UI should look like.

For example:

function App() {
  return (
    <main>
      <h1>Student Dashboard</h1>
      <p>Welcome back!</p>
    </main>
  );
}

React evaluates the component and its JSX to determine the UI structure.

Stage 3: Commit

React applies necessary changes to the browser's DOM.

On the first render, it creates and inserts the required DOM elements. On subsequent renders, React applies the necessary changes rather than rebuilding the entire DOM tree without regard to what changed.

The browser then paints the resulting interface.

12.4 What Is the DOM?

DOM stands for Document Object Model.

The browser represents an HTML document as a structured tree of nodes that JavaScript can inspect and modify.

For this HTML:

<main>
  <h1>Student Dashboard</h1>
  <p>Welcome back!</p>
</main>

The DOM has a structure similar to:

main
├── h1
│   └── "Student Dashboard"
└── p
    └── "Welcome back!"

JavaScript can interact with the DOM using browser APIs. React provides a declarative way to describe the desired UI and manages the associated DOM updates.

12.5 What Is the Virtual DOM?

The virtual DOM is a commonly used term for React's in-memory representation of the UI.

Instead of asking you to manually create and update every browser DOM node, React lets you describe your interface using components and JSX.

React uses the resulting UI representation to work out which changes need to be committed to the actual DOM.

The virtual DOM is a conceptual model; modern React uses internal data structures and rendering mechanisms to coordinate this work. You do not need to implement a virtual DOM yourself.

Analogy — Editing a Document

Imagine you have a long document and need to correct one sentence.

You would usually change that sentence rather than rewrite the entire document from scratch.

React follows a comparable goal: it determines the necessary UI changes and applies them to the DOM.

The analogy is useful, but do not interpret it to mean that every React update changes only one element. The number of DOM operations depends on what changed in the rendered tree.

12.6 How Does React Use This Idea?

Suppose you have a component:

function StudentProfile() {
  return (
    <section>
      <h1>Rahul</h1>
      <p>Course: React</p>
      <p>Institute: BR TECHGEEKS</p>
    </section>
  );
}

React renders this structure.

If a later render produces different content, React compares the latest output with the previous result to determine the required DOM changes.

If the institute name remains the same, React generally does not need to replace that paragraph simply because another part of the output changed.

The important point is that React manages these updates; you do not manually rebuild the complete interface each time.

12.7 Virtual DOM Does Not Mean Every React App Is Automatically Faster

The virtual DOM is part of React's rendering architecture. It is not a guarantee that every React application will outperform every manually written JavaScript application.

Actual performance depends on the application structure, the work performed during rendering, and the DOM updates required.

React's main benefit at this stage is that it gives you a structured and declarative way to build and manage interfaces.

Rendering calculates what the UI should look like. Committing applies the required DOM changes. The virtual DOM concept helps explain how React coordinates updates, but it should not be treated as a guarantee of universal performance improvements.

Topic 13: React Developer Tools

13.1 What Are React Developer Tools?

React Developer Tools is a debugging tool for React applications.

It is available as a browser extension and provides two especially useful panels:

  • Components: Inspect the React component tree and examine component props and other available information.
  • Profiler: Record rendering activity to help investigate performance.

It complements the browser's normal Developer Tools.

13.2 Why Do We Need It?

Imagine your application has this structure:

App
├── Navbar
├── StudentProfile
└── CourseSection
    ├── CourseCard
    └── CourseCard

When a page becomes complicated, it may be difficult to understand which component is responsible for a specific section.

React Developer Tools lets you inspect the component hierarchy instead of relying only on the browser's HTML elements panel.

This is helpful when debugging props, understanding component composition, and investigating rendering performance.

13.3 Install the Browser Extension

Use the official React Developer Tools page:

https://react.dev/learn/react-developer-tools

From there, choose the supported browser extension for your browser.

For Chrome, the installation process generally involves:

  1. Open the Chrome Web Store from the official React Developer Tools instructions.
  2. Find the React Developer Tools extension.
  3. Install it.
  4. Open or refresh your Vite React application.
  5. Open browser Developer Tools.

You should see React-specific panels when the extension recognizes a React application.

13.4 Inspect a Component

Use this example in App.jsx:

function StudentCard({ name, course }) {
  return (
    <article>
      <h2>{name}</h2>
      <p>Course: {course}</p>
    </article>
  );
}

function App() {
  return (
    <main>
      <StudentCard name="Rahul" course="React" />
      <StudentCard name="Priya" course="JavaScript" />
    </main>
  );
}

export default App;

When you open the Components panel, you can inspect the rendered component tree.

You should be able to locate App and its StudentCard children.

Selecting a StudentCard lets you examine the props being passed to that instance.

For example, the first card receives:

name = "Rahul"
course = "React"

The second receives:

name = "Priya"
course = "JavaScript"

This helps you verify that the parent is passing the expected information.

13.5 Understanding the Components Panel

The Components panel is useful for questions such as:

  • Which component renders this section?
  • What props did the parent pass?
  • How are the components nested?
  • Which part of the component tree should I inspect while debugging?

The panel shows React's component structure, which is different from the raw HTML DOM tree.

13.6 Understanding the Profiler Panel

The Profiler helps record rendering activity.

For example, a large dashboard may contain many components. If a performance problem occurs, profiling can help you investigate which components rendered and how much time was associated with that work.

Do not worry about advanced performance optimization yet. For Week 1, learn where the Profiler is and what problem it is designed to help diagnose.

Common Beginner Mistakes

Mistake 1: Using class Instead of className

Incorrect:

<div class="card">Hello</div>

Correct:

<div className="card">Hello</div>

Mistake 2: Returning Multiple Adjacent JSX Elements

Incorrect:

return (
  <h1>Hello</h1>
  <p>Welcome</p>
);

Correct:

return (
  <>
    <h1>Hello</h1>
    <p>Welcome</p>
  </>
);

Mistake 3: Forgetting Curly Braces for Variables

Incorrect:

function App() {
  const name = "Rahul";
  return <h1>name</h1>;
}

This displays the literal word name.

Correct:

function App() {
  const name = "Rahul";
  return <h1>{name}</h1>;
}

Mistake 4: Using a Component Name with a Lowercase First Letter

Prefer:

function StudentCard() {
  return <article>Student</article>;
}

Use it as:

<StudentCard />

React interprets JSX tags beginning with lowercase letters as built-in HTML elements.

Mistake 5: Passing a Number as a String Accidentally

<StudentCard duration="3" />

Here, duration is a string.

<StudentCard duration={3} />

Here, duration is a number.

Use the type appropriate to the data you need.

Mistake 6: Trying to Modify Props

Props are inputs supplied by a parent. Do not assign new values to props.name or mutate received props.

Instead, use the value received by the component to describe the UI.

Mistake 7: Confusing JSX with HTML

JSX looks similar to HTML, but it is syntax used inside JavaScript. It has its own rules, including className, htmlFor, and the requirement to close elements correctly.

Mistake 8: Editing the Wrong File

If you change App.jsx, your root component output should change. If the browser still displays the old page, inspect the terminal and browser console and confirm that you are editing the correct project directory.

Revision Notes

Before moving to the next phase, make sure you can explain each of these points in your own words.

React: A JavaScript library used to build user interfaces with reusable components.

SPA: An application structure where internal navigation and UI updates can happen without reloading the entire HTML document on each navigation.

CSR: A rendering approach in which browser-side JavaScript creates or updates the UI.

Vite: A tool used to scaffold, develop, and build frontend applications.

JSX: HTML-like syntax embedded in JavaScript for describing React interfaces.

JavaScript expressions in JSX: Curly braces allow variables, calculations, and other suitable JavaScript expressions to be used inside JSX.

Fragment: A way to group multiple JSX elements without creating an extra wrapper element in the DOM.

Functional component: A JavaScript function that returns UI content.

Composition: Combining smaller components to build a larger interface.

Props: Inputs passed from a parent component to a child component.

One-way data flow: The normal pattern in which data is passed down through the component hierarchy.

Children: The nested content supplied between a component's opening and closing tags.

Rendering: React calling components to calculate the UI they describe.

Virtual DOM: A common term for React's in-memory representation of the UI, used as part of its rendering and update process.

React Developer Tools: A browser tool for inspecting React components, their props, and rendering performance.
